# Feature [[cat001]] [[cat002]] [[product]]

## providing

One interactive terminal view of every agent this machine is running and every
message they have exchanged. Three panes: a roster — one row per agent across
both runtimes, carrying its runtime, project, role, state, activity and age —
a message log in time order, `from` → `to` with a derived subject line, and a
detail pane showing the message under the log's cursor in full. It renders and
does not join: the roster comes from [[ft012]]'s published census rows and the
log from [[ft014]]'s `messages` verb, and this Feature computes neither.
No DESTRUCTIVE verb reaches a worker: `resume` / `stop` / `accept` / `rm` /
`reclaim` destroy or reassign worktrees, branches and addresses and stay with
whoever allocated them. [[sp033]] admitted `send`, which destroys nothing and
allocates nothing, so this Feature WRITES to the bus as well as rendering it —
the boundary is ownership, not mutation ([[adr0035]]).

The roster's `PROJECT` column reports each row's own attribution exactly as
[[ft012]] publishes it, and that attribution is not one thing: for claude rows
it is the tmux-pane-to-registry mapping ([[adr0024]]), while for pi rows it is
the tmux session group `parse-pi-window` reads from the window name — the
display host, not the bus slug a message's `from`/`to` route through. Those
can disagree: a peer spawned with `pi-worker spawn --project amdemo` from a
`dotfiles` repo shows `amdemo` in this column while messaging on the
`dotfiles` bus, because the bus slug follows the repository and the tmux group
follows the display host. The column is honest about the display host; a
bus-scope column would be a separate ask.

Delivered by [[sp030]], which also widened both sources — [[ft014]] gained
worker presence and the project-wide `messages` read, [[ft012]] gained a second
probe and a `runtime` column. [[sp031]] added the detail pane, made
`--project` real, and replaced independent per-pane scrolling with a cursor
the view follows.

[[sp032]] made the view NAVIGABLE rather than merely readable, and changed no
source. The two lists answer the mouse — click to select, wheel to scroll the
pane under the pointer — the detail pane became a peer of the other two with
its own scroll and a full-screen zoom, paging and jump keys reach all three,
and the log now tail-follows CONDITIONALLY: it follows while the cursor sits
on the newest message, freezes the moment the operator scrolls back, and says
so with a `+N new` count in its header until `End`/`G` returns it to live. A
session opens with the message pane already at its tail, so the live view is
live from the first frame rather than after a keystroke. The shell underneath
is `bubbletea`; every byte of column layout, truncation and neutralisation
stayed exactly where it was.

[[sp033]] made the view ANSWERABLE, and gave it an operator. The monitor now
knows who is watching it: `pi-worker whoami` answers which party the OS user is
([[ft014]]), resolved ONCE at startup and degrading to no identity — the
current product — when nobody is registered, when the CLI refuses, or when it
is absent entirely. Mail addressed to that operator carries a row marker and an
`N for you` count kept deliberately separate from [[sp032]]'s `+N new`, which
counts every arrival past the cursor and so says nothing about the operator on
a busy bus. The comparison is on the minted ADDRESS ([[adr0034]]) that
[[ft014]]'s widened `messages` projection now publishes, never on a label: a
message you sent is not for you, and an address from a registration you have
since released is not you either. The message pane renders newest-first with
live at the HEAD, inverting [[sp032]]'s tail-follow across every liveness and
scroll derivation. And `a` opens a reply composer bound to the selected
envelope's address at OPEN time, so a sample arriving mid-draft cannot redirect
the reply; `ctrl+s` sends through [[ft014]]'s `send`, dispatched as a `tea.Cmd`
so neither reader loop gains an exec ([[adr0014]]), with the CLI's own stderr
shown and the draft restored on failure.

[[sp034]] made the view THREADED, and changed no source. The message pane now
groups envelopes into conversations: a thread is the SORTED COMPOSITE of its
participants' minted ADDRESSES ([[adr0034]]), never their rendered labels, so
two parties sharing a label stay two threads and a multi-recipient envelope
forms its own. The grouping is a reader-side derivation over what [[ft014]]'s
`messages` verb already publishes — no `thread_id` is added to an envelope
([[adr0028]]) and no `content` is parsed that was not parsed before
([[adr0031]]). A session opens THREADED and `t` flips back to the flat
chronological log; `--once` is always flat, because a pipe has no cursor and
nothing to expand. Threads sort by their newest member, so an arrival re-sorts
and a waking conversation jumps to the head — the meaning [[sp033]]'s
newest-first inversion gave the top of the pane. Expanding nests a thread's
messages inline beneath it, any number of threads at once, and a child row
omits its recipient: the pair is implicit in the thread, and the pane's
scarcest resource is width.

[[sp035]] corrected what [[sp034]] got wrong the moment a thread was
UNFOLDED: the newest message rendered TWICE, once as the thread row's own
summary and again as the first child. The fold now starts at the
SECOND-newest, so an expanded conversation of `N` shows one summary row and
`N-1` children and every message appears exactly once. The count column keeps
reporting the CONVERSATION's total rather than the rows on screen, so the
number does not change as a thread opens and closes. A thread of one
therefore has nothing beneath it and is NOT EXPANDABLE: its glyph cell is
blank, and expand, collapse and toggle are all no-ops on it, so the chevron
means "there is something under here" — the only honest reading once the
newest member lives on the thread row.

[[sp035]] also gave the detail pane the ADDRESSES. Two threads whose
participants wear the same labels are indistinguishable in the log — on a
real bus `claude-main <> jan` appears twice, four distinct addresses, because
every registration mints a fresh never-reused one ([[adr0034]]) and a
re-registered session is a new party wearing an old label. The grouping is
right and was left alone; keying on labels is what [[adr0034]] refuses. The
detail pane now renders the envelope's own `from_address` and `to_addresses`
in FULL beside the labels, which is where the operator disambiguates and
where they copy an address from. The log's `PARTICIPANTS` column was
deliberately not touched: a per-row disambiguator would spend the pane's
scarcest resource on every row to serve a rare collision.

[[sp036]] closed two defects the previous two specs' own audits found, and
corrected three display details. Every grid cell in all three grids —
roster, flat log, thread — is now NEUTRALISED at `pad`, the single function
that writes one, and neutralised BEFORE it measures. That ordering is the
whole fix: `runeWidth` returns 0 for C0 but 1 for DEL and C1, while
`neutralize` strips all three, so a measure-first implementation emitted a
SHORT cell and shifted every column to its right while the escape still
reached the terminal. Until this, only SUBJECT was neutralised and every
LABEL cell was not — and a label is registry-resolved from a name the worker
CHOSE, so it is attacker-influenced exactly as content is. TAB is closed by
the same change: `runeWidth` scores it 0 while a terminal expands it to
eight cells.

[[sp036]] also removed the second ordering. `Threads()` no longer sorts at
all — it groups by key in first-appearance order and keeps each group in
input order — so `orderedMessages` is the ONLY place the pane orders
anything and [[sp034]]'s single-reorder rule holds by construction rather
than by documentation. Before this, `Threads()` ordered by the `At` string
while the flat pane ordered by id, and under ordinary clock skew between two
agents the two panes disagreed about which envelope was newest; since
[[sp035]] preserves the selection across a mode toggle, that disagreement
could move the cursor off row 0 and flip the pane from live to `+N behind`
with nothing having arrived.

The display corrections: the expand glyph is `+` collapsed and `-` expanded,
blank on a child row and on a non-expandable thread. `PARTICIPANTS` now
reports the NEWEST message's DIRECTION as `from > to` while collapsed and
only the newest SENDER while expanded, since the children below already name
each sender — the cell orders by what was said last, never by the
address-sorted key, which stays what [[adr0034]] requires of the thread KEY.
And the detail pane pairs each party's label with its own full address on
that party's OWN line, so a reader of a multi-recipient envelope no longer
matches address to label by position.

## api_surface

A single Go binary linked to `~/.local/bin/agent-monitor`, built and linked by
`agent-monitor/dot.yaml`. It is the user interface, so nothing wraps it —
[[adr0030]] admits Go for this one interactive TUI on its own merits and
carries [[adr0003]]'s `nushell/actions/` wrapper mandate out explicitly.

- `agent-monitor` — full screen, alternate buffer, roster and messages, plus a
  detail pane shown by default ([[sp031]]; `d` toggles it off and back on).
- `agent-monitor --once` — render one frame to stdout and exit 0; no raw mode,
  no alternate screen, so it composes in a pipe and in a tmux status line. No
  detail pane and no toggle key: a pipe has no cursor and no height.
- `agent-monitor --project <name>` — restricts the ROSTER to rows whose
  `project` matches `<name>`, case-insensitively and by exact match rather
  than substring: a project is a slug/identifier, so a substring match would
  let `dotfiles` silently also catch a hypothetical `dotfiles-extra` project,
  and case-insensitivity keeps it consistent with the interactive filter's own
  case-insensitive match. It composes with the interactive `/` filter — both
  apply together, never one replacing the other. `--project ""` (explicitly
  empty) is treated as unset, never as "rows with no project". An unmatched
  value yields an empty roster with its header intact and exit 0 on quit — an
  answer, not an error, matching [[ft012]]'s own contract for a project with
  no agents. `--once --project <name>` honours the flag too. The MESSAGE pane
  is never filtered by this flag: the bus is scoped by repository, so every
  message in view is already in scope regardless of which project a roster
  row belongs to. [[sp030]] T8 parsed this flag and discarded it
  (`_ = project`) as scaffold; [[sp031]] made it real alongside the `PROJECT`
  column below.

- `agent-monitor --as <label>` ([[sp033]]) — identifies the operator as the
  party wearing `<label>` rather than the one matching the OS username,
  resolved through [[ft014]]'s `whoami --label` so the registry is read in the
  module that owns it and never re-derived here. An unheld label, an ambiguous
  one (two `kind: person` parties — refused by name), a tombstone, or any
  failure yields NO identity with the reason shown; a half-identity, a label
  with no address, is unrepresentable, because the for-you comparison and
  `send --as` would then disagree about who the operator is. Absent the flag,
  the operator is the party whose label equals the OS username — which
  `pi-worker register` claims by default, so "your bus label is your username"
  holds without the operator maintaining it.

Keys ([[sp032]], [[sp033]] and [[sp034]] widened this list): `q` / `Q` /
`Ctrl-C` quit,
`r` / `R` force a census refresh, `/` filter, `d` / `D` toggle the detail pane
([[sp031]]), `a` open the reply composer on the selected message and `ctrl+s`
send it ([[sp033]]; `esc` abandons the draft). `a` is the reply key because
`r` was already refresh — the spec proposed `r`, collided, and was amended
rather than shadowing a documented binding. Every binding here is covered by a
test driving a REAL `tea.KeyMsg` through the translation layer, not only by a
model-level test of its behaviour ([[adr0036]]).
[[sp034]] added `t` / `T` (flip threaded <-> flat), `l` / `->` (expand the
thread under the cursor), `h` / `<-` (collapse it — from a CHILD row this
collapses the thread the cursor is standing inside, so it can climb out) and
`space` (toggle). [[sp035]] narrowed all three: on a one-message thread they
are no-ops, because such a thread is not expandable. None shadowed a
documented binding: `KeyLeft` / `KeyRight`
were already decoded by `translateKey` and handled nowhere, and `l`, `h`,
`space`, `t` were unbound. The expansion keys act only with the message pane
focused, threaded, and a non-empty list; `t` flips the mode from either pane,
because it is a view mode rather than a pane action. In a filter or composer
draft all four are TEXT, the rule that already made `q` and `d` text there.
`tab` cycles THREE stops — roster, messages, detail — skipping a hidden detail
pane and a no-op while zoomed. Arrows and `jk` move the focused pane's
SELECTION rather than scrolling it directly; `PgUp` / `PgDn` move a list pane's
cursor by `viewport-1` (the overlapping row is how a reader re-finds their
place) and scroll the focused detail body by a full window (no cursor there to
land relative to); `Home` selects the first row, `End` and `G` the last, all
clamping at both ends and no-ops on an empty list. `enter` / `o` zoom the
detail pane to the full screen and `esc` returns, restoring the previous body
scroll; `esc` also cancels an open filter draft. A filter draft swallows every
rune while editing — `q` and `d` typed into a query are text, not quit or
toggle — and swallows the paging keys too, which are specials rather than
runes and so need their own branch.

MOUSE ([[sp032]]): a left press on a data row focuses that pane and moves its
cursor to the clicked row; a press on a pane header or column-header row
focuses without moving the cursor; a press on a separator changes nothing. The
wheel scrolls the pane UNDER THE POINTER by three lines without taking focus
or moving any cursor, including over an unfocused pane. Motion reports are
ignored, never treated as presses. Enabling mouse reporting COSTS the
terminal's own click-drag selection for the session; `Shift`+drag still selects
in WezTerm and tmux, and that trade is accepted rather than worked around.

The interactive filter matches `From` OR any entry of `To`, case-insensitively
— [[sp033]] closed `dotfiles-1xfo`, where filtering to a worker's name hid
every message addressed TO it. Exit status
is 0 on a clean quit, including when zero agents are running, and the terminal
is restored on every exit path — [[sp032]] moved that restore from a
hand-rolled `sync.Once` to `bubbletea`'s own panic and signal handling, which
the shell deliberately does not opt out of.

## data_model

Holds no durable state. Three clocks, because the two sources cost different
amounts:

| sample | source | cadence |
|---|---|---|
| roster, gated | `agent-census --json --detail --fast --if-changed <stamp>` | 3 s |
| roster, forced | the same without `--fast` or the gate | 20 s, and on `r` |
| messages | `pi-worker messages --json` | 2 s, ungated |

The gated poll is cheap and silence means "unchanged, keep the last sample" —
never "zero agents"; a consumer that redrew from empty output would blank
itself every tick. The forced clock exists because that gate fingerprints
claude account files only (`dotfiles-eee4`), so a pi worker changing state
never opens it; without a second clock pi rows would go stale indefinitely on a
machine where claude happens to stay quiet. The message read needs no gate at
all — it is local file work.

One sample carries both runtimes at one instant: `probe-all` calls
`probe-pi-workers` unconditionally on every invocation, gated-open or forced,
so a sample's single age is exact for pi rows as well as claude ones. That
invariant is what makes the displayed age honest, and it is currently pinned
only on this side of the boundary (`dotfiles-htkc` asks for the census-side
case that would catch the census breaking it).

A failed sample leaves the previous frame on screen marked stale by age; the UI
never blanks and never invents a value. Age is the SAMPLE's capture age, the
same for every row, because no census row carries a per-agent timestamp
(`dotfiles-a1tq`). Pi rows carry `branch: ""` because `pi-worker workers`
exposes no branch field (`dotfiles-ycaz`). Both loops carry [[adr0014]]'s three
guards: fail fast on unrecoverable setup, a sleep floor per iteration, retry
bounded outside the loop.

[[sp032]] made SCROLL FIRST-CLASS, which is the change every other behaviour
in that spec rests on. A pane's scroll offset is now its own state that a wheel
moves without dragging the cursor along; `SetRosterLen` / `SetMessagesLen`
CLAMP that offset into range instead of re-deriving it from the cursor, and
cursor motion adjusts scroll only by the minimum needed to bring the cursor
back on screen. Before this, scroll was re-derived on every `SetLen` — that is,
every two-second sample — so any wheel offset died on the next tick and a
frozen pane was impossible to express.

Liveness for the message pane is DERIVED, never stored as a mode:
`cursor == maxIndex(len) && scroll == maxTop(len, viewport)`. A growing sample
follows the tail only while that holds; otherwise nothing moves and
`PendingMessages` accumulates what arrived. Every mutator that can move the
pane clears the count when it lands live, so `End`, `G`, a click on the last
row and a wheel back to the bottom all return to live as a CONSEQUENCE of where
the cursor ended up rather than as key-specific special cases. Liveness is
false whenever no viewport has been reported, and that gate is load-bearing
rather than defensive: `--once` never reports one, and following a tail there
would make `scrolledMessageSample` slice every message but the newest out of
the frame a pipe receives, breaking [[sp030]] T9's byte-plain contract.

[[sp034]]'s threading is a pure DERIVATION over the sample, not state: the
pane's rendered ROW LIST is recomputed each frame from the messages, the
expansion set and the mode, and that ONE list feeds `SetMessagesLen`, the
scroll slice, the renderer and the detail pane's selection alike — so
[[sp032]]'s first-class scroll and [[sp033]]'s liveness (`cursor == 0 &&
scroll == top`) carry over unchanged rather than gaining a second authority.
A thread row's selection resolves to its NEWEST member, which is what keeps
the detail pane, `a`'s reply recipient and the detail selection key naming one
envelope. The expansion set is a `map[string]bool` on the `cmd/` shell, never
on `Model` — several fixtures compare whole models with `*m != want`, so a map
field there is a COMPILE error, which is the guard rather than a convention.
A key for a thread that has since left the bus is consulted but never trusted:
it is inert, not a phantom row. One predicate, `isThreaded(model, height)`,
decides threaded-or-flat for BOTH the renderer and the row resolution, because
two independent reads of the same field disagreed at height 0 and put one
cursor over two different lists.

Two defects were recorded against this surface when [[sp035]] shipped, and
[[sp036]] fixed BOTH: the thread derivation ordered by the envelope's `At`
STRING while `orderedMessages` ordered by id, a second reorder observable
under clock skew (`dotfiles-i1sw`), and label cells — `FROM` / `TO` /
`PARTICIPANTS` — bypassed the neutraliser that `content` passed through, so
an escape inside a registry-resolved LABEL reached the terminal
(`dotfiles-br55`). Neither is open; see the [[sp036]] paragraphs below for
what replaced them.

[[sp035]] added one derived value and one display line. `LogRow.Expandable`
is computed in `ThreadRows` and NOWHERE else — the glyph cell reads it and
`cmd/`'s `applyThreadOutcome` reads it before touching the expansion set, so
the rule that a one-message thread cannot open has a single authority rather
than two layers each deciding `Count > 1` for themselves. That shape is a
direct consequence of [[sp034]] Task 6, where two independent reads of
`Threaded` disagreed at height 0 and put one cursor over two different lists;
a test now scans every non-test source and fails if a second derivation
appears. The guard also sits ahead of the toggle's own
`expansion[key] = !expansion[key]`, which would otherwise INSERT a key for a
thread that can never open. In the detail pane the address line is appended
before the single height clamp, so it competes for the pane's budget like any
other line rather than escaping it.

The detail pane is the ONLY pane on a `bubbles/viewport`; roster and messages
keep the cursor model. Two scroll authorities over one pane would fight — the
per-sample derive yanks a viewport's own `YOffset` back — so `tui.Model` owns
`DetailScroll` and the viewport is rebuilt per frame as a pure renderer over
it. Its scroll survives re-renders of the same selected message and resets when
selection changes, keyed on the message's VALUE identity (id, time, from, to,
kind) rather than its cursor index: a filter that re-indexes the list can put a
different envelope under the same index, and an index key gets exactly that
case wrong.

`Model` (`internal/tui`) carries a cursor per pane rather than a scroll offset
a keystroke moves directly ([[sp031]]): `j`/`k` and the arrow keys move
`RosterCursor`/`MessagesCursor`, and each pane's scroll is DERIVED from its
cursor plus the viewport height the caller reports every frame, so a filter
that shrinks a list clamps the cursor in the same pass and a terminal resize
can never leave the cursor off-screen. The detail pane reads whichever message
is under `MessagesCursor` and re-renders it as the cursor moves; toggling the
pane with `d` never touches selection, so the same message is still selected
when it is shown again.

Three rendering rules are load-bearing rather than cosmetic. The frame is
clamped to the terminal height, each pane keeping its header and a short pane
yielding its surplus — without it a tall frame scrolls the terminal and
carries the roster off the top while the pane offsets are applied correctly
and invisibly (`dotfiles-m0km`). [[sp031]] extended that budget to three
regions: the detail pane is capped independently at roughly a third of the
terminal height or eight rows, whichever is smaller, and hides itself below a
minimum combined height for roster and messages rather than squeezing either
of them into uselessness — the total frame still never exceeds the terminal
height at any size, `--once` renders without the detail region at all (a pipe
has no cursor and no height). And the interactive path writes CRLF, because
raw mode
disables the ONLCR mapping that turns a bare LF into a carriage return; with
LF each line starts where the previous one ended and the frame staircases off
the right edge (`dotfiles-r9ty`). `--once` never enters raw mode, which is why
both defects were invisible to the one-shot path and to every unit test.

The subject column is derived by the reader: first line of `content`, or
`status — summary` for a `state` envelope. Type is read from the envelope's
`kind`, never inferred from the shape of `content` ([[adr0031]]). No `subject`
field is added to an envelope — the transport interprets nothing it carries
([[adr0028]]) — and the column does not parse content to prettify it, so a
JSON payload renders as its ugly first line by design, asserted so nobody
"fixes" it. Every rendered byte
passes through a neutraliser covering C0, C1 and DEL: this pane shows content
written by OTHER AGENTS, so an unneutralised escape could reposition the
cursor or overwrite the roster above it. Truncation counts display cells, never
bytes, and never cuts mid-escape.

That underived rule is a boundary, and [[sp031]]'s detail pane draws it rather
than moving it: the SUBJECT column stays exactly as above — raw-first-line,
never parsed — while only the detail pane formats. Its body is pretty-printed
when the content parses as JSON and rendered raw when it does not, a parse
failure falling back to raw rather than erroring; both paths pass through the
same neutraliser and the same cell-aware wrapping the subject column uses,
never cutting mid-escape, and a body longer than the pane's height budget is
truncated with a visible indicator rather than a silent cut. [[ft014]]'s
opacity rule — "it carries any consumer's vocabulary and gates on none of
it" — binds the TRANSPORT; `agent-monitor` is a consumer, so formatting what
it DISPLAYS in a second, dedicated pane does not touch that contract, and no
`subject` field is invented on an envelope either way.

## sample

```text
agents — updated 0s ago
UID/NAME       RUNTIME ROLE    STATE         ACTIVITY  AGE
copacks-6f     claude  —       —             busy      0s
dotfiles-fe    claude  —       —             busy      0s
peer-4         pi      peer    complete      idle      0s
peer-5         pi      peer    complete      idle      0s
impl-1         pi      —       unknown       —         0s

messages — updated 0s ago
TIME     FROM         TO               SUBJECT
12:02:01 r1           peer-4           You are ada, a demo peer running in the …
12:02:07 peer-4       peer-5           ada here — name one thing tmux must neve…
12:02:23 peer-5       peer-4           Per adr0028, tmux must never transport m…
12:02:26 peer-4       r1               {
```

Captured live, predating [[sp031]]'s `PROJECT` column and detail pane — the
roster and log shapes above are otherwise unchanged. `unknown` is an
observation and licenses nothing ([[adr0017]]); an empty `ACTIVITY` is a
worker that never published presence, not a guess; and the `{` is an
envelope's opaque body rendering exactly as the derivation rule says it
should — expanding that same envelope in the detail pane is what [[sp031]]
adds.

A `{` in the SUBJECT column is therefore ambiguous between two causes, and the
difference matters. It is correct when the envelope's `content` is an object
the derivation rule declines to parse. It is a DEFECT when the envelope is
mis-typed — `dotfiles-56lh` shipped worker results onto the bus stamped as
prose, so the `status — summary` branch could never fire and every result read
as `{` for weeks. The fix belonged in the writer, not here ([[adr0031]]).
Since [[dotfiles-oj4c]] the writer refuses the mismatch outright, so this
column can trust `kind` rather than the shape of what it is handed.

## components

- `agent-monitor/cmd/agent-monitor/main.go` — flag parsing (`--project`,
  `--once`), the `bubbletea` program and its `shell` model ([[sp032]]:
  `Update` maps a `tea.KeyMsg` / `tea.MouseMsg` onto a `tui.Model` method and
  does nothing else; `View` is the frame joined with `"\n"`), the three-way
  frame builder and its height/detail budget, `frameLayout` + `hitTest` (the
  ONE place a screen row becomes a (pane, row) pair), the zoom layout, and the
  once-per-session `shell.opened` latch that opens the message pane at its
  tail.
- `agent-monitor/internal/source/` — `census.go` (gated + forced samplers, the
  never-blank monitor), `messages.go` (the ungated message sampler),
  `loop.go` ([[adr0014]]'s guards, consolidated).
- `agent-monitor/internal/render/` — `roster.go` (columns including
  `PROJECT`, drop-from-the-right priority, staleness header), `log.go`,
  `subject.go` (derivation, neutralisation, cell-aware truncation),
  `detail.go` — the detail pane: header plus JSON-or-raw body, reusing
  `subject.go`'s neutraliser and cell-wrapping ([[sp031]]).
  [[sp034]] added `thread.go` — `Threads()` (address-keyed grouping, newest
  first, participant labels resolved from the thread's own envelopes) and
  `ThreadRows()` (the flatten into `LogRow`, thread row plus children when a
  key is expanded) — both pure functions holding no state, and widened
  `log.go` with the thread column grid (`RenderThreadRow`, `RenderThreadLog`)
  that thread rows and child rows SHARE, so `SUBJECT` starts at the same cell
  on both and the header cannot drift from the rows.
  [[sp035]] changed `ThreadRows` to fold from `Messages[1:]`, added
  `LogRow.Expandable`, blanked `log.go`'s glyph cell for a non-expandable
  thread, and gave `detail.go` a `detailAddressLines` helper that reuses the
  body's own neutraliser and cell-aware wrapping.
  [[sp036]] put `neutralize` inside `roster.go`'s `pad` — the one function
  that writes a grid cell, and the reason the fix is one line rather than a
  list of wrapped call sites — deleted `isNewer` and every sort from
  `thread.go`, and gave `log.go` `threadPartyLabel` and
  `threadDirectionRecipients` for the direction cell. `detail.go`'s
  `addressPartyLine` renders one party per line. Two tests are executable
  anti-patterns rather than prose: one fails if a sort returns to `Threads`,
  the other if `pad` ever measures before it neutralises.
- `agent-monitor/internal/tui/` — `keys.go` (three-stop focus, filter,
  `--project` composition, per-pane cursor with FIRST-CLASS scroll, the
  detail-visible toggle and zoom, paging and jump motions, `ClickPane` /
  `ScrollPane`, `OpenMessagesAtTail`, `messagesLive` and `PendingMessages`).
  [[sp034]] added `Threaded` and `Outcome.Thread` (an INTENT — expand,
  collapse, toggle — carrying no key, because `Model` may hold neither the
  row list nor the expansion set), and split the counters: `SetMessagesLen`
