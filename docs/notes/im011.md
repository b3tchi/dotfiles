# Implementation [[cat001]] [[cat002]] [[product]]

## solves
[[us022|agent-counts-per-project]]

## approach
Shipped as one nushell action on `PATH`
(`nushell/actions/agent-census` → `~/.local/bin/agent-census`), split
into a **probe layer** that shells out and a **pure transform layer**
that takes those structures and returns rows. Nothing in the transform
layer reaches for the world, which is what makes the joins testable:
arranging a live agent into `blocked` on demand is not repeatable, so a
suite that needed it would only ever run on one machine.

What the spec did not anticipate, and execution settled:

**Which records count.** [[sp026]] named `claude agents --all --json` as
the source without asking what `--all` returned. It returns historical
job records — 13 records for 6 running agents on the shipping machine,
the extras aged 25 to 101 days. Filtering on a live pid was not enough
either: a finished background job stays resident under
`claude bg-pty-host`. The rule that shipped is [[adr0024]] — a process
exists AND the job is not terminal.

**Two axes, not one.** `state` is the job's lifecycle and survives the
process; `status` is the process's activity and exists only while one
does. The first implementation coalesced them. The job axis decides the
bucket, because `status=idle` + `state=blocked` is alive and waiting on
you — reporting that as idle would bury the row [[us022]] exists for.

**Liveness from `status` presence.** Observed invariant, 13/13 live and
in fixtures: `has(status) <=> has(pid)`, every such pid alive. That
replaced the process-table lookup — same signal from the supported
command, with no window between two probes for the process to exit in.
`ps` is still needed for pane ancestry.

**Deduplication.** A resumed session appears twice upstream, one live
record plus a historical leftover sharing its `sessionId`. Collapsed on
`sessionId`, live twin winning. Keying on `name` would be wrong: two
genuinely different sessions can share one.

Attribution is tmux-first: an agent with a pid resolves through its
pane via an ancestor walk, which separates two projects sharing a
filesystem path. Without a pane, `cwd` is matched against the [[ft001]]
registry by path COMPONENTS, longest match winning; a tie — the real
registry collides twice — yields `unknown` with the path shown rather
than a guess, per [[adr0017]].

Language was fixed by [[adr0001]] with no [[adr0002]] bash trigger and
no [[adr0003]] daemon case. Source discipline is [[adr0025]].

## features
- [[ft012]] — the capability this implements; its `## api_surface` and
  `## data_model` are the shipped contract.
- [[ft001]] — consumed for the registry read behind the `cwd` fallback,
  including `$env.PROJECT_CONFIG_PATH`, which the module exports on
  load and the census honours rather than assuming the default path.

## data_model
Four probe inputs, each captured as a fixture:

| probe | shape |
|---|---|
| `claude agents --all --json` × N accounts | agent records, each tagged with its account |
| `tmux list-panes -a -F "#{pane_pid} #{session_group} #{session_name}"` | pane_pid → project |
| `ps -eo pid=,ppid=` | pid → ppid, for the ancestor walk |
| `$env.PROJECT_CONFIG_PATH` or `~/.config/project/projects.yaml` | project → path, via [[ft001]] |

The pane probe requests `session_name` as a third field: an ungrouped
session reports an empty `session_group`, and the name is then the only
label available. The two-field probe the spec described would have
silently lost those panes.

Accounts are discovered by globbing `~/.claude-*` plus bare `~/.claude`
and `$CLAUDE_CONFIG_DIR`, deduplicated by CANONICAL path — `~/.claude`
is commonly a symlink to one of the suffixed dirs, and following both
would count every agent in that account twice.

Output rows and the bucket table are defined by [[ft012]].

## api_surface
As published by [[ft012]]: `agent-census [--json] [--project <name>]
[--detail] [--all]`. This card adds no surface of its own.

## components
- `nushell/actions/agent-census` — probe layer, pure transform layer,
  CLI surface.
- `nushell/dot.yaml` — the linux-section link entry.
- `tests/agent-census/` — 87 cases over `harness.nu`, `run-tests.nu`,
  `transform-cases.nu`, `probe-cases.nu`, `cli-cases.nu`, driven from
  captured fixtures and stub executables on a bare PATH. The repo had
  no nushell unit harness before this; the suite passes with no tmux
  server, no claude on PATH and a foreign `$HOME`. Fixtures are
  sanitised — the repository is public.
