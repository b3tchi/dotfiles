# Implementation [[cat001]] [[cat002]] [[product]]

## solves
[[us022|agent-counts-per-project]]

## approach
Ship the census as one nushell action on `PATH`
(`nushell/actions/agent-census` → `~/.local/bin/agent-census`), the shim
pattern already used by `wm-ipc.nu` and `project-picker`. The action is
split in two layers, and the split is the whole design: a **probe
layer** that shells out (`claude agents --all --json` once per account,
`tmux list-panes`, `ps`, the [[ft001]] registry file) and a **pure
transform layer** that takes those four data structures and returns
rows. Only the pure layer holds the logic worth getting wrong, and
because it takes data rather than reaching for the world, it is testable
against captured fixtures with no live agents in a given state.

Attribution resolves tmux-first: an agent with a live `pid` has its
process ancestors walked until one matches a tmux `pane_pid`, and that
pane's `session_group` is the project. This is what makes two projects
sharing a filesystem path separable. Only when no pane is found does the
`cwd` get matched, longest-prefix, against the registry; a tie or a miss
routes to an `unknown` row carrying the raw `cwd`, per [[adr0017]] —
"I cannot tell" is a verdict, not a reason to guess.

Language is fixed by [[adr0001]] (structured pipeline in the
workflow-tooling layer), with no [[adr0002]] bash trigger and no
[[adr0003]] daemon case, so: nushell, no compiled helper.

## features
- [[ft012]] — the capability this implements; its `## api_surface` and
  `## data_model` are the contract this card builds to.
- [[ft001]] — consumed for the registry read behind the `cwd` fallback.
  Called exactly as its `## api_surface` documents; no extension needed.

## data_model
Four probe inputs, each captured as a fixture for tests:

| probe | shape |
|---|---|
| `claude agents --all --json` × 2 accounts | list of agent records, each tagged with its account |
| `tmux list-panes -a -F "#{pane_pid} #{session_group}"` | pane_pid → project |
| `ps -eo pid=,ppid=` | pid → ppid, for the ancestor walk |
| `~/.config/project/projects.yaml` | project → path, via [[ft001]] |

Output rows and the state-bucket table are defined by [[ft012]]'s
`## data_model` and are not restated here.

## api_surface
As published by [[ft012]]: `agent-census [--json] [--project <name>]
[--detail]`. This card adds no surface of its own.

## components
- `nushell/actions/agent-census` — probe layer, pure transform layer,
  CLI surface.
- `nushell/dot.yaml` — the `actions/agent-census:
  ~/.local/bin/agent-census` link under the linux section.
- `tests/agent-census/` — captured fixtures plus a nushell runner that
  drives the pure layer. The repo has no nushell unit harness today
  (`tests/` holds only the dockerized `tmux-ssh` suite), so this card
  introduces a small one.
