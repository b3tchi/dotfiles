# Feature [[cat001]] [[product]]

## providing

A Secret Service keyring on WSL, backed by gopass, plus an IPv4 loopback
bridge for the canvas-authoring MCP server's OAuth redirect. Together they
let libsecret clients — MSAL above all — persist tokens and complete
interactive sign-in on a box that has no desktop keyring and no working
`localhost` path from the Windows browser.

## api_surface

`gopass-secretservice` claims the well-known bus name
`org.freedesktop.secrets` on the session bus and implements
`org.freedesktop.Secret.Service` (`OpenSession` — plain algorithm only,
`SearchItems`, `GetSecrets`, `Unlock`, `Lock`, `ReadAlias`, `SetAlias`,
`CreateCollection`), `org.freedesktop.Secret.Collection` (`CreateItem`,
`SearchItems`, `Delete`), `org.freedesktop.Secret.Item` (`GetSecret`,
`SetSecret`, `Delete`) and `org.freedesktop.Secret.Session` (`Close`), with
the properties libsecret reads on each. The single collection is exported at
both `/org/freedesktop/secrets/collection/login` and the alias path
`/org/freedesktop/secrets/aliases/default` — libsecret addresses the default
collection by alias path directly, and exporting only the canonical path
fails with "Object does not implement the interface".

`GOPASS_SECRETSERVICE_PREFIX` overrides the store namespace (default
`secretservice`). `GOPASS_SECRETSERVICE_ALLOW` overrides the caller
allowlist — comma-separated prefixes matched against the item's
`xdg:schema` attribute, `*` to allow everything (default
`com.microsoft.powerapps.canvasmcp`). A `CreateItem` whose attributes fall
outside it is refused with `AccessDenied`, so no unrelated application can
accumulate secrets here. Values over 1 MiB are refused with
`LimitsExceeded`. Encryption, unlock and sync are gopass's, not this
daemon's.

`canvas-mcp-relay` takes no arguments. It polls `ss -ltnp` each second and,
for every `[::1]:<port>` listener owned by a `CanvasAuthoring` process with
no IPv4 counterpart, accepts on `127.0.0.1:<port>` and splices to
`[::1]:<port>`.

## data_model

Each Secret Service item is one gopass secret at
`<prefix>/<sha256-of-attributes>`, holding JSON: `attributes`, `label`,
`value` (base64), `content_type`, `created`, `modified`. The id is the first
32 hex chars of the sha256 over the item's attribute pairs sorted by key, so
storing the same attribute set replaces the item rather than duplicating it —
which is what libsecret's store-or-update semantics expect.

Access is confined to the namespace: every store path passes a
`^[0-9a-f]{32}$` id check before reaching gopass, and listing runs
`gopass ls --flat <prefix>` rather than over the whole store, so the daemon
never enumerates unrelated secret names. Secrets are held in memory only for
the length of a call; gopass owns everything at rest.

Relay state is a port set held in memory, rebuilt from `ss` on every tick;
nothing is persisted.

Residual risk, accepted knowingly: persisting a refresh token to disk is
weaker than the previous memory-only accident, and encryption at rest is only
as strong as `/mnt/c/Users/jbecka/.gopass-age-password`, which DrvFs cannot
permission. The Secret Service spec has no caller authentication, so any
same-user process can read items over the session bus; unlike gnome-keyring
this daemon never locks or prompts, and it speaks only the `plain` algorithm,
so secrets cross the bus unencrypted. `core.autopush`/`core.autosync` are
disabled on the store so a future remote cannot push tokens off the box.

## sample

```text
$ secret-tool store --label="test" app claude   # -> CreateItem
$ secret-tool lookup app claude
ns-test-ok
$ gopass ls
└── secretservice/
    └── caaf7c06f1fbb6a67eea1b9f07c474a2      # MSAL token cache

$ journalctl --user -u gopass-secretservice -n2
gopass-secretservice up: org.freedesktop.secrets (store secretservice/)
CreateItem caaf7c06… (label="MSAL token cache for Power Apps Canvas MCP server.")
```

Before: every `connect` call opened a browser sign-in, or hung on
`Connecting - waiting for sign-in (Ns)...` until killed. After: first
`connect` signs in once, later ones return instantly from the cache.
