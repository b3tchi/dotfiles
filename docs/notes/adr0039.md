# ADR [[cat001]] [[cat002]] [[product]]

## title
Go for clipd, the cross-host clipboard agent

## title
Go for clipd, the cross-host clipboard agent

## context
[[sp039]] replaces the xrdp-chansrv clipboard channel and
`clip-win-bridge.sh` with [[ft018]]: one `clipd` binary per host that
watches the native clipboard, writes each copy as an age-encrypted file
into a LAN-only Syncthing folder, and decrypts a remote entry only when
the user picks it from the `$mod+v` picker. It must run on the Linux X
sessions (`:40` kwi3, `:10` i3) and natively on the Windows host, and the
same source should later serve Termux.

[[adr0003]] is the standing rule for a compiled Go helper, a strict
three-condition AND. clipd meets condition 1 (a long-running agent per
display) and condition 3 (a clipboard event loop is not a pipeline that
completes and exits). It does not meet condition 2: it holds **no network
listener** (Syncthing owns the transport), proxies no stream, and its
event rate is one clipboard change per human copy. Stretching condition 2
to cover it would make the gate uncitable for the next daemon that
honestly needs it. [[adr0021]] (hotkeyd) and [[adr0030]] (agent-monitor)
set the precedent for this shape: admit Go on stated, binding-level merits
without widening [[adr0003]].

The merits are concrete and were measured in [[poc024]]:

- **Win32 clipboard from one cgo-free binary.** `AddClipboardFormatListener`
  on a message-only window, `GetClipboardSequenceNumber`, the
  `ExcludeClipboardContentFromMonitorProcessing` check, and writes carrying
  `CanIncludeInClipboardHistory=0` / `CanUploadToCloudClipboard=0` all
  worked from Go via raw `syscall.NewLazyDLL` calls with
  `CGO_ENABLED=0`. Nushell cannot own a window message loop; pwsh can, but
  only as a second implementation of the whole agent.
- **age in-process.** `filippo.io/age` is the reference implementation, in
  Go. Encrypting and decrypting in-process means plaintext never crosses a
  pipe to an `age` child, and no `age` binary is needed on Windows.
- **One source, three targets.** The same module cross-compiles to
  `linux/amd64`, `windows/amd64` and `linux/arm64` (Termux) from one
  machine. A shell agent on Linux plus a pwsh agent on Windows would be two
  implementations of the entry format, TTL and never-send rules — the
  security-critical part — drifting independently.

Options surveyed: (a) nushell/sh agent on Linux plus pwsh on Windows —
two implementations of the secret-handling path, plaintext piped through
`age` children, rejected; (b) stretch [[adr0003]] condition 2 — rejected,
same reasoning as [[adr0021]]; (c) a new ADR, on the [[poc024]] evidence,
that decides Go for clipd and states its wrapper surface explicitly.

## decision
**Go is authorised for `clipd` ([[ft018]]), standing on its own merits —
not on [[adr0003]]'s three-condition gate.** Condition 2 does not hold
(no listener, no stream, human-rate events) and this ADR does not borrow
it. The decision rests on the three merits above: Win32 clipboard access
from one cgo-free binary, age encryption in-process, and one source
cross-compiled for Linux, Windows and Termux. The only direct dependency
is `filippo.io/age` (Win32 via stdlib `syscall`); any other direct import
needs a new ADR.

**Wrapper surface — [[adr0003]]'s nushell-wrapper rule, discharged per
platform:**

- **Linux:** `nushell/actions/clipd.nu` is the user-facing front end
  (`setup | peer add | peer rm | status | start | stop`). Users and
  scripts manage clipd through it.
- **Windows:** no nushell is required on the host. The front end is a
  logon scheduled task that runs `clipd.exe agent windows`, set up by
  `clipd/windows/setup.ps1`, plus the `clipd.exe` CLI itself
  (`list | pick <id> | pick --latest | status`) until the Quickshell
  picker reaches Windows through kwi3.
- **Machine callers on the hot or boot path may invoke the binary
  directly:** the session launchers (i3 `exec_always`, the kwi3 session
  script) start `clipd agent x <display>`, and `quickshell/qs-clip.sh`
  calls `clipd list` / `clipd pick`. Same reasoning as [[adr0015]] and
  [[adr0021]]: a nushell hop on the `$mod+v` path or in session start adds
  startup cost where the user is waiting and nothing is gained. This
  carve-out covers these three callers only.

**Scope — this authorises one binary, nothing wider.** It does not touch
[[adr0003]]'s gate or wrapper mandate for any other helper, does not
authorise rewriting the existing `i3/scripts/clip-*` sh daemons in Go
(they are replaced by [[sp039]] or stay as they are), and adds no network
listener: if clipd ever needs one, that is a new decision.

## consequences
**Positive.** One implementation of the entry format, TTL, never-send
rules and age handling runs on every host, so the secret-handling path
cannot drift between platforms. Plaintext stays in the clipd process —
no `age` child pipe, no temp files. The Windows agent is a single static
`clipd.exe` with no interpreter or cgo toolchain on the host. Termux
becomes a cross-compile, not a port.

**Negative, and load-bearing.** A Go toolchain is a build-time dependency
on every Linux host that builds clipd (`clipd/dot.yaml` needs the
`command -v go` guard and the build-to-temp-then-move pattern from
hotkeyd). The Windows binary is cross-built on Linux and copied over, so
the Windows install depends on a Linux build step. `filippo.io/age` and
its transitive `golang.org/x/crypto` are third-party code in the trust
path of every clipboard secret; version bumps need the same review as
code changes. The
Linux front end is split between `clipd.nu` (management) and direct calls
from three machine callers, so a reviewer must check this ADR to know
which callers are allowed to skip the wrapper. The repo now has three
Go-on-its-own-merits ADRs ([[adr0021]], [[adr0030]], this one) beside
[[adr0003]]; that bookkeeping is accepted rather than folded into a
wider gate.
