# ADR [[cat001]] [[product]]

## title
every bus party is addressed by a minted, never-reused address; names are labels for display

## context
[[adr0028]] bundled two decisions in one file. Its transport clause — tmux is
the display and process host and never carries a message — is load-bearing,
repeatedly cited, and untouched by this record. Its final sentence is a second,
separable decision: "Workers are addressed by stable UID and window NAME, never
by `@window-id` or `%pane-id`." That sentence has now been contradicted twice
by shipped code.

`dotfiles-3rsq` recorded the first half: workers are in fact addressed by
`window_id`, not by window name. `dotfiles-1d1f` contradicted the other half —
the bus does not address workers by UID at all.

The reason it changed is that a minted name is not an identifier, it is a
convention a function maintains. `dotfiles-bg65` is what that costs: `mint-uid`
searched a single run's directory, so once sp029 T9 retired `--run`, every
spawn of a role minted `<role>-1` forever. Two live workers shared one queue,
`resolve-run` reached whichever run sorted first, and the other was left
"addressable by nothing but `rm -rf`". Uniqueness was then made project-wide —
still maintained by a minting function, still not guaranteed by the identifier.

[[adr0028]]'s own stated reasoning for naming UIDs was anti-recycling: tmux ids
are reused, so a stale target silently resolves to a different worker. That
reasoning is correct and this decision serves it more strongly, which is why
this supersedes a clause rather than reversing a principle.

## decision
Every addressable party on the bus — workers and runs alike — is addressed by a
minted address that is unique by construction and never reused. The mint is a
ULID behind an `a` prefix; nothing derives an address from a name, a session, a
tmux id, or a counter.

Names become labels. A registry maps address → label, and every display
resolves through it, falling back to the RAW address when resolution fails —
never to a guess, per [[adr0017]]. The CLI accepts labels and resolves them
before anything reaches the wire, so an operator still types `peer-4` while
only the address travels.

This supersedes [[adr0028]]'s addressing sentence only. Its transport clause
stands unchanged and unqualified: tmux hosts and displays workers, and never
carries their messages.

## consequences
The failure mode `dotfiles-bg65` demonstrated is now unrepresentable rather
than prevented: two parties claiming one label get different addresses, and a
message to one leaves the other's queue empty. The anti-recycling property
[[adr0028]] wanted is strictly stronger, since an address is never reused even
across a respawn that keeps its session.

The costs are real and were paid immediately. Addresses are unreadable by
humans, so every display and every log line now depends on a registry lookup;
when that registry is missing or stale, an operator reads a ULID instead of a
name. `agent-monitor` needed a rendering fix before the change was usable at
all — a head-truncated address is its timestamp prefix, so two senders minted
in the same second rendered identically until the tail was elided instead.

A message addressed to a label nobody has claimed now goes nowhere
permanently, where the label-keyed queue would have delivered it once the
claimant appeared. No caller relies on that, and `dotfiles-bocf` proposes
refusing an unresolvable label outright, but until then the tolerance is a
silent discard.

Uniqueness rests on the mint's randomness rather than on a check. That argument
holds by construction, with one narrow exception found during audit: the mint
is not `--env` while the ULID helper it wraps is, so an ambient primed seed
could in principle repeat an address. It is unreachable in production and the
address-claim refuses a duplicate loudly, but the guarantee is "random plus a
refusal", not "random alone".
