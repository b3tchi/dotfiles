# ADR [[cat001]] [[product]]

## title
the bus carries two envelope kinds, and kind names the shape of content

## context
The worker bus shipped with four envelope kinds — `inbox`, `result`, `error`,
`identity` — and a `content` field the transport does not inspect. Three
separate defects in one week traced to that vocabulary rather than to any code
that used it.

`dotfiles-9oa4`: [[ft014]]'s card documented a `message` kind while the wire
carried `inbox`, so a consumer written from the documentation special-cased a
kind that never arrives and fell through on the one that does.

`dotfiles-56lh`: a worker's result reached the bus stamped `inbox`, because the
relay went through a writer that hardcoded that kind. The reader's one
sanctioned prettifier keys on `kind == "result"`, so it could never fire, and
every worker result rendered in `agent-monitor` as a bare `{` for weeks.
Nothing failed; the envelope was well-formed and simply lied.

`dotfiles-u4oy`: `bus-settled`'s `error` never reached the bus at all, so a
worker that settled without reporting produced silence its commissioner never
heard.

Reviewing the vocabulary against what consumers actually branch on showed the
four kinds were not four types. `error` differed from `result` only in spelling
its outcome field `code` instead of `status` — and `protocol_error`, its sole
value, was already a legal `WORKER_STATE` beside `complete` and `failed`. A
comment in `derive-state` admitted the split existed to paper over that
mismatch. `identity` was never a bus envelope at all: it lives in the durable
state root so an accepted worker stays resumable after cleanup and logout.
`inbox` was the default, and nothing branched on it — which is precisely why
forgetting to set a kind was invisible.

The shape of `content` already distinguished the two real cases: prose arrived
as a JSON string, machine state as a JSON object. That distinction was
observable to any human reading an envelope and unavailable to every consumer,
because the field that was supposed to carry it did not.

## decision
The bus vocabulary is exactly two kinds, and `kind` names the SHAPE of
`content` by rule:

- `message` — `content` is a JSON string. Freetext addressed to a reader.
- `state` — `content` is a JSON object carrying `status`, drawn from the
  existing `WORKER_STATES`.

`validate-envelope` enforces the pairing at the WRITER. An object stamped
`message`, or a string stamped `state`, is refused before anything reaches
disk. This is the load-bearing half: it makes `dotfiles-56lh` unrepresentable
rather than merely fixed.

`result` and `error` both become `state`; the error envelope's `code` becomes
`status`. `identity` leaves the bus vocabulary entirely and is validated on its
own gate as the durable record it always was.

A worker that needs a human decision reports `status: waiting_human` (or
`blocked`) with the question as its `summary` — no separate `question` kind, no
`options` field, and no correlation id on the reply, because a blocked worker
has at most one unanswered question by construction. The answer is an ordinary
`message`.

## consequences
A consumer can tell machine state from prose by reading one field, and a
mis-stamped envelope cannot be written at all. `derive-state`'s kind dispatch
disappeared entirely; the comment explaining why two shapes needed two branches
went with the code it explained. `agent-monitor`'s subject renderer now covers
errors and blocked workers, which the `result`-only branch never reached.

The cost is a real loss of resolution. `status` must now carry every
distinction `kind` used to make, so a consumer wanting only errors filters on a
value rather than matching a type, and a future kind of state that is genuinely
not a worker status has nowhere natural to live — it would need either a new
status value that stretches the word, or a third kind and a fresh argument for
why two were not enough. The single-outstanding-question assumption behind the
uncorrelated answer is unenforced: nothing rejects a second question from a
blocked worker, and if that ever becomes possible the reply routing breaks
silently rather than loudly.

`identity` leaving the vocabulary means two validation gates exist where there
was one, and they can drift apart. That risk is mitigated by extracting the
shared addressing rules into one `validate-addressing` both call, with a test
that feeds a single malformation to both gates and requires both to refuse —
so loosening one and not the other fails.

This narrows [[ft014]]'s `## data_model`, which still documents the retired
four-kind vocabulary including a sample envelope that would no longer validate
(`dotfiles-4th4`). Fixing that card is the drift this decision exists to stop.
