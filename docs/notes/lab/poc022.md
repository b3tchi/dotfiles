# PoC [[cat001]] [[board]]

## informs
[[sp028|pi-visible-tmux-workers]]

## hypothesis

Pi 0.84.4 can run a named worker inside an existing linked tmux project group,
persist and resume one session ID, expose worker metadata, signal completion,
and clean up only the worker window while leaving the project group intact.

## method

A throwaway `/tmp/poc-sp028-*` directory and private tmux socket were used;
no repository source or normal tmux session was touched. The experiment created
two linked sessions in group `pocproj`, launched a one-shot Pi worker in
window `impl-demo`, attached stable pane metadata, waited for completion via
`tmux wait-for`, closed the worker window, then launched `rev-demo` with
`pi --session <same-id>`. Pi used a private session directory. Versions:
Pi 0.84.4 and tmux 3.7c. The private server and scratch directory were
deleted after measurement.

## result

Validated. The worker appeared in both linked views with identity
`impl-demo@pocproj` and `@pinned=1`. Its first run exited 0 and returned
`POC_OK`; the resumed run exited 0 and returned `POC_RESUMED`. Exactly one
session JSONL existed before and after resume. Both completion signals woke the
waiting coordinator. Closing both worker windows left only the seed `main`
window. Two earlier harness attempts were inconclusive because the test used a
wrong tmux group construction and relied on `pane_current_command`; neither
failure implicated Pi or the proposed protocol.

## recommendation

Proceed with [[ft014]] and [[sp028]]. Match the existing `tmux-start` group
construction, identify workers through explicit pane options rather than
`pane_current_command`, keep session storage independent of tmux window
lifetime, and use private tmux sockets in integration tests.
