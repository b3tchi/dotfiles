# PoC [[cat002]] [[board]]

## informs
[[sp044|us028-ultrawide-lens-focus-control]]

## hypothesis
With a device-tree `dongwoon,dw9800k` actuator on the s5kjn1's CCI bus
(VAF supply + `lens-focus` link), (a) the mainline `dw9719` driver drives
the lens, (b) libcamera's simple pipeline exposes `LensPosition`, (c) a
focus value set before streaming survives a camera start, and (d) EV
compensation changes the image.

## method
Throwaway dtb patch (`~/.cache/poc-sp044/`, discarded), kernel 7.2.9,
libcamera 0.8.0, GStreamer 1.28.7, 2026-11-22. `fdtput` on a copy of
`/boot/dtbs/qcom/sm7325-nothing-spacewar.dtb`: phandle 0x1c6 on
`regulator-camu-vaf`, new `actuator@c` (`compatible =
"dongwoon,dw9800k"`, `reg = <0xc>`, `vdd-supply = <0x1c6>`, phandle
0x1c7), `lens-focus = <0x1c7>` on `camera@2d`; flashed with `mkinitfs`
(the `spacewar-dtb-fix` path unit saw "already patched" and did not
re-flash), reboot. Original dtb backed up first. Then: media graph,
`v4l2-ctl` on the lens subdev, `cam --list-controls`, and a live view
(Python + `libcamerasrc` -> `waylandsink`) with focus set through
`v4l2-ctl` as the user and exposure through `libcamerasrc` properties.

## result
- (a) validated. `18-000c` binds to `dw9719` as `dw9800k`; the media
  graph gets `dw9719 18-000c` (subtype Lens, `/dev/v4l-subdev29`, group
  `video`) with `focus_absolute` 0-1023, default 0. Setting it as the
  plain user moves the lens; the user confirmed focus works in live view.
- Power-up error at boot: `dw9719 18-000c: Error writing reg 0x0002:
  -6`, three times. The regulator-fixed VAF has no `startup-delay-us`, so
  the driver's first write after enable likely lands before the chip is
  up. The lens works anyway afterwards; the error still needs a fix.
- (b) invalidated. libcamera opens the lens (`'dw9719 18-000c': Control:
  Focus, Absolute`) but `cam --list-controls` shows no `LensPosition`:
  the simple pipeline / softISP (no AF algorithm) does not publish lens
  control. Focus is reachable only through the V4L2 subdev.
- (c) validated. `focus_absolute=377` set before streaming still reads
  377 two seconds after the stream starts; libcamera does not reset it.
- (d) invalidated. `ExposureValue` is listed ([-8..8]) but changing it
  live has no visible effect: the softISP AGC ignores it. Manual
  `ExposureTime` / `AnalogueGain` with AE off work live (user-confirmed).
- Idle power: VAF stays `enabled users=1` while no app streams.
  wireplumber and quickshell keep the lens subdev open (libcamera holds
  subdev fds for the life of its CameraManager), and `dw9719_open` takes
  a runtime-PM reference, so the VCM stays powered whenever any libcamera
  client runs.

## recommendation
Keep the DT approach: `actuator@c` as `dongwoon,dw9800k` with
`vdd-supply = <&vreg_camu_vaf_1p8>` and `lens-focus`, through the
nothing-pmos dtb build. Add `startup-delay-us` to `regulator-camu-vaf`
(try 10000) to clear the power-up `-6`. The default far focus can be a
boot-time `v4l2-ctl -c focus_absolute=377` on the lens subdev: the value
survives camera start. Three gaps need decisions before planning:
1. `LensPosition` through libcamera needs a simple-pipeline patch
   (forward `LensPosition` to `CameraLens`), or the AC accepts the V4L2
   subdev as the camera API for focus.
2. EV compensation needs a softISP AGC patch, or the exposure AC drops
   EV and keeps manual exposure time + gain (which work today).
3. "Motor off when idle" fails while wireplumber / quickshell hold the
   lens open; it needs a driver change (power on stream, not on open),
   a libcamera change, or a relaxed AC.
