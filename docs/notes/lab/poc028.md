# PoC [[cat002]] [[board]]

## informs
[[sp043|us027-ultrawide-focus-actuator]]

## hypothesis
The s5kjn1 ultrawide module on the Nothing Phone (1) has a focus actuator
(VCM) on its CCI bus that answers over I2C and, when driven, visibly
sharpens a scene the parked lens renders soft.

## method
Throwaway scratch dir (discarded), kernel 7.2.9, libcamera 0.8.0
(`cam -c1`, 1280x720 XRGB8888), i2c-tools + libgpiod, 2026-11-22, run on
the phone itself in five passes:
- Downstream: nothing-pmos `docs/status.md` names the ultrawide actuator
  `dongwoon,dw9800w @ 0xc` on `cci1_i2c0`. The live DT has no actuator
  node and no `lens-focus`; the s5kjn1 node has only vdda/vddd/vddio.
  The kernel ships `dw9719.ko` (`CONFIG_VIDEO_DW9719=m`) with
  `dongwoon,dw9800k` among its compatibles.
- Live DT: s5kjn1 at `18-002d`, EEPROM `gt24p128e` at `18-0051`. The DT
  already defines `regulator-camu-vaf` (`vreg_camu_vaf_1p8`,
  regulator-fixed, TLMM gpio 71 active high, vin = `bob`), but nothing
  consumes it: 0 users, disabled.
- Powering VAF by hand: unbind `regulator-camu-vaf` from
  `reg-fixed-voltage`, `gpioset -c gpiochip4 71=1`, rebind on exit.
- Per lens position: write DW98xx regs (0x02 = 0x00 power-up, 0x03/0x04 =
  10-bit position), read back, run `cam --capture=25` as the user, keep
  the last frame. One baseline frame with VAF unpowered (today's state).
- `cam` must run as the user: as root libcamera allocates from the
  root-only `default_cma_region` dma-heap, which is exhausted (24 MB CMA,
  24 kB free) -> `dma-heap allocation failure`; the user falls back to
  udmabuf.

## result
- VAF off: every access to `0x0c` NACKs (`No such device or address`),
  streaming or not. This is why no VCM was visible before.
- VAF on: `i2cdetect -r 18` shows `0x0c`; reg 0x00 = `0xf2` (DW98xx IC
  id), reg 0x01 = `0x07`. Power-up ACKs; every position write 0-1023
  reads back exactly and holds across camera restarts.
- The lens moves: on a room scene (~0.5-2 m, dim) pos
  100-250 resolves fabric pattern, a cable and object edges; pos 1023 and
  the VAF-off baseline are heavily blurred. The unpowered lens rests at
  the close-focus end, which explains today's soft stills ([[poc027]]).
- Laplacian variance (400x300 centre crop) is noise-dominated: baseline
  1555, peak 1810 at pos 250, 1603 at pos 1023. The images are the
  evidence; the metric only orders them.
- EEPROM (16 KiB) holds the module serial `F13570042C5XM31021` and a
  flagged, checksummed block at 0x92 with 10-bit values 564/396/408.
  These are plausibly AF calibration codes; the layout is unconfirmed.
- Caveat: no truly distant (infinity) scene was tested; best focus for
  infinity is expected at or below pos ~100.

## recommendation
A focus actuator exists and works. Draft the follow-up story for the
hardware layer: add an `actuator@c` node under the s5kjn1's CCI bus
(`compatible = "dongwoon,dw9800k"`; dw9800w is the same family, verify
the register map against `dw9719.c`), with `vdd-supply =
<&vreg_camu_vaf_1p8>`, and a `lens-focus` phandle on the s5kjn1 node, via
the nothing-pmos dtb fix. libcamera then sees a lens with LensPosition.
Until AF exists, park the lens at a fixed far-focus code (~100-250) at
stream start. Run `cam` as the user, not root, while CMA stays this small.
