# PoC [[cat001]] [[cat002]] [[board]]

## informs
[[sp038|session-launcher]]

## hypothesis
A nushell launcher that (a) builds the child env with `env -i` from a
NUL-separated snapshot written once at session start, (b) cds to the
snapshot's HOME, and (c) runs `setsid -f /bin/sh -c '<close every fd > 2>;
exec "$@"'` produces, from a hotkeyd-shaped caller (own session, clean env,
no extra fds) and from a restore-shaped caller (inside a tmux pane: TMUX,
TMUX_PANE, PWD, NU_*, SHLVL, OLDPWD set, cwd elsewhere, non-CLOEXEC fds 7
and 9 open), two children with identical parent, session shape, fd set,
environ and cwd. A naive `setsid -f` launcher does not.

## method
Scratch dir only (Claude scratchpad `poc-launch/`, deleted afterwards), no
repo code, no X server (fds/env/parentage are /proc facts, a `sleep` child
suffices), sandboxed HOME and XDG_RUNTIME_DIR, display name :977 never
opened. nu 0.116.0, util-linux setsid 2.42.4, WSL2. Files: session-start.sh
(`env -0 > $XDG_RUNTIME_DIR/wm-session-env`), launch.nu (candidate),
naive.nu (`^setsid -f ...$argv`), probe.sh (child: writes
/proc/$$/stat ppid/sid/pgid, cwd, fd list, sorted environ minus `_`, then
`exec sleep 20`). Path A: `env -i $BASE setsid sh -c "nu launch.nu probe A"`
(proc.Run shape). Path B: subshell in /tmp with `exec 7>… 9<…` and the noisy
env, `nu launch.nu probe B`. Path N: same noisy caller, naive.nu. Probes
killed by exact pid.

## result
- A and B: `ppid=1`, each its own session (sid == pgid), cwd = snapshot
  HOME, fds `0 1 2 3 10 255` - the same set a bare `sh probe.sh` with no
  launcher shows (3/10/255 are the probe shell's own), so NO caller fd
  survived. `diff A.env B.env` -> IDENTICAL (PWD = HOME, SHLVL=1, no TMUX,
  no NU_*).
- N (naive): fds `0 1 2 3 7 9 10 255` - the caller's 7 and 9 LEAKED; cwd
  /tmp; environ carries TMUX, TMUX_PANE, NU_VERSION, nushell's own
  CURRENT_FILE/FILE_PWD/LAST_EXIT_CODE, caller PWD.
- Parent: after `setsid -f` the intermediate exits at once, so both
  children reparent to the namespace's reaper (pid 1 here); under a session
  with a subreaper both reparent to THAT one - same for every caller.

## recommendation
Validated. Build `wm-launch-detach` exactly in this shape: env from the
session snapshot via `env -i` (never the caller's), cwd = snapshot HOME,
`setsid -f /bin/sh -c` with an explicit close-every-fd->2 loop before
`exec "$@"` - `setsid -f` alone leaks every non-CLOEXEC caller fd, and
nushell itself adds CURRENT_FILE/FILE_PWD/LAST_EXIT_CODE to a child's env.
Missing snapshot: refuse by name (exit 78), never fall back to the caller's
env. The snapshot must be (re)written at every session start (xinitrc /
kwi3-session-env.sh) so DISPLAY and friends are never stale. Not covered
here: KWin `systemd-run` and Windows `Start-Process` backends (stub-tested
in the real work), and a real terminal on a real display (the sp038 proof
test).
