# PoC [[cat001]] [[board]]

## hypothesis
An agent can ask its operator a question and resume on the answer with **no
messaging channel built at all** — no `Stop` hook, no tmux nudge, no monitor
subagent — because a `run_in_background` Bash call parks the agent and the
harness wakes it when the command exits. If true, most of [[poc019]] round 8's
recommended machinery is unnecessary.

Secondary claims, all gaps [[poc019]] left open: the loop survives a human
slower than the park window; concurrent agents share one store without
crosstalk; the whole protocol can hide behind a CLI so the agent knows no path;
and the operator side can be a plain folder with no command at all.

## method
Isolated throughout: tmux server `tmux -L pocinbox`, scratch dir under the
session scratchpad, scratch `--settings` files. The real `~/.claude/settings.json`,
the `default` tmux server, and the live `preview-d` (:4200) / `akm-graph-d`
(:4810) daemons were never touched. Workers on `--model haiku`, Claude Code
2.1.220, tmux 3.7b. Every path absolute, per [[poc019]] round 8's cwd hazard.

Four delivery designs were built and measured in sequence, each discarded when
the next beat it:

1. **`Stop` hook park** — [[poc019]] round 8's design, rebuilt: `.ask`/`.reply`
   file pair, hook parks scanning for a reply, delivers via
   `hookSpecificOutput.additionalContext`.
2. **Monitor subagent** — single request/response file; parent dispatches a
   subagent that blocks in one Bash call and returns the reply as tool output.
3. **Direct foreground Bash call** — same, minus the subagent.
4. **`run_in_background` Bash call** — agent launches the blocking command
   detached and ends its turn; the harness re-invokes it on exit.

Designs 2–4 sat behind a Python CLI (`agent-inbox`, per [[adr0015]]) owning
store location, filenames, waiting, and filing; the agent's whole interface is
`agent-inbox ask "<q>"` → answer on stdout.

That CLI is kept alongside this record as `poc020-agent-inbox.py` — a reference
artifact only, so the findings below can be read against real source. It is
throwaway PoC code: no tests, no review, and a list of deliberate defects in its
footer. The shipped version is built fresh through the lifecycle; this file is
not promoted.

Measured across runs: token cost per exchange, whether the reply steered the
artifact (answers deliberately chosen *against* the model's default — JSON when
it kept emitting YAML, PIPE, PYTHON, SEMICOLON), concurrency with 4 agents on
one store, and a 5-round multi-turn conversation with 3 operator
counter-questions.

## result

### Background Bash retires the entire channel (the headline)
- An agent running `agent-inbox ask` with `run_in_background: true` ends its
  turn in ~6s and parks. On reply it self-resumes: pane logged
  `Background command "..." completed (exit code 0)`, then it read the output
  and wrote the artifact. **No nudge was sent.** Verified explicitly by
  answering and sending nothing.
- This makes the `Stop` hook, the park loop, the tmux `send-keys` nudge, and the
  monitor subagent all unnecessary. Every one of them existed only to solve
  "nothing wakes a parked agent" — which the harness already does.

### Cost, measured
| design | tokens per exchange |
|---|---|
| monitor subagent | ~15 100 |
| direct foreground call | 247 |
| `run_in_background` | **49–73** |

~60x cheaper than the subagent for identical behaviour. The subagent buys only
context isolation of the retry loop, which is three lines.

### The Bash tool's 120s DEFAULT timeout is the trap
A subagent blocking on the CLI died at ~2m16s, not at the CLI's 540s. It then
failed *messily*, not cleanly: `Error: summary is required when message is a
string`, a self-resume into the background, and the parent degrading into idle
polling. The 600s ceiling is opt-in — callers must pass an explicit timeout.
Foreground callers therefore need `--timeout` under 120s unless they set it;
background callers appear unbound (probed at 1800s, though no run actually
waited that long — see open questions).

### A retry must be idempotent or it forks the conversation
Naive retry after a timeout minted a *second* request and orphaned the first.
Fixed by matching on question text: re-asking the same question resumes the same
pending file, and a reply that landed between retries is returned immediately.

### Multi-turn works, and needs no threading
One file per round is sufficient. A 5-round conversation completed correctly:
the operator answered three questions with *counter-questions* ("could be other
format?", "xml is not an option?"), and the agent re-asked each time, converging
on `report.json` with the right columns and sort order. Separately, an operator
negotiated `SEMICOLON` — a delimiter absent from the original options — into the
answer set, and got `alice;30`.

### The silent deadlock is the real hazard
Given a counter-question, one agent reasoned about it correctly, enumerated its
options, then **ended its turn without re-asking**. Result: nothing pending,
nothing running, agent `idle`. The operator sees an empty inbox and concludes
the work finished. It required a manual nudge to recover.

Two mitigations, both verified: a prompt rule — *never end your turn without
either finishing the work or having a pending ask* — carried a 5-round run
through 3 counter-questions with no stall; and the condition is externally
detectable as registry `idle` + no pending request + task incomplete, the same
reconciling poll [[poc019]] round 6 recommended for permission stalls.

### Concurrency is a non-issue
4 agents (`alpha`/`beta`/`gamma`/`delta`) on one store, each addressed by a
spawn-assigned `AGENT_NAME`, all answered differently, zero crosstalk — every
artifact matched its own reply.

### Operator side needs no CLI
Answering by plain file edit, with `agent-inbox` never invoked, worked for all
four agents. Filenames carry the asker and the question
(`beta--field-delimiter-for-the-data-file-comma-or-pipe.md`), the template
explains itself, and `sent/` becomes a readable conversation archive.

### Smaller findings
- **The inbox must be reachable or it stalls on its own first write.** With the
  store outside the agent's workspace, `acceptEdits` does not cover it and the
  agent hits a permission prompt — the inbox meant to prevent stalls causing
  one. Fixed with `--add-dir`.
- **`--add-dir` is variadic** (`<directories...>`): unless another flag follows
  it, it swallows the prompt and the agent silently starts with no task.
- **Trust prompts** fire for any fresh non-inherited dir, confirming
  [[poc019]] round 3; subdirs of a trusted dir inherit and stay silent.
- **Replies carrying side-instructions are ignored** — "ok use json notify me
  via mail when done" produced the JSON and no notification.
- Slug-based filenames truncated at 48 chars lose the meaningful tail
  (`...comma-pipe-or-.md` dropped "semicolon").
- The CLI's default store is created on any invocation, so a call without
  `$AGENT_INBOX` set silently creates `~/.local/state/agent-inbox`.

## recommendation
Build the inbox on **`run_in_background` + a CLI**, and build none of the
channel machinery.

- **Agent interface is one verb**: `agent-inbox ask "<question>"`, launched with
  `run_in_background: true`. The agent learns no path, no filename, no protocol.
- **Operator interface is a directory**, not a command. Self-describing
  filenames, a template that states the whole protocol inline, and automatic
  filing to `sent/` as the conversation archive.
- **Do NOT build**: a `Stop` hook channel, a park-then-idle loop, tmux
  `send-keys` nudges, or a monitor subagent. This *supersedes* [[poc019]] round
  8's recommendation, which was correct only because that PoC never tested
  background dispatch — its whole delivery design compensates for an absence the
  harness already fills.
- **Make `ask` idempotent on question text.** Non-negotiable: without it any
  retry forks the conversation.
- **Ship the anti-stall prompt rule with the feature**, plus the `idle` +
  no-pending reconciling detector. The silent deadlock is the only failure mode
  here that loses work quietly.
- **Keep the store at `$XDG_STATE_HOME/agent-inbox`, mode 0700, per
  [[adr0013]]**, and settle retention there — these files quote whatever the
  agent had in context.
- Python was right for this proof per [[adr0015]]; a shipped version should
  settle the [[adr0003]] compiled-helper question, though nothing here needs
  compiled speed.

Open, not settled by this PoC: whether background calls have any duration
ceiling (probed at 1800s, longest actual wait ~9 min); behaviour across a long
idle gap (hours); whether an editor whose write-then-rename changes the inode
still trips the mtime watcher (nvim `:w` worked, exotic configs untested); and
desktop notification on a new request, where [[ft010]] would fit.

All scratch dirs, the `pocinbox` tmux server, and the accidental
`~/.local/state/agent-inbox` were removed. The only surviving code is the
reference artifact noted in `## method`, reconstructed beside this record after
teardown rather than carried over from the experiment.
