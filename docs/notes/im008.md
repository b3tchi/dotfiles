# Implementation [[cat002]] [[cat001]] [[product]]

## solves
none — fix+feature spec
[[sp019|notification-service-and-history-browser]]; the
`org.freedesktop.Notifications` first-owner-wins collision between the
`:0` and `:10` bars ([[adr0004]]) was captured directly at spec stage,
with the history-browser scope promoted to [[ft010]]. No source
`us###`.

## approach
Split the notification stack into one owner + many read-only
consumers — the shape [[ft007]] and the `qs-stats-daemon` singleton
already prove on this repo, recorded as [[adr0012]].

**Owner.** A user-scoped headless `quickshell -p notif` daemon
(`quickshell/notif/shell.qml` — no Window anywhere) hosts the single
`NotificationServer` and owns the user-bus name. It is launched from
`qs-start.sh` behind a USER-LEVEL flock + pgrep guard (the
`qs-stats-daemon` mould: sha1 hash over the profile QML + store
script, restart-on-change), not the per-display `qs_kill_session`
scoping — that axis keeps two *bars* apart and is wrong for a bus
singleton; the session kill sweep spares the daemon by matching its
`/proc/<pid>/cmdline` against the notif profile path. On each
notification the daemon makes two serialized writes through
`qs-notif-store.sh`: `append` (body on stdin, never argv) into the
persistent file-per-entry store under
`${XDG_STATE_HOME:-$HOME/.local/state}/qs-notif/` (age-capped ~2
days, pruned on write — the deliberate memory-only departure recorded
in [[adr0013]]), then `state` to atomically rewrite the live-state
file under `$XDG_RUNTIME_DIR` (count / critical / seq / last). Only
the daemon ever mutates store or state; single-writer extends to the
daemon's own internal ordering via a job queue that runs every
append/dismiss/state invocation one at a time. Execution details that
landed beyond the sketch: a zero-interval settle tick before every
state snapshot (`trackedNotifications` does not update synchronously
in the arrival tick), a startup seq-continuation scan so a restarted
daemon continues the store numbering, `seq` carries the D-Bus id of
the last genuinely-new arrival (dismiss/refresh writes never bump
it), and a natural close/expiry only refreshes state — it NEVER
deletes a store entry (history removal is exclusively an explicit
FIFO `dismiss`). Dismiss commands arrive over a FIFO the daemon owns;
the reader loop is hardened per [[adr0014]] (fail-fast `mkfifo`,
sleep floor, timer-bounded respawn — the fork-bomb fix from
execution, commit d069180). All store/glue logic lives in `#!/bin/sh`
scripts per [[adr0002]].

**Consumers.** `NotificationServer` and every notif-state property are
ripped out of `config/shell.qml` and `Bar.qml`; ticker, bell, and
count are driven by `tail -F` on the live-state file (path from
`QS_NOTIF_FILE`, exported by `qs-start.sh`) — the same source model
`Bar.qml` already uses for qs-stats. The four state lines arrive as
separate reads, so the bar commits seq+text together only when the
final `last` line lands and restarts its ticker ONLY on a changed
seq. Bell dismiss is a one-shot fire-and-forget `dismiss latest` FIFO
write; the resulting count change rides back through the state-file
tail, never optimistically. Every session renders identical
notifications because they read one file.

**Browser.** `config/NotifHistory.qml` instantiates the shared
[[ft008]] `Combo` (`filterMode: external`, newest-first — the clip
picker shape from [[im006]]), hosted in the MAIN instance beside
`ClipHistory`, reached over `qs-notif.sh toggle/list/dismiss` and the
[[ft003]] keybind layer (`$mod+Shift+n`; the name-workspace bind
relocates to `$mod+Shift+o`; `for_window [title="qs-notif"]` floats
it). View + dismiss only — no clipboard copy, no action-invoke
(`actionsSupported` stays false), preserving the [[adr0010]] posture.
Two shipped deltas from the ClipHistory mould: dismiss re-runs `list`
IN PLACE and the window stays open (a list may hold more entries,
unlike a single-value clipboard); and Del-dismiss is caller-side only
via `Keys.onReleased` + a release-time empty-filter snapshot, because
Combo's TextInput natively claims the Key_Delete PRESS before any
ancestor handler or Shortcut can see it — no `Common/` edits.

## data_model
Owned by [[ft010]]: persistent entry store
`${XDG_STATE_HOME:-$HOME/.local/state}/qs-notif/NNNNNN.notif`
(header `<epoch>\t<urgency>\t<app>`, folded summary line, raw body
bytes), atomic tmp+`ln` writes (collision = bounded retry, never a
lost entry), age-cap prune on write (`QS_NOTIF_MAX_AGE`, default
172800 s); live-state file `$XDG_RUNTIME_DIR/qs-notif.state`
(`count`/`critical`/`seq`/`last`; writer override `QS_NOTIF_STATE`,
consumer path `QS_NOTIF_FILE`), atomic tmp+rename; command FIFO
`$XDG_RUNTIME_DIR/qs-notif.cmd` (`QS_NOTIF_FIFO`), 0600, `dismiss
<id|latest>` lines. Everything is 0700/0600 by construction
(`umask 077`); a needed-but-unset XDG var fails loudly at exit 78,
never a guessed path. Live tracked count is daemon memory (resets on
restart); the store is history and survives.

## api_surface
`qs-notif.sh toggle | list | dismiss <id|latest>` plus the
`$mod+Shift+n` keybind — the full contract (verbs, exit codes
0/1/78, env knobs) is [[ft010]]'s api_surface. `list` reads the
store dir directly, read-only, and never needs a live daemon;
`dismiss` writes the FIFO under a hard open+write timeout (default
2 s) so a dead daemon is a bounded exit 1, not a hang. No bar
exposes any notification surface anymore.
