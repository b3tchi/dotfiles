# Implementation [[cat002]] [[product]]

## solves
[[us026|full-resolution-still-capture]]

## approach
Full-resolution stills inside the LibCamera QML module's `CameraSource`
([[ft019]]): the `simple` pipeline offers one stream, so `capture()` stops
the 1280x720 viewfinder, reconfigures the stream as StillCapture at the
largest still size strictly below the sensor mode (3840x2880 on the
s5kjn1; 1:1 output is corrupted by the software ISP, [[poc027]]), drops 4
AE settle frames, grabs one, reconfigures back to the viewfinder and saves
the upright JPEG off the GUI thread. The preview freezes on its last frame
while `capturing`. The clipboard copy is a 2048-long-side PNG encoded off
the GUI thread. No retry loops ([[adr0014]]); the hotkeyd camera layer is
untouched ([[adr0040]]).

## features
- [[ft019]] (extended: capture semantics, `capturing`, `stillSize`)
- [[ft007]] (clipboard history keeps image/png)
- [[ft011]] (camera layer, unchanged)

## data_model
No persistent state; JPEGs at the caller's path.

## api_surface
`CameraSource.capturing: bool` (read-only), `CameraSource.stillSize: size`
(read-only, 0x0 when the camera has no still larger than the viewfinder),
`capture(path)` now full-still; `captured(path, ok)` unchanged.
