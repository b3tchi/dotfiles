# Feature [[cat002]] [[product]]

## providing
Region screen capture for X11 sessions: the user selects a rectangle on the
live desktop and gets a PNG on disk plus the image itself on the clipboard
(image/png — pastes directly into an image-aware target: Claude Code CLI, a
chat box, an editor). Consumed by the i3 keybind layer on every X11 platform
that runs the shared base config: native :0, xrdp :10 (WSL and desktop),
proot/Termux:X11.

Was file-PATH-as-text (like a tmux copy) until the [[ft007]] clip-history
image feature landed; switched once pasting a real picture became the
common case this tool is used for. Pasting the path by hand still works —
the file is still on disk — it is just no longer what the clipboard itself
holds.

Compositor-free by construction — the selector never blends with the screen
behind it, so it needs no compositor and works identically with or without
picom. See [[poc008]].

SCOPE: region, window, and whole-desktop, all through ONE overlay/keymap —
originally region-only; window and desktop were added once pasting a real
picture (not a path) made single-window capture the common quick case. The
`i3-scrot` binds (`Print` whole, `$mod+Print` window, `$mod+Shift+Print`
select) are an OLDER, separate capture path in `i3/config`, deliberately
left as-is — this feature's `w`/`d` now duplicate what those already did,
by a different mechanism (i3 tree geometry + this overlay, not i3-scrot),
not a replacement for them. `ksnip` is not a capture path either —
annotation-only (`ksnip -e <file>`), a consumer of this output.

## api_surface
Keybind-driven, no programmatic callers:

    $mod+Shift+s          raise hotkeyd's "screenshot" layer + launch the
                          overlay (ON RELEASE — see below)
      drag                select a region -> capture, save, copy image, exit
      click,click         2-tap corners (touch-friendly over RDP) -> as above
      w                   the i3-focused window -> save, copy image, exit
      d                   whole desktop -> save, copy image, exit (was `w`
                          before window capture existed)
      q | Esc | right-clk cancel, capture nothing (`q` matches the
                          ModeBar "quit" hint; both exit every mode)

Output contract:

    file      ~/Pictures/screenshots/shot_<YYYYMMDD-HHMMSS>.png
    clipboard that file's own bytes, as image/png (CLIPBOARD selection)
    exit      hotkeyd returns to layer "default"; nothing left running

**No i3 mode is involved in either phase, as of [[sp024]].** The aiming
phase was an i3 `mode "screenshot" {}` block until then; it is now an
External hotkeyd layer raised by `qs-screenshot.sh`, matching the drag
phase [[sp023]] had already moved. i3 stays in `default` for the whole
gesture, so there is no mode to get stuck in and the Escape/`q` dead-overlay
bindsyms that guarded that risk are gone with the block. The selector's own
seat grab owns the keys while it lives.

The bind fires **on release**, like its `$mod+Print` / `$mod+Shift+Print`
siblings (`dotfiles-b3d4`). On press, a held chord relaunched the launcher
for as long as it was down; each launch replaced the previous SELECTOR but
not the previous LAUNCHER, which then ran its clear and wiped the layer the
newer launch had raised — the hint strip and ring flickered. A
session-scoped pid token in `qs-screenshot.sh` now settles ownership: only
the launcher still named by the token clears on exit.

KNOWN LIMITATION, accepted at [[sp024]]: with hotkeyd unreachable (panic
config linked, sway, dead daemon) the raise fails silently and NOTHING
paints — no hint strip, no ring — because no i3 mode survives to paint them
instead. The capture itself is unaffected. Pixels, never keys.

## data_model
No persistent state. Two transient artefacts:

    ~/Pictures/screenshots/shot_<ts>.png   the saved capture (permanent)
    $XDG_RUNTIME_DIR/qs-shot-src.$QS_SID   session-scoped pointer, removed on exit

`$QS_SID` is the filename-safe display id from `quickshell/qs-session.sh`
(":0" -> "_0"), so concurrent :0 and :10 sessions never share state — the
collision class in dotfiles-8xt.

## sample
Select a region and paste the picture straight into a chat box:

    $mod+Shift+s          # crosshair over the LIVE desktop, bar shows the mode
    <drag a box>          # outline in the mode colour #cb4b16
    # -> ~/Pictures/screenshots/shot_20260715-142031.png saved
    # -> that image is now on the clipboard (image/png)

    ctrl+v                # into Claude Code CLI, a chat box, an editor

    ksnip -e ~/Pictures/screenshots/shot_20260715-142031.png   # annotate the
                                                                # file directly,
                                                                # optionally

## components
- `quickshell/qs-screenshot.sh` — launcher: resolves the session, execs the
  overlay. Forces `GDK_BACKEND=x11` (WSLg leaves a `wayland-0` socket that GTK
  auto-connects to even with `WAYLAND_DISPLAY` unset).
- `quickshell/qs-region.py` — the overlay: GDK window whose X Shape BOUNDING
  region is cut to the rubber-band outline, seat grab for input, captures
  after release. Same stack and technique as `quickshell/qs-focus-border.py`.
  Its `_key` handler owns the selector keys under the grab (`w` focused
  window; `d` whole desktop; `q`/`Esc` cancel) — a shaped overlay under a
  grab is not an i3-managed window, so these are handled in-process, not by
  i3 binds. `focused_window_rect()` reads the i3 TREE (`i3-msg -t
  get_tree`) for `w`'s geometry — same source of truth
  `qs-focus-border.py`'s border overlay uses, not X11 WM hints
  (`_NET_ACTIVE_WINDOW`) — and this overlay's own POPUP window is never
  part of that tree, so no query races its own visibility.
- `hotkeyd/cmd/hotkeyd/config.go` — the `$mod+Shift+s` bind (`OnRelease`) and
  the `"screenshot": {External: true}` declaration. The i3 `mode "screenshot"`
  block this feature used to name was DELETED from `i3/config.common` by
  [[sp024]]; i3 owns no part of this gesture any more.
- `quickshell/config/Bar.qml` — renders the hint strip. It reads the name off
  hotkeyd's layer feed now (`activeMode` prefers any non-default
  `daemonLayer`), not i3's mode-change IPC — unchanged code, different source.
- `i3/picom.conf` — `focus-exclude` + `unredir-if-possible-exclude` must list
  the overlay by name for native :0 (picom matches by name; the overlay never
  takes focus by design).
- `quickshell/test-blink-measure.sh` — 60fps luma harness that proves the
  no-blink property.

PREDECESSOR: a frozen-PNG quickshell/QML overlay (`quickshell/region/`) ships
today and provides the same api_surface with a 0.35 dim, at the cost of a
67-150ms black blink per open. Replaced by [[sp012]]; see [[poc009]] for why
keeping it in QML cannot work.
