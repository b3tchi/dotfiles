# ADR [[cat002]] [[cat001]] [[product]]

## title
python is the language for proofs and first MVPs, not for components
that have proven themselves

## context
[[adr0015]] admitted Python for two distinct kinds of work under one
decision: **X-ecosystem clients** (`python-xlib`, `PyGObject` — the
bindings with working prior art in this repo) and **prototypes and
measurement code** (spikes whose product is a number or a verdict).

Bundling them has not held up. The prototype clause is uncontroversial —
compiling a Go binary to learn whether an approach is viable inverts the
cost of the question. The X-client clause turned out to grant something
broader than intended: a standing home. Anything X-shaped could stay
Python indefinitely, and did, because [[adr0015]] never said when a
component stops being an allowed Python client and starts being a
liability.

[[sp021]] then documented what that liability actually costs, for one
daemon: an interpreter dependency on every graphical platform, bind
validation deferred to runtime, and version skew across
Arch / Arch ARM / WSL. [[adr0021]] resolved it for `hotkeyd` alone,
narrowing [[adr0015]] for X-session keystroke daemons on
static-binary / no-interpreter-skew / compile-time-validation merits. It
was written as a carve-out because no general rule existed to appeal to.

That is the gap this ADR closes. The `hotkeyd` rewrite was not a special
case; it was the first instance of a pattern — Python got the component
to the point where its shape was known, and the shape then justified a
compiled implementation. Naming that as the default makes the next
rewrite a normal step rather than a fresh argument, and stops the
question being re-litigated per component ([[adr0015]]'s own option (a),
which it rejected for the same reason).

## decision
Python's role is **proofs and first MVPs**. It is the right language to
find out whether something works and what its shape is; it is not the
default home for a component that has answered those questions.

- **PoCs, spikes, measurement code** — Python, unreservedly. This clause
  of [[adr0015]] is carried forward unchanged. `docs/notes/lab/poc###`
  work has no graduation expectation at all; it is thrown away once read.
- **First MVP of a component** — Python is a legitimate starting point
  even where the eventual implementation will not be, when it gets to a
  working answer materially faster.
- **A component that has proven itself** — has stable shape, is depended
  on, and is expected to keep running — should graduate to a compiled
  implementation (Go per [[adr0003]] / [[adr0021]], Rust per [[adr0008]]
  where the binding demands it). `hotkeyd`'s Python-to-Go rewrite is the
  worked example.

Two things this does NOT mean:

- **It is not a rewrite mandate.** Shipped Python components stay until
  something else forces the question — a substantial change, a platform
  that cannot carry the interpreter, or a liability of the kind [[sp021]]
  named. `quickshell/qs-region.py` and `quickshell/qs-focus-border.py`
  are load-bearing Python today and are not scheduled for anything by
  this ADR.
- **It is not "Python is banned once shipped".** Where a binding exists
  in Python and has no working equivalent here — GTK shaped windows via
  `PyGObject` is the standing example — staying Python is the correct
  answer, and the reason gets stated at the component rather than assumed
  from [[adr0015]]'s old blanket permission.

The test is *"has this component proven its shape, and would a compiled
implementation remove a named liability?"* Both yes → graduate. Either no
→ stay, and say which.

## consequences
[[adr0015]] is superseded: its prototype clause survives here, its
X-ecosystem-client clause is replaced by the graduation rule above.
[[adr0021]] stands unchanged and stops being an unexplained carve-out —
it becomes the first application of this rule, and future daemons cite
this ADR for the general case plus [[adr0021]] for the keystroke-daemon
specifics.

One dangling statement to read correctly rather than trip over:
[[adr0021]] says "It does not flip [[adr0015]]'s status: [[adr0015]]
remains Accepted." That was true when written and is scoped to what
[[adr0021]] itself did — narrow `hotkeyd` out without disturbing the
general permission. THIS ADR is what flips it. [[adr0021]] is not edited,
because ADRs are not rewritten to match later decisions; the supersession
chain on [[adr0015]] is the authoritative signal, and a reader arriving
via [[adr0021]] follows it there.

Archived specs ([[sp022]] among them) reason about an "[[adr0015]]
family". Those are historical records of decisions made under the old
rule and stay as written.

The cost is that "first MVP" is a judgement call, and a component can sit
in Python past the point where it has clearly proven itself. That is
accepted deliberately: the alternative is a hard rule (line counts,
consumer counts) that would force rewrites of code nobody is struggling
with. The graduation question belongs at a retro, where the liability is
concrete and the shape is known — which is where the `hotkeyd` one was
actually asked.

A second-order effect worth stating: a Python first MVP is now explicitly
allowed to be thrown away rather than extended. Knowing at the outset
that a component may be rewritten changes what is worth building into the
Python version — the answer is usually "less".
