# Feature [[cat001]] [[cat002]] [[product]]

## providing
A localhost Go daemon (`preview-d`) plus its mandatory nushell wrapper
that renders any file on demand and drives a live native window which
follows the editor cursor. Two route modes compose: a stateless
`/file/<path>` that renders one file as-is (renderer chosen by the path's
type) and a stateful `/preview<N>` live window that hot-swaps which file
it shows as the cursor moves. Bidirectional — the editor pushes the
cursor's file in, and selecting a node in the akm embed pushes a path back
out to open in nvim. Renders code, markdown, images, video, svg and STL,
and embeds [[ft004]] (akm graph) as a cross-origin iframe and [[ft002]]
(d2 diagrams) as relayed SVG bytes. Consumed by nvim and nnn.

The display half is a Qt Quick client ([[adr0018]]): one long-lived `qml6`
process per slot, native delegates for `image | svg | md | code | video |
none` and a lazily-instantiated `WebEngineView` for `html | akm | stl`.
The wry/WebKitGTK host (`preview-wv`), its `shell.html`/`app.js` and the
shell-side `postMessage` reverse channel are gone; [[adr0007]]'s
server-side `POST /open` is the surviving reverse path. The [[adr0006]]
frame-header-stripping proxy is no longer on the `.d2` path — the native
svg tier fetches bytes instead of framing a page — though `/d2embed/`
remains for browser use.

## api_surface
HTTP on `localhost:$PREVIEW_PORT` (default 4200):

- `GET /file/<path>` — render one file as-is; renderer selected by the
  path's extension/type: code (syntax HTML), markdown (HTML), image
  (thumbnail, full-res on `?full`), video (poster frame, `<video>` on
  `?live`), STL (orbit viewer, raw bytes on `?full`). An akm-zettel path
  resolves to a cross-origin `<iframe>` of [[ft004]]; a `.d2` path
  resolves to a `<iframe>` of the same-origin `/d2embed/` proxy of
  [[ft002]] ([[adr0006]]). Embedded backends are lazy-spawned if not
  already listening. A `?slot=N` on the request is threaded onto the akm
  iframe src so a selection there routes back to slot `N`'s nvim
  ([[sp009]]).
- `GET /d2embed/<path>` — same-origin reverse-proxy of the [[ft002]]
  d2 page for `<path>`, with frame-blocking headers stripped ([[adr0006]]);
  path-jailed like `/file/<path>`.
- `GET /file/<path>?native` — the native-tier payload for the Qt Quick
  client ([[adr0018]]), by classified type: `md` → raw bytes as
  `text/plain` (capped, literal `[preview truncated]` marker); `code` →
  a chroma fragment with **inline** styles and no `<html>` wrapper,
  suitable for Qt rich text; `html` → raw file bytes; `.d2` → the SVG
  bytes relayed from [[ft002]]'s `GET /api/svg` (404 passes through as
  404; relay failure is a 502 with a plain-text cause, deliberately not
  the 200-page idiom, which existed for iframe display). Types with no
  native payload (`image`, `video`, `stl`, `akm`) ignore the parameter and
  serve their existing response — behaviour without `?native` is
  unchanged everywhere.
- `GET /preview<N>` — live window `N`. Non-websocket requests return JSON
  `{slot, path, type}`; the served HTML shell is gone with the wry host.
  The same `/preview<N>` path upgrades to a websocket for the per-window
  redraw push, whose frames are now `{path, type}` — `type` drawn from the
  closed nine-value vocabulary `image | svg | md | code | video | html |
  akm | stl | none`, classified server-side by `classifyPath` so tier
  selection stays where its tests live. Multiple `N` = multiple concurrent
  windows, each an isolated slot (path + client set).
- `POST /preview<N>` body `{path}` — set window `N`'s current path (the
  editor cursor signal). An absolute path under the root is canonicalized
  to root-relative at ingestion; an absolute path outside the root is a
  `400` (never broadcast as a guaranteed 404). Broadcast is conditional
  ([[sp011]]): an akm-zettel path is first forwarded server-to-server as
  `POST /api/highlight {path, slot}` to [[ft004]] (scoped-timeout client,
  the [[adr0007]] pattern); on an akm→akm transition with a successful
  forward the window is NOT redrawn — the running [[ft004]] embed
  highlights in place instead of reloading. Every other transition (and
  any forward failure — degrade to reload, never a dead preview)
  broadcasts the redraw as before.
- `POST /open` body `{path, slot?}` — open the path in the running editor
  via `nvim --server <addr> --remote` (the reverse channel); path-jailed +
  arg-vector exec. With `slot`, routes to that slot's registered parent
  nvim ([[sp009]]); without `slot`, uses the process-global `$NVIM`
  (back-compat). `424` when the target addr is unbound / `$NVIM` unset.
- `POST /register` body `{nvim, slot?}` — bind an nvim's `v:servername` to
  a window slot; omitting `slot` allocates a free one and returns
  `{slot: N}` (concurrent registers get distinct slots). This is how each
  nvim claims its own preview window + reverse-open target ([[sp009]] /
  [[adr0007]]).
- `GET /status`, `POST /stop` — health snapshot / graceful stop
  (ft002/ft004 parity).

Mandatory nushell wrapper ([[adr0003]]) at
[nushell/actions/preview](../../nushell/actions/preview), the user-facing
API: `preview start | stop | status | register [--slot N] | open <path> | send <path> [--window N] | window [N] [--close]`.
No consumer invokes the binary directly. `window [N]` ([[sp013]]) spawns
the slot's window as `qml6 preview/qml/PreviewView.qml -- <N> <port>` —
idempotent (per-window pidfile; validity is an **exact-argument** check on
`/proc/<pid>/cmdline`, requiring an element ending `PreviewView.qml` AND an
element exactly `<N>`, so slot 1's pidfile can no longer validate against
slot 2's live window; stale or recycled pid → cleaned and respawned, never
signaled). `--close` keys on `kill -0` liveness, never on exit code —
`qml6` exits 143 on SIGTERM universally, which is the runtime's behaviour
and not a fault. `stop` closes all windows before the daemon. Spawn sets
`QT_FORCE_STDERR_LOGGING=1` (without it the client's stderr, including its
bad-args usage line, is swallowed entirely) plus the [[adr0019]] /
[[adr0020]] environment. Window resolution and docking are pid-based
(`xdotool search --pid` → `[id=…]` under i3, `[pid=…]` under sway), and
`show` **re-docks a live window** on every call rather than only on first
open; docking itself is X11-gated ([[adr0018]], [[us021]]). `PreviewStart` (nvim) calls `register` with `v:servername` to
claim a slot, then spawns that slot's window and `send` targets it
([[sp009]] / [[sp013]]).

## data_model
Ephemeral, no persistence. In-memory session map: window slot `N` →
`{ current path, set of websocket clients, parent nvim address }`, swapped
atomically under a mutex (the [[ft004]] hub pattern). Slots are allocated
on `/register` (lowest free N, mutex-guarded so concurrent registers stay
distinct); the parent nvim address drives per-slot reverse-open ([[sp009]]). Video poster frames are cached
per-path under a mutex (ffmpeg-extracted, first-frame); the cache is
currently unbounded — eviction is deferred (bd `dotfiles-e6o`). Embedded
peer daemons are lazy-spawned once under a double-checked lock and
health-polled with a timeout. Config via env `$PREVIEW_PORT` (default
4200). Window-client lifecycle state is wrapper-owned:
`~/.cache/preview/wv-<N>.pid` + `wv-<N>.log` per window ([[sp013]]).

Client-side memory is bounded for the window's whole life, which the
long-lived design makes a contract rather than an implementation detail:
the web tier plateaus at ~574 MB via [[adr0020]]'s V8 ceiling, and the
native svg tier holds ~85 MB indefinitely. The latter needed a fix — the
viewBox probe races the `Image`'s own fetch, and losing that race left
`sourceSize` at 0, decoding the document's declared size (a 728×7561
diagram = one retained 22 MB ARGB raster per superseded decode). The stage
now holds its `Image` sourceless until the natural size has settled and
the fit has run. A seven-tier sweep ends inside ~745 MB, flat. All viewer libs (three.js / `<model-viewer>`, syntax assets) are
compiled into the binary via `go:embed` — offline, no CDN, no
target-side build ([[ft004]] precedent).

## sample
```nu
preview start                       # spawn daemon (daemon only — no window)
preview window 1                    # open native webview window 1 (preview-wv, idempotent)
preview send ~/notes/us006.md       # push a file to window 1 -> it redraws
preview open ~/notes/us006.md       # (reverse) open that path back in nvim
preview window 1 --close            # close window 1; `preview stop` closes all + daemon
```

nvim side (`CursorHold` autocmd calls the wrapper):

```lua
vim.api.nvim_create_autocmd("CursorHold", {
  callback = function() vim.system({ "preview", "send", vim.fn.expand("%:p") }) end,
})
```

## components
- [preview/](../../preview) — Go daemon (`preview-d`): routes, renderers, session hub
- [nushell/actions/preview](../../nushell/actions/preview) — wrapper (start/stop/status/open/send)
- [nvim/plugins/preview.lua](../../nvim/plugins/preview.lua) — nvim cursor-signal + reverse-open integration
- [preview/qml/PreviewView.qml](../../preview/qml/PreviewView.qml) — the
  client ([[adr0018]]): one `ApplicationWindow` titled `preview <N>`,
  a `QtWebSockets` client on `ws://127.0.0.1:<port>/preview<N>`, and a
  `Loader` hot-swapped per `{path, type}` frame. Native delegates for
  image / svg / md / code / video / none; pan-zoom, `sourceSize` clamp
  and the poll-and-cache-bust live reload follow the `d2-view/BoardView`
  precedent. Its svg poll is **asynchronous** with a last-wins guard: a
  synchronous XHR blocked the GUI thread for seconds, and a WM that
  implements `_NET_WM_PING` answers an unanswered ping by closing the
  window — which Qt exits cleanly, so the failure looked like a normal
  close rather than a hang.
- [preview/qml/WebTier.qml](../../preview/qml/WebTier.qml) — the reserved
  web tier: the repo's only `import QtWebEngine`, so engine libraries load
  at first `html|akm|stl` frame and never before ([[poc018]]). Recovers a
  terminated renderer once, then shows fallback text rather than dying.
- Retired: `preview-webview/` (the Rust wry/tao host from [[sp013]], via
  [[poc007]]) and `preview/static/{shell.html,app.js}`. `stl-viewer.js`
  and the `/static/` route survive — the web tier still serves the orbit
  viewer through them. [[adr0008]]'s Rust exception is untouched as
  policy; it simply has no live instance here now. This also closes bd
  `dotfiles-qdl` (the forced-`GDK_BACKEND=x11` window blocked by the WSL
  sway profile's `xwayland disable`): the client opens natively under
  sway via `xdg_shell`, no forced X11.
