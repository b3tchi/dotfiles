# ADR [[cat001]] [[product]]

## title
census reads supported surface only

## title
The agent census reads only the supported claude CLI surface

## context
Two sources describe claude agents on disk:

- `claude agents --all --json` — the documented command.
- `~/.claude-*/jobs/<id>/state.json` and `~/.claude-*/sessions/<pid>.json` —
  internal files carrying richer fields: `originCwd`, `worktreePath`,
  `interactiveLineage`, `children`, `detail`, `needs`, and crucially
  `updatedAt`.

The internal files were surveyed while writing [[sp026]] and rejected: the
format is undocumented, and the sessions registry was 23 of 26 stale dead pids
at the time of survey. The command's reported `cwd` already carries
origin-not-worktree semantics, which was the one thing the files were wanted
for — a job running in `.claude/worktrees/<branch>` reports the repo root.

## decision
[[ft012]] reads `claude agents --all --json` and nothing else from the claude
installation. `tmux`, `ps` and the [[ft001]] registry are read directly; the
internal `jobs/` and `sessions/` trees are not.

## consequences
The census cannot distinguish a real `busy` from a stale one. `updatedAt` —
the field that would settle it — lives only in `sessions/<pid>.json`. An
abandoned session was observed sitting at `busy` for six hours with zero CPU
and was counted as working. That is a known, accepted inaccuracy, tracked as
bd `dotfiles-ubc4.9`, not an oversight.

Two alternatives were weighed and rejected for now:

- Reading `updatedAt` from the sessions registry — accurate, but reverses this
  decision, which is why it needs a superseding ADR rather than a quiet patch.
- Inferring activity from a CPU delta across two `ps` samples — stays on
  supported surfaces but requires a delay between samples, which is fatal for
  a ~600 ms command a status bar may poll.

The upside is that the census keeps working across claude upgrades that
reshape internal state files, and its failure modes are the command's failure
modes rather than a private format's.

If the stale-`busy` inaccuracy starts mattering to a real consumer, supersede
this ADR rather than editing it.
