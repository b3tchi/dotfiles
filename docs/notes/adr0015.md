# ADR [[cat001]] [[product]]

## title
Python is an allowed language for X-ecosystem clients and prototypes

## context
[[adr0001]] makes nushell the default for scripts and data manipulation,
[[adr0002]] pins the five conditions under which bash wins, [[adr0003]]
authorises a compiled Go helper when a process is a long-running daemon
*and* proxies streams or has a hot latency path *and* has no nushell
structural fit, and [[adr0008]] allows Rust in place of Go when the
capability exists only as a Rust binding. Together they cover shell-shaped
work, boot-chain work, and network daemons.

Two kinds of work fall through every one of those tests:

- **X-ecosystem clients.** Selecting XI2 raw events, calling `XGrabKey`,
  owning a selection, or shaping a GTK window are library calls, not
  structured pipelines — nushell has no binding and no event loop, and
  bash meets none of the five [[adr0002]] conditions. They are also not
  what [[adr0003]] describes: no listener, no stream proxying, and a hot
  path measured in one keystroke per human action rather than per frame or
  per request. Go and Rust both have X bindings (`xgb`, `x11rb`), so this
  is not a Rust-only-binding case under [[adr0008]] either; the pull
  toward Python is that `python-xlib` and `PyGObject` are the bindings
  with working prior art *in this repo*.
- **Prototypes and measurement code.** Spikes whose product is a number or
  a yes/no verdict, thrown away once read — compiling a Go binary to learn
  whether an approach is viable inverts the cost of the question.

The repo has been resolving both cases as Python for a while with no
decision recorded: [quickshell/qs-keymon.py](../../quickshell/qs-keymon.py)
(XI2 raw key listener), [quickshell/qs-region.py](../../quickshell/qs-region.py)
(GTK shaped-window region selector),
[quickshell/qs-focus-border.py](../../quickshell/qs-focus-border.py),
[i3/test-events.py](../../i3/test-events.py), and the pytest suites beside
them. The immediate forcing case is [[ft011]] (`global-hotkey-layer`,
[[sp020]]): a per-bind `XGrabKey` daemon, which is exactly an X client with
an event loop and no nushell fit.

Options surveyed: (a) leave the gap open and argue per daemon — what has
happened so far, and it re-litigates every time; (b) read [[adr0003]]
broadly so any daemon must be Go — costs the python-xlib prior art and
makes throwaway spikes expensive; (c) name Python as an allowed language
under stated conditions.

## decision
**Python is allowed — never the default — when at least one holds:**

1. **The capability is an X11/GTK-ecosystem binding with working prior art
   here**: `python-xlib` (XI2, `XGrabKey`, selections, shaped windows),
   `PyGObject`/GTK. The binding, not taste, is the justification, mirroring
   how [[adr0008]] admits Rust for wry.
2. **The code is a prototype, spike, or measurement harness** whose output
   is a verdict or a number, and which is discarded or rewritten before it
   ships. Throwaway status must be stated in the file's header comment.

**Python is NOT allowed for:** workflow tooling and structured-data work
([[adr0001]] keeps nushell), the boot chain ([[adr0002]] keeps bash), or a
daemon that satisfies all three [[adr0003]] conditions — a listener with
stream proxying or a per-request hot path is still Go, and this ADR does
not widen [[adr0003]] or authorise rewriting any existing nushell script.

**No nushell wrapper mandate.** [[adr0003]] requires compiled engines to
sit behind a `nushell/actions/` wrapper because a binary is unreadable and
unrunnable at the call site. A Python entry point is neither, so the
front-end convention is the one the X-session daemons already use: a thin
shell launcher beside the daemon (`qs-bar.sh`, `qs-notif.sh` shape) owning
start / stop / status / restart. Adding a nushell hop in front of a
keystroke daemon would add startup cost on the very path this ADR exists
to keep short.

**Dependency and runtime rules.** Interpreter dependencies are declared in
the owning app's `dot.yaml` as distro packages (`python-xlib`,
`python-gobject`) — no virtualenv, no `pip install` at runtime, since these
processes start from the X session before any activation step could run.
Reader loops obey [[adr0014]] (fail fast, sleep floor, timer-bounded
respawn) exactly as the shell readers do.

## consequences
**Positive.** The X-client work the repo already does becomes sanctioned
rather than tolerated, with a test to apply instead of a precedent to cite.
Spikes stay cheap, which keeps the [[adr0003]]-style "measure first"
discipline affordable. `python-xlib` is already an installed dependency of
the quickshell layer, so [[ft011]] adds no new runtime.

**Negative, and load-bearing.** A third sanctioned language means three
idiom sets to maintain and review, and the boundary between "prototype"
and "shipped" is a judgement call that will be abused at least once — a
spike that quietly becomes load-bearing is the predictable failure, which
is why condition 2 demands the throwaway label in the file itself.
Interpreter startup (~30-60 ms) rules Python out for anything invoked per
keystroke or per frame *as a fresh process*; only long-lived daemons and
one-shot tools qualify. The GIL is irrelevant at human input rates but
becomes a real ceiling if any Python daemon later grows a concurrent hot
path — at which point [[adr0003]] applies and the daemon should be ported,
not patched. Python's own dependency surface (system packages, version
skew across Arch / Arch ARM / Termux / WSL) now matters on every platform
that runs a graphical session.

## superseded_by
[[adr0024|python-is-for-proofs-and-first-mvps]] — the prototype clause is
carried forward unchanged; the X-ecosystem-client clause is replaced. This
ADR granted Python a STANDING home for anything X-shaped and never said
when a component stops being an allowed Python client and starts being a
liability, so nothing ever graduated on its own. [[adr0021]] had to carve
`hotkeyd` out by hand for exactly that reason. adr0024 makes graduation the
default and turns that carve-out into the first instance of a rule.

Shipped Python is NOT invalidated by this supersession — see adr0024's
decision section: no rewrite mandate, and a Python-only binding (PyGObject
shaped windows) remains a correct answer with the reason stated locally.
