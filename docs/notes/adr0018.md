# ADR [[cat001]] [[cat002]] [[product]]

## title
The preview client renders natively; a web engine is a reserved tier

## context
[[ft005]]'s display half was a wry/WebKitGTK host (`preview-wv`, admitted
under [[adr0008]] as a Rust-only binding). It could not survive an i3
reparent, and it carried a browser engine for every file type including
plain images and markdown.

Three PoCs measured the alternative before this spec ran: [[poc016]] (a Qt
Quick window survives the six-stage i3 reparent sequence), [[poc017]] (a
`WebEngineView` survives the same), and [[poc018]] (a `QtWebEngine` import
placed inside a lazily-instantiated component loads its libraries only at
`Loader` instantiation, while a top-level import costs ~22 MiB with no view
in existence).

## decision
The preview window is a single long-lived Qt Quick process
(`preview/qml/PreviewView.qml`, run by `qml6`) that hot-swaps a `Loader`
delegate on every `{path, type}` frame. Render tiers split by classified
type:

- **Native tiers** — `image`, `svg`, `md`, `code`, `video`, `none` — render
  with Qt Quick primitives only. No web engine is involved.
- **Reserved web tier** — `html`, `akm`, `stl` — render in a
  `WebEngineView` whose `import QtWebEngine` lives **only** inside
  `preview/qml/WebTier.qml`, so the engine's libraries load at first
  web-tier frame and never before.

The hard requirement is identity: **one process, one X11 window id, no
engine reload across type swaps.** A fix that buys any other property by
recreating the window, the view, or the engine is not acceptable.

Type classification stays server-side in `preview-d` (`classifyPath`), and
the client switches on a closed nine-value vocabulary
(`image | svg | md | code | video | html | akm | stl | none`).

## consequences
Cost follows use: a session that never opens an `html`/`akm`/`stl` file
never pays for the engine. Measured — baseline ~55 MB / 1 pid, and ~277 MB
/ 5 pids only after the first web-tier frame.

Window docking is scoped to X11. Placement resolves the window by pid
(`xdotool search --pid` under i3, native `[pid=…]` under sway), and both
docking entry points gate on `xdotool getactivewindow`, so under Wayland
the window spawns, renders, and follows the editor across workspaces, but
dock-beside-frame does not run (bd `dotfiles-8ryw`; follow-up [[us021]]).
This mirrors the X11-per-display scope the wry host had.

The `preview-wv` crate, `shell.html`, `app.js`, and the shell-side
`postMessage` reverse channel are deleted. [[adr0007]]'s server-side
`POST /open` channel is the surviving reverse path, exactly as that ADR
anticipated.

[[adr0008]] is **not** superseded — its rule (Rust when the binding exists
only in Rust) still stands. Only its motivating example no longer has a
live instance in this repo.

The engine's runtime needs two further policies that this tier made
necessary: [[adr0019]] (GL on xorgxrdp) and [[adr0020]] (V8 heap ceiling).
