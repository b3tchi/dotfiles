# ADR [[cat001]] [[product]]

## title
Go for agent-monitor, an interactive terminal UI

## context
[[sp030]] proposes [[ft016|agent-monitor-tui]]: a single interactive terminal
view over every agent this machine runs, joining a roster pane and a
message-log pane refreshed on two different clocks. [[ft016]]'s
`## api_surface` already commits to a single Go binary linked to
`~/.local/bin/agent-monitor` with no `nushell/actions/` wrapper, and its
`## data_model` commits to two concurrent sampling loops inside one process
(a slow roster tick against `agent-census --json --detail`, a fast message
tick against `pi-worker messages --json`, each rendering from its last good
sample per [[adr0014]]'s guards). Neither commitment has a citable ADR yet;
this is that ADR.

[[adr0003]] is the repo's standing rule for when a compiled Go helper is
required over nushell, but its gate is a strict three-condition AND:
long-running daemon, "Websocket/stream proxying or hot-path latency", and no
nushell structural fit. `agent-monitor` holds no listener and proxies no
stream — it is a foreground TUI a human quits with `q`, not a daemon anyone
starts and leaves running — so it satisfies condition 3 alone (its work,
raw-mode rendering with two live samplers, cannot be modelled as a pipeline
that completes and exits) and fails condition 1 and 2 outright. Reading
condition 3 loosely enough to wave a TUI through on its own would make the
gate uncitable the next time a proposal needs to pass it honestly.
[[adr0021]] already ruled on exactly this temptation for `hotkeyd` and
refused to borrow the clause; [[adr0008]] set the same precedent shape for
Rust. Both admit a language for a *specific, stated* reason beside
[[adr0003]] rather than stretching its test.

What `agent-monitor` actually needs, and what [[adr0001]]'s nushell default
cannot express: raw-mode terminal input (disabling line buffering and local
echo to read single keystrokes for `tab` / `/` / `jk`), an alternate screen
buffer (so the full-screen view does not scroll the caller's terminal
history), `SIGWINCH` resize handling (recomputing pane layout as the
terminal resizes), and two independently-clocked concurrent samplers running
inside the same process without blocking each other or the input-read loop.
Nushell's process model is blocking pipeline evaluation with no
goroutine-equivalent concurrency primitive and no raw-terminal-mode API —
structurally the same gap [[adr0002]] and [[adr0003]] already found for
long-running servers, here hit by an interactive renderer instead of a
daemon.

Options surveyed: (a) leave the roster and message views as separate
one-shot nu/CLI invocations (`agent-census --json`, `pi-worker messages
--json`) with no live TUI — abandons the joined, live-refreshing view
[[sp030]] and [[ft016]] specify, and re-litigating that scope is out of
place in an ADR; (b) stretch [[adr0003]] condition 2 or 3 to cover an
interactive renderer with concurrent samplers — rejected for the same reason
[[adr0021]] rejected it: it would make the gate meaningless for the next
daemon proposal that needs to cite it honestly; (c) a new ADR, shaped like
[[adr0021]] and [[adr0008]], that admits Go for this TUI on its own stated
merits and resolves the wrapper-mandate question explicitly.

## decision
**Go is authorised for `agent-monitor`, [[ft016]]'s interactive terminal UI,
standing on its own merits — not on [[adr0003]]'s three-condition gate.**
This ADR does not invoke that gate and states why: `agent-monitor` holds no
listener and proxies no stream; it satisfies condition 3 alone (no nushell
structural fit), and condition 1 (long-running daemon) does not hold — it is
a foreground process a human starts and quits, not something left running
unattended. Borrowing the clause anyway would make it unciteable the next
time a genuine daemon proposal needs to pass it honestly. The merits that DO
carry this decision:

- **Raw-mode input and an alternate screen buffer** — putting the terminal
  into raw mode (per-keystroke reads for `tab` / `/` / `jk`/ `q` / `r`) and
  swapping to the alternate screen for a full-screen view are terminal
  operations nushell's pipeline model has no primitive for; Go's stdlib
  (`golang.org/x/term`-style raw mode via syscalls, or manual `ioctl`/termios
  handling) reaches them directly.
- **Resize handling** — `SIGWINCH` must recompute the roster/message pane
  split live; this is signal handling around a running event loop, not a
  pipeline stage.
- **Concurrent samplers** — the roster probe (slow tick, ~600 ms dominated by
  one `claude` call per account, refreshed on its own clock or on `r`) and
  the message probe (fast tick, local file reads) run concurrently with the
  input-read loop inside one process. Goroutines map directly to this; a
  nushell script would need to fork and coordinate three separate processes
  to get the same shape, at which point it is not "a script" in any sense
  [[adr0001]] or [[adr0002]] contemplates.

[[adr0001]]'s default is not overridden here — it is simply silent on
interactive raw-mode renderers, the same category of gap [[adr0003]] already
found for long-running servers. This ADR fills the adjacent gap for
interactive terminal UIs, the way [[adr0003]] filled it for daemons.

**Wrapper carve-out — stated, not implied.** [[adr0003]] mandates a
`nushell/actions/` front-end for every compiled helper it authorises,
because "the binary is an engine, not an interface." That reasoning does not
apply here: `agent-monitor` **is** the interface — a human runs it directly
and interacts with it via raw keystrokes for the whole session. A nushell
wrapper in front of it would forward argv, add a shell start-up, and buy
nothing, the same shape of refusal [[adr0021]] recorded for `hotkeyd`.
**`agent-monitor` is therefore carved out of** the [[adr0003]]
**`nushell/actions/` wrapper mandate**; the binary links straight to
`~/.local/bin/agent-monitor`, per [[ft016]]'s `## api_surface`. This
carve-out covers `agent-monitor` (and, by the same reasoning, any future
compiled helper whose entire job is to *be* the interactive interface); it
does not touch [[adr0003]]'s wrapper mandate for any engine-shaped compiled
helper.

**Scope — this authorises one binary, nothing wider.** This decision covers
`agent-monitor` only. It grants no licence to rewrite any existing nushell
script or `nushell/actions/` entry in Go — [[adr0001]] stays exactly as
written for everything else in the repo, including `agent-census` and
`pi-worker`, both of which `agent-monitor` only calls as external CLIs
([[ft016]]'s `## components`) and neither of which this ADR touches.

**Boundary conditions, stated rather than left implicit.** A future proposal
for a *non-interactive* Go helper (no raw mode, no alternate screen, no
human at the keyboard for its duration) gets no benefit from this ADR — it
must still fail or pass [[adr0003]]'s three-condition gate on its own terms.
Symmetrically, if `agent-monitor` ever grows a network listener (for
example, a remote-attach mode), that listener falls under [[adr0003]] again,
not this ADR — this decision is scoped to the interactive-TUI merits above,
not to the binary's name.

## consequences
**Positive.** `agent-monitor` gets direct terminal control (raw mode,
alternate screen, `SIGWINCH`) that nushell cannot provide, and its two
sampling clocks run as goroutines inside one process instead of coordinated
external scripts. The interactive-TUI gap next to [[adr0003]]'s daemon gap
is now named and citable, so the next interactive-renderer proposal has
somewhere honest to point instead of stretching [[adr0003]] condition 3 or
inventing a fourth condition on the spot. The wrapper question is resolved
explicitly here rather than left for a future reviewer to infer from
[[adr0021]]'s hotkeyd precedent by analogy.

**Negative, and load-bearing.** A Go toolchain becomes a build-time
dependency for `agent-monitor`'s rotz recipe, same as every other
[[adr0003]]-lineage binary (needs the `command -v go` guard). The repo now
carries a second, ADR0003-adjacent citable reason for a compiled Go helper
outside daemons; a future contributor auditing "why is this Go" has one more
place to check ([[adr0003]] for daemons, this ADR for interactive TUIs,
[[adr0021]] for hotkeyd's per-binary carve-out, [[adr0008]] for Rust-only
bindings) rather than one uniform rule — accepted deliberately, the same
bookkeeping cost [[adr0021]] accepted for its own carve-out. `agent-monitor`
is invoked directly with no nushell front-end, so it has no unified
`nushell/actions/` audit surface the way other authorised compiled helpers
do; that is the explicit trade this ADR makes, not an oversight.
