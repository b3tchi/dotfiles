# ADR [[cat001]] [[product]]

## title
A delegated stage's completion is read from a typed field, never from its prose

## context
When an agent finishes a delegated stage, something has to decide whether the
stage actually passed. Two sources are available and only one is trustworthy:

- the **typed result envelope** the agent writes through a tool call, with a
  `status` and a `validation` verdict in named fields;
- the agent's **own prose** — its summary, its final message, the text in its
  pane.

Prose is the one thing a language model can always produce. An agent that has
not run its validation can still write "SRE PASS — all eight categories
reviewed", and it will look exactly like an agent that did. Nothing about the
text distinguishes them.

The cost of getting this wrong is asymmetric and irreversible. A false
completion closes the worker's window, deletes its worktree, and tells the
pipeline to move on — the three things that destroy the evidence needed to
notice the mistake.

This was tested rather than assumed. A mutation that made the verdict check
fall back to reading the summary when the typed field was empty survived the
entire suite, because a separate envelope-level rule happened to reject that
same input first. Two layers coincidentally covering one hole is not the hole
being closed.

## decision
A stage may report `complete` only when its typed `validation` field carries the
verdict its own discipline produces. `spec-refinement` must carry `SRE PASS`;
every other stage must carry a non-empty verdict. The check reads that field and
nothing else — never the summary, never the transcript, never the pane.

Completion is likewise never inferred from an idle prompt, an exited process, or
a pane that has stopped changing. An agent that settles without calling the
typed result tool is recorded as `protocol_error`, not as success: the ABSENCE
of a result is itself a reportable outcome.

A worker with no recorded identity cannot say which stage it is, so its
completion is refused outright rather than passing ungated.

## consequences
An agent that does its work correctly but forgets the tool call is marked as a
protocol error and has to be resumed. That is the intended trade: a
false negative costs one resume, a false positive costs the work.

Every stage that wants a gate must define what its verdict looks like. Adding a
stage without one gets the default — non-empty — which is weak but honest; the
stage's own reviewers can tighten it when they know what evidence that stage
produces.

The gate lives inside the write path (`bus-result`), not at the callers, so a
new caller cannot bypass it by taking a different route. This costs a little
flexibility: a caller that legitimately wants to record an ungated result has
nowhere to do it, which is deliberate.

Tests for a rule like this must assert against the gate DIRECTLY. Asserting
through a higher layer lets an unrelated rule mask the gate's absence, which is
precisely what happened here and was only caught by mutating the code and
watching the suite stay green.
