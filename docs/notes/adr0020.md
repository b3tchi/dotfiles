# ADR [[cat002]] [[product]]

## title
The preview web tier runs under a fixed V8 old-space ceiling

## context
[[adr0018]]'s window is long-lived by design, so per-navigation memory
behaviour matters in a way it never did for a short-lived host.

Re-navigating the same akm URL grew the renderer ~32-39 MB per visit with
no delta decay, which read as an unbounded leak in two separate
measurements. It is not. Attribution put 100% of the growth in the single
renderer child (the `qml6` browser process stayed flat), `smaps` put every
growing byte in V8's pools, and continuing the loop past the point both
earlier runs stopped showed a **plateau at ~1333 MB** with negative deltas
as major GC reclaimed. V8 derives its old-space limit from host RAM, so on
a 24 GB machine the natural ceiling is far above anything a preview window
should hold.

## decision
The wrapper composes `--js-flags=--max-old-space-size=256` into
`QTWEBENGINE_CHROMIUM_FLAGS` on **every** display — the limit is
RAM-derived, not display-derived, so it is not conditioned on xorgxrdp the
way [[adr0019]]'s GL flags are.

The value must be one whitespace-free token: QtWebEngine splits that
environment variable without quote handling, so a space silently truncates
the flag and V8 receives only its first component.

## consequences
The plateau moves from ~1333 MB to ~574 MB, reached by about the seventh
web navigation and flat thereafter (verified to 160 navigations). Combined
with the native-tier fix this spec also shipped, a seven-tier sweep ends
around 745 MB instead of climbing.

The ceiling is a real trade, honestly narrow: content whose **live** JS
heap sits between 256 MB and the old ~1.33 GB natural limit used to render
and now exhausts the heap. No akm content approaches this — a
1301-node/16104-link graph renders flat at 676 MB — so the exposure is the
`html` tier, i.e. arbitrary local HTML. A caller-set
`QTWEBENGINE_CHROMIUM_FLAGS` is the documented escape hatch.

The ceiling bounds V8's old space only. It does **not** bound
ArrayBuffer/TypedArray backing stores — a probe allocated ~1 GB of
`Float64Array` with zero terminations.

Crash **recovery** at the ceiling is not yet complete: a page that loads,
stays healthy past the reload-budget probation, then exhausts the heap can
still loop (bd `dotfiles-f532`, P1, with a measured repro). Fast heap
exhaustion is bounded to two terminations followed by the crash text.
