# Spec [[cat002]] [[cat001]] [[board]]

## solves
[[us019|programmable-global-keybinds]]

## problem
[[ft011]]'s api_surface (frozen per [[im010]]) has no way for a
non-keybind external process to set layer state. `quickshell/qs-region.py`
enters `screenshot-drag` on a mouse-press, not a chord, so today it has to
go through `i3-msg mode screenshot-drag` and a real i3 `mode "screenshot-drag"
{}` block just to get the signal to `quickshell/qs-focus-border.py`
(`i3/config.common:170-176`). That block and its Escape/q bindsym pair are
exactly the scattered i3-owned surface [[ft011]] exists to eliminate
("the single source of truth for global binds instead of the bindsym /
bindcode tables scattered across i3 entry points and modes") — it just
survived the [[sp021]] Go cutover because it was never keybind-driven in
the first place.

Delta, scoped narrow: [[im010]]'s compiled bind table gains a new
declaration kind — an EXTERNAL-TRIGGER layer, declared in source
(`config.go`) exactly like a normal layer, but with no chord entry.
A new CLI/socket verb, `hotkeyd set-layer <name> --display :N`, accepts
writes ONLY for layers declared this way — every other layer stays
chord-only. `qs-region.py` calls this instead of `i3-msg mode
screenshot-drag`; `qs-focus-border.py` subscribes to hotkeyd's existing
state socket instead of i3's mode-change IPC event. The real i3
`mode "screenshot-drag" {}` block (and its now-redundant Escape/q
dead-overlay bindsyms) retires from `i3/config.common`.

Explicitly NOT in scope: a generic "any process can set any layer"
write API. [[adr0012]] frames hotkeyd's state channel on a
singleton-daemon / read-only-consumers model; this stays true for every
existing layer. The new verb only ever accepts a name pre-declared
external-triggerable at compile time, so hotkeyd remains sole authority
over its own state — it just gained one more legitimate trigger source
beside X11 chords, not an open write surface. No ADR overturn needed.

Migration story: [[im010]] is still `status: proposed` (accepted at
[[sp021]]'s epic finale, pending `dotfiles-ylmp.20`'s live `:0` soak).
This is additive scope layered on top, not a correction to what shipped —
frame as a BODY REFRESH of [[im010]]'s `api_surface`/`components` once
this lands, not a supersession; the core approach (zero-dependency,
binds-compiled-into-source) is untouched. Sequencing: this spec should
not start implementation before [[im010]] itself reaches `accepted`.

[[us019]]'s acceptance_criteria do not currently name external triggers;
whether it gains a new AC line or this stays purely an [[ft011]]
surface-growth is a spec-writing call.

## solution
Extend [[im010]]'s compiled bind table (`hotkeyd/cmd/hotkeyd/config.go`)
with a new declaration kind — an external-trigger layer: same struct
shape as a normal layer entry, but with no chord binding, only a name.
`hotkeyd` gains one new CLI/socket verb, `set-layer <name> --display
:N`, whose handler rejects any name not declared external-triggerable at
compile time — so [[adr0021]]'s compile-time-validation discipline
extends to this surface too, and [[adr0012]]'s read-only-consumer
framing for the *existing* state channel is untouched (this is a new,
narrow, named exception, not a general write API). `quickshell/
qs-region.py` calls `hotkeyd set-layer screenshot-drag --display :10`
instead of `i3-msg mode screenshot-drag`; `quickshell/
qs-focus-border.py` subscribes to hotkeyd's existing state socket
instead of i3's mode-change IPC event — one state-feed pattern instead
of two. The real i3 `mode "screenshot-drag" {}` block and its Escape/q
dead-overlay bindsyms retire from `i3/config.common`, consuming
[[ft011]] (the surface being extended) and touching [[ft006]] (region
capture, `qs-region.py`'s owning feature). No ADR overturn — [[adr0012]]
stays true for every pre-existing layer; this only touches the new
declared subset.

Sequencing carried from `## problem`: implementation waits for [[im010]]
to reach `accepted` first.

Four design decisions, resolved here against the real code so no task
has to guess:

1. **Signal-only layer.** An external-trigger layer (`bind.Layer` gains
   `External bool`) declares NOTHING but the flag: no Binds, Mods,
   ExitKeys, OneShot, Hold, OnHoldRelease, OnExit. It holds zero grabs
   (`chordsFor` contributes nothing) and does NOT shadow the global
   table (`match()` falls through to the global index while it is
   active). Rationale: during a drag the overlay's seat grab owns all
   input anyway, so daemon grabs would be inert; and a STRANDED
   external layer must cost pixels (a red ring, a suppressed border),
   never keys — [[us019]] AC5 ("if the process owning the binds stops,
   the session remains usable"). This is also what makes retiring the
   drag mode's Escape/q honest: the real keyboard escape when the
   overlay dies is the `mode "screenshot"` block's own Escape/q
   fallback, which STAYS in `i3/config.common`.
2. **Separate control socket.** The verb travels over a NEW per-display
   socket `$XDG_RUNTIME_DIR/hotkeyd-<n>-ctl.sock` (one JSON request
   line, one JSON reply line). The state socket `hotkeyd-<n>.sock`
   keeps never reading client bytes — [[adr0012]]'s "mutation never
   flows back through this socket" stays LITERALLY true; the exception
   is a new socket, not a loosened old one.
3. **Authority policy.** The daemon accepts exactly: a name declared
   `External` in the compiled table (enter), or `default` (clear).
   Everything else is refused by name — including any request while a
   chord-entered layer (nav/resize/system/switcher) is active, so an
   external process can never kick the user out of a layer they stand
   in. Idempotent re-set is an ok no-op (publish-on-change already
   guarantees no duplicate feed line).
4. **i3-arbitration divergence, documented.** `engine.run`'s
   `EnterLayer` refuses while i3 owns a mode (its grabs would
   collide). `SetExternalLayer` is ALLOWED while i3 is in a mode —
   necessarily: `qs-screenshot.sh` puts i3 into the real `"screenshot"`
   mode for the bar's hint strip BEFORE the overlay starts, so the drag
   signal always arrives with `i3Mode == "screenshot"`. Safe because a
   signal-only layer contests no grabs. i3 ENTERING a new non-default
   mode while an external layer is active still force-exits it
   (involuntary route 2, unchanged).

Conventions:

- TDD per suite conventions already in the tree: engine/daemon changes
  land with table-driven Go tests first (RED before GREEN); daemon
  seams stay interfaces so `daemon_test.go` drives the new select case
  with fakes, zero Xvfb (the wiring-deletion discipline in daemon.go's
  file doc).
- Stdlib only — `net`, `encoding/json`; `go.mod` require block stays
  empty and the existing invariant test keeps proving it ([[adr0021]]).
- Frozen contracts no task may change: state-socket wire format +
  replay-on-connect ([[ft009]] consumers); `--health` codes 0/6/7/8/9/
  10 ([[adr0017]]); panic path in i3 + shell ([[ft003]]); hold layers
  end by asking the server ([[adr0016]]).
- Consumer spawn discipline: `qs-region.py` calls the verb
  fire-and-forget exactly like today's `i3-msg` call (DEVNULL, a
  failure never blocks or aborts the capture); `qs-screenshot.sh`
  guards with `|| true`. Direct-binary invocation matches the Bar.qml
  `state-tail` precedent — no `hotkeyd.sh` verb, no nushell hop
  ([[adr0015]] via [[adr0021]]'s carve-out).
- Docs and spec prose hard-wrap at 80.

Anti-patterns — reviewers reject on sight:

- reading client bytes on the STATE socket, or any second writer to it
  ([[adr0012]])
- accepting a set-layer name not declared `External` at compile time,
  or any "register a layer at runtime" surface (the general write API
  [[adr0012]]'s framing forbids and `## problem` scopes out)
- an external layer that grabs, shadows the global table, or declares
  behavioral fields (decision 1)
- retry loops in the CLI verb or the border helper's feed reader
  ([[adr0014]] — one attempt, named error, caller owns retry)
- blocking the daemon's run loop on a control client (reads happen in
  the connection's own goroutine under a deadline)
- leaving the old `i3-msg mode screenshot-drag` call beside the new
  verb "for safety" — a signal in two channels is the double-fire
  class [[ft011]] exists to kill
- deleting the `mode "screenshot"` block or its Escape/q fallback —
  only `screenshot-drag` retires

Known limitations, accepted up front:

- If BOTH `qs-region.py` and `qs-screenshot.sh` die without clearing,
  the external layer stays up until a manual `hotkeyd set-layer
  default` or daemon restart — cost is cosmetic only (decision 1);
  accepted over adding a daemon-side timeout (a timeout would make the
  signal lie during a legitimately long 2-tap capture).
- The ctl socket is best-effort at startup like the state socket: bind
  failure is logged and the daemon serves without it; the verb then
  fails named at the client.
- [[us019]] is `status: done`; per `## problem`, spec-writing settled
  this as [[ft011]] surface-growth with NO new AC line. Tasks below
  cite the existing AC lines they genuinely bind to (AC1 state-feed,
  AC4 validated-by-name, AC5 session-stays-usable, AC6
  migration-changes-nothing) and cite [[ft006]]/[[ft011]] contract
  lines where an AC does not reach.

  (`{"set_layer":"<name>"}`) under a read deadline in the connection's
  OWN goroutine, forwards over a channel into `Run`'s select (new
  case), replies `{"ok":true}` or `{"ok":false,"error":"<named>"}`. A
  hung, silent, or garbage-writing client never blocks the run loop
  and never crashes the daemon — both asserted.
- Daemon-side validation against the COMPILED table regardless of what
  the CLI checked: only External-declared names and `default` reach
  `SetExternalLayer`; anything else is refused with the name in the
  reply ([[us019]] AC4 at the socket boundary).
- [[adr0012]] preserved literally: the STATE socket still never reads
  client bytes — existing publisher tests green, plus a test writing
  garbage to the state socket and asserting no state change and no
  disconnect-triggered behavior beyond today's.
- Lifecycle matches the state socket's: stale ctl socket unlinked
  under the flock guarantee at startup, removed at shutdown; bind
  failure logged, daemon serves without it (best-effort, the
  `buildPublisher` policy).
- Wiring-deletion coverage: a `daemon_test.go` test fails if the
  control case is removed from `Run`'s select (the dotfiles-eez2
  discipline named in daemon.go's file doc).
- Grab set provably untouched by external transitions:
  `chordsFor(active external)` equals `chordsFor(default)`, and no
  `SyncBinds` call is made on an external entry/clear.

#### edge_cases
- Two rapid requests (enter then clear racing): serialized through the
  channel, replies in order, final state deterministic.
- Request arriving during shutdown: connection closed, no reply
  deadlock, `shutdown()` still completes.
- Oversized request line: bounded read refuses named, connection
  closed, daemon unaffected.
- `$XDG_RUNTIME_DIR` vanishing under the ctl socket: fail named per
  [[adr0014]], daemon survives (same policy as the state feed).
- Empty line / valid JSON with missing key: `{"ok":false}` with a
  named parse error, never a silent drop.

#### test_plan
