# Spec [[cat002]] [[board]]

## solves
[[us030]]

## implements
[[im015]]

## problem
[[pn001]] can drive the Nothing Phone (1)'s ultrawide lens and manual
exposure ([[us028]], [[poc028]], [[poc029]]), but only from ad-hoc test
scripts. The camera overlay always shoots at the boot default far focus
and auto-exposure, which over-exposes bright scenes.

What exists:
- [[sp044]] (ready, not yet shipped) puts the lens behind its V4L2 subdev
  (`focus_absolute`, group `video`), sets the far default at boot, and
  keeps manual `ExposureTime` / `AnalogueGain` working live. libcamera's
  simple pipeline exposes no `LensPosition`, and the softISP AGC ignores
  `ExposureValue` (split out to [[us029]], draft). So "brighter / darker"
  must come from manual exposure time and gain, not EV, unless [[us029]]
  lands first.
- [[ft019]] (accepted) is the QML camera source behind the overlay; it
  lists exposure controls as a non-goal, so this story widens its
  surface (focus and exposure properties, or a sibling control path).
  [[us026]]'s full stills ([[sp042]]) must keep working and must carry
  the shown focus and exposure.
- The overlay is driven by the hotkeyd `camera` chord layer ([[ft011]],
  entered by $mod+f) over quickshell IPC. [[adr0040]] binds it: a layer
  key that hands work to the overlay runs its command AND ExitLayer, with
  no OnExit talking to the overlay. Focus / exposure step keys need to
  stay in the layer for repeated presses, so spec-writing must either fit
  them under [[adr0040]] (re-enter per step, or a sub-layer) or supersede
  it for idempotent step keys. [[adr0022]] (external processes never
  clear a chord-entered layer) also holds.
- "Nothing stuck" on exit: with no OnExit, the reset must come from the
  overlay or camera start itself (next start restores far focus and
  auto-exposure), including after an involuntary exit (hotkeyd killed,
  2-minute auto-close).

Candidate features: [[ft019]] (widen), [[ft011]] (new layer keys).
Category [[cat002]]. Depends on [[sp044]] shipping the lens subdev.

## solution
hotkeyd keys, overlay does the work, under [[cat002]].

1. Keys: the hotkeyd `camera` layer ([[ft011]], `config.go`) gains
   focus and exposure step keys modelled on the `controls` layer: a
   letter steps one way, held Alt / Shift steps back, held repeats.
   Step keys run `qs-overlay.sh camera-<verb>` and STAY in the layer;
   snap / close keep running their verb + ExitLayer; still no OnExit.
   This contradicts [[adr0040]] ("every key exits"), so a new ADR
   supersedes it: terminal keys exit, step keys stay, no OnExit (the
   snap/close race it fixed cannot return, step keys never leave the
   layer). [[adr0022]] holds: the layer stays compile-time declared.
2. IPC: CameraOverlay's `camera` target gains step verbs (focus
   near / far / default, exposure auto / manual / brighter / darker),
   routed through `qs-overlay.sh` like `snap`.
3. Module ([[ft019]], widened; exposure leaves its non-goals):
   `CameraSource` gains focus (writes the lens V4L2 subdev
   `focus_absolute` from [[sp044]], steps on a fixed code ladder, default
   = the boot far code from [[sp044]], one source) and exposure
   (`AeEnable`, `ExposureTime`, `AnalogueGain` as libcamera request
   controls; switching to manual seeds from the last AE metadata so the
   picture does not jump; brighter / darker walk one ladder: exposure time
   up to the frame limit, then gain). Still captures ([[us026]], [[sp042]])
   carry the same controls on the StillCapture requests.
4. Overlay shows a small focus / exposure readout (as the `capturing…`
   label) while the preview is up.
5. Nothing stuck: every camera start resets focus to the far default
   and exposure to auto, and stop restores focus too, so an involuntary
   exit (hotkeyd killed, 2-minute auto-close) needs no OnExit.

Exposure steps use time + gain, not EV: the softISP AGC ignores
`ExposureValue` ([[us029]]). Depends on [[sp044]] shipping the lens
subdev. Trade-offs: the overlay must be up for focus to change (one
owner, readout and stills consistent) instead of hotkeyd driving
`v4l2-ctl` directly; an ADR supersession; [[ft019]]'s surface widens.
Evidence: live manual exposure on softISP [[poc028]]; subdev focus and
a pre-set focus surviving camera start [[poc029]]. Unproven: a focus
write from the module's own fd while libcamera streams (poc029 set it
before start).
Validated by [[poc030]] (sp045 Task 1): focus writes from the streaming
process's own subdev fd succeed and the picture follows in 1 frame;
manual exposure controls apply in 4-5 frames and AE metadata seeds
manual mode. Sharpness was not measurable in that run and moves to
Task 4's on-device test.

### keys (camera layer)
| key | verb | stays in layer |
|---|---|---|
| `n` (held repeats) | `camera-near` focus one step nearer | yes |
| Alt+`n` / Shift+`n` | `camera-far` one step farther | yes |
| `d` | `camera-refocus` back to the far default | yes |
| `a` | `camera-auto` toggle auto / manual exposure | yes |
| `e` (held repeats) | `camera-brighter` (auto -> manual first) | yes |
| Alt+`e` / Shift+`e` | `camera-darker` (auto -> manual first) | yes |
| space / Return / f | `camera-snap` | no (ExitLayer) |
| Escape / q | `camera-close` | no (ExitLayer) |
| BackSpace | exit key, preview stays | no |

### conventions
- libcamera-qml: C++17, Qt6, `QT_NO_KEYWORDS`; pure maths in
  `controlutil` (no libcamera / Qt Multimedia types) so ctest runs on any
  host; libcamera thread never touches QObjects except via queued calls
  carrying the stream generation (existing pattern in
  `requestComplete`).
- Lens found generically: the first `/dev/v4l-subdev*` whose
  `VIDIOC_QUERYCTRL(V4L2_CID_FOCUS_ABSOLUTE)` succeeds; never a fixed
  number ([[sp044]] convention).
- Focus default comes from the overlay (`focusDefault`, set from the
  machine file `camera.focusFar`, [[adr0037]]); -1 = no default, the
  module then keeps whatever the lens has at start.
- Focus ladder in dioptres: `code = far + round(18.9 * D)` with D in
  {0, 0.5, 1, 2, 3, 5, 8, 12, 20, 25} ([[poc028]] calibration), clamped
  to the control's min / max from QUERYCTRL.
- Exposure ladder in 1/3-stop steps of (time x gain): time first, from
  100 us up to the current frame duration limit, then analogue gain up to
  the control's max; darker walks back the same way. Bounds from
  `camera->controls()` (`ExposureTime`, `AnalogueGain` ControlInfo).
- While manual, every queued request carries `AeEnable=false`,
  `ExposureTime`, `AnalogueGain`; while auto, `AeEnable=true` once on the
  switch and then nothing.
- IPC verb = QML function name: `qs-overlay.sh camera-<verb>` calls
  `quickshell ipc call camera <verb>`; no argument parsing.
- Phone tests that use the camera follow the camera test protocol
  (bd dotfiles-dqhj): announce the run, agree the scene, then start.

### anti-patterns
- No OnExit on the camera layer (still true after [[adr0040]] is
  superseded); reset lives in camera start / stop.
- No retry loops: a failed subdev open or ioctl sets `error` once and
  disables focus keys (`focusAvailable=false`); never loop.
- No `v4l2-ctl` / `system()` from the module or overlay: ioctl from C++.
- No blocking ioctl on the libcamera thread; focus writes happen on the
  GUI thread (one small ioctl).
- Never kill or restart shared daemons (preview-d, hotkeyd of the live
  session) during tests; use a private hotkeyd only via unit tests.
- No EV (`ExposureValue`): the softISP AGC ignores it ([[us029]]).

### known limitations
- The far default exists twice: [[sp044]]'s udev rule and the machine
  file. A mismatch only shifts the overlay's default; Task 8 checks both
  read 385.
- Focus changes only while the overlay is up (single owner, by design).
- Manual exposure is sensor-bounded by the softISP; no AE tuning
  ([[us029]] owns that).
- Auto-exposure still over-exposes bright scenes; manual is the fix here.

#### type

#### depends

#### files_touched

#### success_criteria
- `lcq::focusLadder(far, min, max)` returns ascending codes for the
  dioptre set in conventions, clamped and de-duplicated; far=385 ->
  first 385, contains 404 (1 dioptre, 1 m) and 442 (3 dioptres, ~0.33 m), last <= max
- `lcq::focusStep(cur, ladder, dir)` returns the next code nearer (+1) /
  farther (-1); a `cur` between rungs snaps to the next rung in `dir`;
  stays put at the ends
- `lcq::exposureStep(t, g, dir, tMin, tMax, gMin, gMax)` moves the
  product t*g by 2^(dir/3); time first then gain going brighter, gain
  first then time going darker; clamps at the ends and reports `atLimit`
- ctest `tst_controlutil` passes on the dev box (offscreen)
#### edge_cases
- min > far or max < far (bad default) -> ladder of one rung = clamped far
- tMax < tMin (no frame duration info) -> time fixed at tMin, gain only
- gain max 1.0 -> brighter beyond tMax reports atLimit, no change
- dir 0 or |dir| > 1 -> treated as sign(dir)
#### test_plan
QTest data-driven cases: each edge above, a full brighter walk from
(100 us, 1.0) to limits and back down returning to the start within one
step, focus walk near-then-far returns to far. Mutation check: flipping
the time/gain order in brighter must fail a named case.

- `focusDefault` changed while active -> applied on next `focusReset()`
