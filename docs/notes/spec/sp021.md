# Spec [[cat002]] [[cat001]] [[board]]

## problem
[[ft011]]'s global keybinding daemon is ~3,886 lines of shipped Python
(`hotkeyd.py` 1941, `binds.py` 1137, `layers.py` 742, `state-tail.py` 66) plus
8,722 lines of tests, sanctioned by [[adr0015]] condition 1 — an X-ecosystem
binding with working prior art here (`python-xlib`). The code is healthy, not
rotting: comments cite the bd id of the bug each line prevents, and the 27
fix-commits out of 61 in 60 days are new-feature delivery, not decay.

The problem is the *liability shape*, not the code quality. Four things:

1. **Interpreter dependency on every graphical platform.** [[adr0015]] names
   this itself as load-bearing-negative: "Python's own dependency surface
   (system packages, version skew across Arch / Arch ARM / Termux / WSL) now
   matters on every platform that runs a graphical session." hotkeyd runs on
   native Arch/Manjaro `:0`, WSL, and proot-Arch-on-aarch64.
2. **The bind table is validated at runtime, not at build time.** 42 distinct
   rejection rules in `binds.py` exist to replace i3's duplicate-binding
   detection, and every one of them can only fire once the daemon loads.
3. **Published guarantees contradicted by open defects.** [[ft011]] states
   replay-on-connect is guaranteed; `dotfiles-4uiu` says the socket replays
   nothing until the first layer change. `dotfiles-eez2` records that
   `run_daemon`'s loop wiring has zero unit coverage — a dropped `pump_i3()`
   ships green without Xvfb. 11 open issues sit in this blast radius, 2 at P1.
4. **Duck-typed seams that no-op silently.** `wire_i3_mode`, `pump_i3`,
   `i3_fileno` and `sync_i3_mode` all reach through `getattr` so test stubs may
   omit methods — an optional-wiring seam that degrades identically in
   production, where it should be a hard error.

Constraints the user has fixed: the rewrite target is Go; binds compile into
the source (dwm `config.h` model — no YAML, no parser, `go build` to change a
bind); and the Python daemon keeps running until parity is *proven*, then is
swapped. Parity must be demonstrated by the existing suites, which is itself
blocked — 102 lines across `test-hotkeyd.sh`, `test-launcher.sh` and
`test-panic.sh` invoke `python3 hotkeyd.py` and `pgrep -f "hotkeyd.py"`
directly, so they cannot currently run against any other implementation.

The two blocking unknowns are settled. [[poc014]] proved XI2 passive grabs work
from Go but only via a vendored `jezek/xgb` fork (stock xgb reads a fixed 32
bytes per event and never reads a GenericEvent's `length*4` payload, silently
desyncing the stream and then hanging forever — `exit=124`). [[poc015]] then
proved the fork is unnecessary: 1027 code lines of stdlib-only X client,
`CGO_ENABLED=0`, static 3.8 MiB binary, cross-compiling to arm64/arm, validated
against the real `:0` and `:10` sessions — it read `i3wm.mod: Mod1` off live
xrdp and enumerated the physical `AT Translated Set 2 keyboard` as a slave
distinct from XTEST, which is the device attribution the daemon exists on.

Not yet resolved, and required before execution: [[adr0003]]'s three-condition
gate does NOT authorise this (its condition 2 wants stream proxying or a
measured hot path where GIL serialisation dominates — untrue at one keystroke
per human action), so a new ADR must carry the decision on its real merits
rather than borrowing a clause it fails. Also open: whether `SIGHUP` reload
survives at all, since [[ft011]] promises "re-register only the grabs that
changed; never drop grabs mid-gesture" and compiled binds reduce reload to
rebuild-and-restart.

## solution
Re-implement [[ft011]]'s daemon in Go with **zero external dependencies** — a
stdlib-only X11 client owning exactly the seven requests the daemon uses — and
compile the bind table into the source, dwm `config.h` style: no YAML, no
parser, no `--binds` flag, `go build` to change a bind. This spec deliberately
carries **no `## solves`**: it is a re-implementation, not a new behaviour, so
the acceptance criterion is parity with what [[im009]] shipped and nothing else.
That makes the parity harness the single gate, so it is specified concretely
below rather than left as a word.

**Why zero-dep, settled by experiment.** [[poc015]] validated 1027 code lines of
stdlib-only client — `CGO_ENABLED=0`, static 3.8 MiB, cross-compiling to
arm64/arm — against the REAL `:0` and `:10` sessions, not a synthetic display:
it read `i3wm.mod: Mod1` off live xrdp and enumerated the physical `AT
Translated Set 2 keyboard` as a slave distinct from XTEST, which is the device
attribution the daemon exists on. [[poc014]] is recorded as the rejected
alternative so nobody re-litigates it: XI2 from Go also works over a vendored
`jezek/xgb` fork, but stock xgb reads a fixed 32 bytes per event and never reads
a GenericEvent's `length*4` payload — the stream desyncs into phantom events and
then the next reply is eaten and the connection hangs forever. The fix is 16
lines, but it arrives bundled with ~30 kLOC of third-party code and a patch to
re-apply on every bump. Owning 1027 lines is the smaller liability, and it is
the ideological match for binds-in-source. A third option was surveyed and
closed: `linuxdeepin/go-x11-client` has correct GE handling and a full XI2
surface, but declares `module go-x11-client` rather than its github path so it
cannot be imported at all, and is GPL-3.0-or-later.

**Decision record.** A new `adr####` under [[cat001]] must carry this before
execution, because [[adr0015]] currently sanctions Python for precisely this
daemon under condition 1. The new ADR stands on the merits the PoCs
demonstrated — a static binary with no interpreter dependency on any graphical
platform, no `python-xlib` version skew across Arch / Arch ARM / WSL, and a
bind table validated by the compiler instead of at load time — and NOT on
[[adr0003]]'s three-condition gate, whose condition 2 wants stream proxying or a
measured hot path where GIL serialisation dominates. That is false at one
keystroke per human action, and borrowing a clause the work fails would make
the decision unciteable later. The precedent to follow in shape is [[adr0008]],
which admits a language for a binding-level reason under stated conditions.

The ADR must also **resolve a live conflict rather than inherit it**:
[[adr0003]] requires every compiled helper to expose a `nushell/actions/`
wrapper as its user-facing API, while [[adr0015]] explicitly refuses that here
because a nushell hop in front of a keystroke daemon adds startup cost to the
recovery path. Going Go triggers a mandate the daemon cannot afford. The
resolution is to keep the existing thin shell launcher (`hotkeyd.sh`,
`hotkeyd-panic.sh`) and exempt X-session keystroke daemons from the wrapper
mandate — stated as a scope
carve-out, not left implied. The ADR must also decline to widen: it authorises
this daemon, not a sweep of the repo's other Python.

**Contracts held frozen** — every one of them a [[cat002]] display-platform
obligation. The rewrite is invisible to every consumer. The state
socket keeps its wire format and its replay-on-connect obligation, so
[[ft009]]'s mode pill and `qs-focus-border.py` need no change; [[adr0012]]'s
daemon-owns-state shape and [[adr0014]]'s fail-fast reader discipline carry over
unchanged. `--health` keeps its per-verdict exit codes (0/6/7/8/9/10) under
[[adr0017]] — only a component's own evidence about itself may trigger recovery,
so the codes cannot collapse into a boolean. [[ft003]]'s panic path is untouched
and stays in i3: grabs die with the client, and a key whose job is to rescue an
already-broken session cannot live in the thing that may be broken.
[[adr0016]]'s hold-layer rule is ported verbatim — the layer ends by asking the
server, never by waiting for a release that is not deliverable.

**Structure.** `cmd/hotkeyd` plus `config.go` (the table) and `internal/{bind,
layer,x11,i3,proc}`. The package split does for free what `hotkeyd.py`'s 1941
lines could not: `bind` and `layer` are pure logic testable with no X and no i3,
which is where most of the value in the current 5,486 pytest lines lives. The
`getattr` seams become real interfaces, so a missing method is a compile error
instead of a production no-op.

**Parity is the gate, and it is currently unmeasurable.** `dotfiles-2ats` must
land first: 102 lines across `test-hotkeyd.sh`, `test-launcher.sh` and
`test-panic.sh` invoke `python3 hotkeyd.py` and `pgrep -f "hotkeyd.py"`
directly, so no other implementation can be tested at all. Parameterised on
`HOTKEYD_BIN` / `HOTKEYD_PROC_PAT` and proven green against Python first, those
suites become the contract; the Go daemon ships when they pass on both displays
plus `live_check.py`'s assertions re-expressed in Go. Note the shape change the
suites need: their negative-validation stages inject a bad table at runtime via
`--binds`, which a compiled table has no equivalent for — those cases move to Go
unit tests over table literals rather than being dropped.

**Sequencing, and why the two daemons cannot overlap.** Two XI2 clients
colliding on one chord is refused with `BadAccess` (measured, [[ft011]]), so
parallel-run is per-display, never side-by-side: Go takes `:10` first — harsher
environment, lower stakes — while Python keeps `:0`. [[us020]]
(`per-display-bind-expression`, the fix for the open `dotfiles-y2ju` Alt+Tab
regression) ships in **Python first**, because a live keyboard bug should not
wait on a rewrite; the Go table is designed to express a display qualifier from
day one so it enters the parity target rather than becoming rework.

**Trade-offs taken, explicitly.** `SIGHUP` table reload is **dropped** —
[[ft011]]'s promise to "re-register only the grabs that changed; never drop
grabs mid-gesture" cannot survive binds-in-source, so reload becomes rebuild +
`hotkeyd.sh restart`, `SIGHUP` degrades to a logged no-op, and [[ft011]] is
amended in this spec rather than left stating something false. A Go toolchain
becomes a build dependency, so `hotkeyd/dot.yaml` needs a `command -v go` guard.
5,486 lines of pytest are rewritten, not translated. And three items [[poc015]]
deliberately left unsolved are execution scope, not polish: a windowed
sequence-correlation map (the PoC's linear scan false-positives past ~65k
requests), `MappingNotify` triggering a regrab, and registering all four
lock-bit variants (`0x40`, `|Lock`, `|Mod2`, `|both`) in one
`XIPassiveGrabDevice` with the per-modifier failure list actually inspected
instead of read as all-or-nothing.

**Supersession.** [[im009]] (`python-hotkey-daemon-cutover`, `accepted`) names
Python in its approach and remains the true record of what shipped — which is
exactly what the parity target is. `spec-refinement` mints `im010` for the Go
shape; `im009` gets `## superseded_by [[im010]]` once `im010` is accepted, and
is not edited in place.

## plan
Implements [[im010|go-hotkey-daemon-rewrite]], which supersedes [[im009]].
Parity target: [[im009]]'s shipped shape, gated by the suites [[ft011]]
lists, parameterised first (`dotfiles-2ats`, Task 1). Port order: pure
logic first (`bind`, `layer` — zero X, zero i3), then `x11` (the
[[poc015]] code), then assembly. Language decision lands as `adr0018`
(Task 2) BEFORE any Go task starts.

File tree — target state; Python files stay in place until Task 17:

    hotkeyd/
    ├── go.mod                  # module hotkeyd — require block stays EMPTY
    ├── cmd/hotkeyd/
    │   ├── main.go             # CLI: --display, --check, --health, state-tail
    │   ├── config.go           # THE bind table, dwm config.h style
    │   ├── config_test.go      # table parity + negative-table literals
    │   ├── daemon.go           # run loop: X + i3 + idle tick + heartbeat
    │   ├── grabs.go            # GrabManager + DeviceRegistry
    │   ├── health.go           # verdicts 0/6/7/8/9/10 ([[adr0017]])
    │   ├── ownership.go        # check --ownership
    │   └── statetail.go        # state-tail subcommand (replaces state-tail.py)
    ├── cmd/livecheck/          # live-X assertions (replaces live_check.py)
    ├── internal/bind/          # types, chord parser, validator (42 rules)
    ├── internal/layer/         # engine (4 shapes) + state publisher
    ├── internal/x11/           # transport + requests + XI2 — [[poc015]] port
    ├── internal/i3/            # i3 IPC client — real interface, no getattr
    ├── internal/proc/          # flock lock, heartbeat, grab report, spawn
    ├── hotkeyd.sh              # STAYS SHELL ([[ft003]]); gains engine select
    ├── hotkeyd-panic.sh        # STAYS SHELL, semantics untouched
    └── test-*.sh               # the parity contract, parameterised (Task 1)

Conventions:

- **Zero dependencies is a hard invariant.** `go.mod`'s require block
  empty, no `go.sum`, no `vendor/`; a test asserts `go list -m all`
  prints only the module. `CGO_ENABLED=0`, static binary, built in
  place as `hotkeyd/hotkeyd` (gitignored) — the tree runs in place, no
  links, exactly as today.
- Wire parsers verify by arrival: assert `off == len(buf)` after every
  variable-length walk ([[poc015]] gotcha 4).
- Seams are interfaces. A test double implements the FULL interface or
  does not compile — the `getattr` no-op class of defect is deleted by
  the type system, not re-audited.
- Startup failures are fatal with a NAMED message and keep the Python
  daemon's distinct exit codes (5 = XI2 unavailable, 4 = panic latch
  present). No `panic()` on the serving path; errors wrapped with `%w`.
- Frozen contracts (a task changing any of these is wrong): state
  socket wire format + replay-on-connect ([[ft009]] consumers);
  `--health` exit codes 0/6/7/8/9/10 ([[adr0017]]); panic path stays in
  i3 + shell ([[ft003]]); hold layers end by asking the server
  ([[adr0016]]); daemon-owns-state ([[adr0012]]); fail-fast readers
  ([[adr0014]]).
- Docs and spec text hard-wrap at 80; Go code is gofmt's problem.

Anti-patterns — reviewers reject on sight:

- any third-party import (the whole point of [[poc015]])
- core `XGrabKey` fallback when XI2 is missing (exit 5, named — never
  silent degradation)
- `XGrabKeyboard` / exclusive `XIGrabDevice` in any path
- device attribution read off the event-header `deviceid` (the master)
  instead of `sourceid` (the physical slave)
- ending a hold layer by waiting for a release event ([[adr0016]])
- collapsing health verdicts toward a boolean ([[adr0017]])
- pidfile-based daemon identity (argv `--display` is the identity)
- trusting GenericEvent sequence numbers for correlation (measured
  useless — [[poc015]] gotcha 10)
- fixed-size event/reply assumptions (never assume 120 bytes)
- a linear pending-error scan (16-bit wrap false-positives past ~65k)
- deriving the next grab set from the ACTIVE set — wanted and active
  are kept separately (dotfiles-hwds.41, recorded in [[im009]])
- a nushell hop anywhere in the start/recovery path ([[adr0015]],
  carried into `adr0018`)
- unbounded reader retry loops ([[adr0014]])

Known limitations, accepted up front:

- `SIGHUP` reload is DROPPED: rebuild + `hotkeyd.sh restart`; SIGHUP
  degrades to a logged no-op. [[ft011]] is amended in Task 18.
- Go toolchain becomes a build dependency (guarded, Task 15).
- Sway stays out of scope (no X passive grabs on Wayland).
- The xrdp 120 ms release guard is permanent ([[ft011]], measured).
- 5,486 pytest lines are rewritten, not translated; coverage parity is
  measured by scenario inventory (Tasks 6, 7, 14), not line count.
- Two XI2 grabbers on one display collide (`BadAccess`), so cutover is
  per-display, never side-by-side: Go takes `:10` first, `:0` last.

  through `HOTKEYD_BIN` (default `"$HERE/hotkeyd.py"`, shebang covers
  python3) and `HOTKEYD_PROC_PAT` (default `hotkeyd\.py`, used in every

- The `--binds` negative-validation stages (`$TMP/faulty.py`,
  `$T8/trap.py`) gain a capability guard `HOTKEYD_HAS_BINDS_FLAG`
  (default 1). When 0, each stage runs the named Go replacement
  (`go test ./internal/bind ./cmd/hotkeyd -run 'TestReject'`) and FAILS
  if that test binary is absent — the cases are never silently skipped.
- `test-panic.sh`'s mocked `ps` lines (`printf '$FAKE_PID python3
  hotkeyd.py ...'`) derive from `HOTKEYD_PROC_PAT`, not literals.
- `test-launcher.sh`'s `PANIC_CHORD` introspection (`python3 -c 'import
  binds'`) accepts a `HOTKEYD_PANIC_CHORD` override so a non-Python
  binary can be probed; default keeps the Python import.

#### edge_cases
- `HOTKEYD_PROC_PAT` must not match `hotkeyd.sh` or the suite's own
  argv (a bare `hotkeyd` pattern would); patterns anchor on
  `--display`.
- Concurrent suite runs: display-scoped pkill patterns preserved so one
  run cannot kill the other's daemon (test-hotkeyd.sh:345 comment).
- `env -u I3SOCK setsid "$HERE/hotkeyd.py"` direct-invocation stages
  (latch bypass) must use `$HOTKEYD_BIN` too — bypassing the launcher
  is the point of those stages, not bypassing the parameterisation.

#### test_plan
- Run each suite twice (defaults; then `HOTKEYD_BIN` pointed at a shim
  that execs the python daemon under a renamed argv) — the second run
  proves the pattern plumbing actually selects, not just defaults.
- `grep -c 'python3\|hotkeyd\.py'` over the three suites post-change:
  every remaining hit is a default assignment or a comment, listed in
  the commit message.
