# Spec [[cat001]] [[cat002]] [[board]]

## solves
[[us022|agent-counts-per-project]]

## problem

There is no way to ask how many claude agents are running per project and
in which state. `claude agents --all --json` answers *what agents exist*
but is blind to projects: it is scoped to one `CLAUDE_CONFIG_DIR`
(7 rows under `~/.claude-personal`, 6 under `~/.claude-work` — one
invocation never sees both), and it labels each agent only by `cwd`.
Attribution therefore has to be reconstructed, and today it is
reconstructed by eye, per session, every time.

The missing capability is a **census**: a CLI that joins the agent list
with the tmux pane→project assignment and returns per-project counts
bucketed by state. It is a horizontal capability — the census emits
structured data and does not render it; the rendering consumers come
later and are several.

Two attribution paths exist and both are needed:

- Interactive agents carry a live `pid` whose process parent is the tmux
  `pane_pid`; the pane's `session_group` **is** the project name
  (`dotfiles_0..3` → group `dotfiles`). Verified: agent 788567 → pane
  788390, agent 3290937 → pane 3290465. This path is authoritative.
- Background agents have no pane. Their `cwd` as reported by
  `claude agents --all --json` is already the *origin* project root, not
  the isolation worktree (job `462e7625` runs in
  `.claude/worktrees/zettel-write-skill` yet reports
  `cwd: /home/jan/.dotfiles`), so a `cwd` match against the [[ft001]]
  registry is sound — with one hazard below.

The hazard: [[ft001]]'s `~/.config/project/projects.yaml` does not hold
unique paths. `auctions` and `iac` both point at
`/home/jan/repos/b3tchi/auctions`; `mindtime` and `mindtime-python` both
point at the mindtime solution dir. A `cwd`-only join silently
mis-credits those agents. The tmux path disambiguates them for free
whenever a pane exists; where it does not, the census must refuse to
guess and surface the agents under an `unknown` row carrying the raw
`cwd`, so undercounting is visible rather than invented.

Consumers, none of which should own this join themselves: a quickshell
bar widget ([[cat002]]), the project switcher and `project list` in
[[ft001]] / [[im001]], the tmux status line, and `claude/statusline.sh`.
Each wants the same numbers rendered differently, which is what makes
this a [[ft001]]-consuming feature rather than an extension of it —
[[ft001]] registers and navigates projects, it does not observe what is
running inside them.

Scope decided during brainstorming:

- Source is the supported CLI surface only — `claude agents --all --json`
  run once per account and tagged. The richer
  `~/.claude-*/jobs/*/state.json` and `~/.claude-*/sessions/*.json`
  files were surveyed and rejected: undocumented on-disk format, and the
  sessions registry is 23/26 stale dead pids.
- States normalize to four buckets: `busy`/`working` → working,
  `idle`/`shell` → idle, `waiting`/`blocked`/`failed` → blocked,
  `done` → done. Any state the upstream adds later lands in `other`
  rather than being dropped.
- Surface: `agent-census [--json] [--project <name>] [--detail]`,
  emitting one row per project with the four counts, a total, and an
  account breakdown, plus the `unknown` row.

Binding decisions: [[adr0001]] makes this nushell — structured pipeline
in the workflow-tooling layer that completes and exits; [[adr0002]]
supplies no bash trigger; [[adr0003]] is not met (no listener, no
streaming hot path), so no Go helper.

Deliberately out of scope: no cache, no daemon, no bar widget. Measured
cost is ~600 ms per account, ~600 ms wall when the two account calls run
in parallel, against 4 ms for `tmux list-panes` and 10 ms for `ps`. That
is fine on demand and wrong for a polling bar, so a TTL cache or an
[[adr0012]]-style read-only broadcast (with [[adr0014]] reader-loop
discipline) is a follow-up spec to be written when a real bar consumer
exists — not now.

A new `ft###` is minted at spec-writing time; no existing feature covers
agent observation. Surveyed for duplication: [[ft001]] (registry and
navigation — consumed, not extended), [[ft004]], [[ft005]], [[ft010]]
(daemons with their own state surfaces — none census agents).

## solution

Mint the census as its own capability — [[ft012]] `agent-census` — and
ship it as a single nushell action on `PATH`
(`nushell/actions/agent-census` → `~/.local/bin/agent-census`, the shim
pattern already used by `wm-ipc.nu` and `project-picker`). One exec,
structured output, no rendering: the bar widget, the project picker,
the tmux status line and `claude/statusline.sh` each consume the same
rows and shape them themselves. That is what makes this a feature
rather than an extension of [[ft001]] — the registry answers *which
projects exist*, the census answers *what is running in them*.

Language is settled by decision, not preference. [[adr0001]] puts any
structured-data pipeline in the workflow-tooling layer ([[cat001]]) in
nushell; [[adr0002]] supplies no bash trigger (this is neither
pre-nushell bootstrap, nor the tmux outer shell, nor a sub-50 ms
one-liner); [[adr0003]] is not met, since there is no listener, no
stream proxying and no hot path — the work is a pipeline that completes
and exits. So: nushell action, no Go helper, no daemon.

The join runs in three steps. Both accounts are fetched concurrently
with `par-each` over the two `CLAUDE_CONFIG_DIR` values, each row
tagged with the account it came from — ~600 ms wall instead of ~1.2 s
serial, and correct where a serial single-account call is simply blind.
A pane index is then built once from `tmux list-panes -a -F
"#{pane_pid} #{session_group}"` plus `ps -eo pid=,ppid=` (4 ms and
10 ms — free next to the agent fetch). Finally each agent resolves:
live `pid` → ancestor walk to a `pane_pid` → the pane's
`session_group` is the project; otherwise longest-prefix `cwd` match
against the [[ft001]] registry; tie or miss → the `unknown` row with
the raw `cwd` kept.

The trade-off taken is refusing to guess. [[ft001]]'s registry does not
hold unique paths (`auctions`/`iac`, `mindtime`/`mindtime-python`), so
a `cwd`-only join would silently mis-credit agents while looking
complete. Routing those to `unknown` makes the gap visible and
fixable — a slightly uglier table beats confidently wrong counts, and
the tmux path already resolves the collision whenever a pane exists.
The second trade-off is source discipline: only the supported
`claude agents --all --json` surface is read. The richer
`~/.claude-*/jobs/*/state.json` and `sessions/*.json` were surveyed and
rejected — undocumented on-disk format, and the sessions registry is
23/26 stale dead pids. Reported `cwd` already carries origin-not-
worktree semantics, which was the only thing those files were needed
for.

Deliberately not built here: no cache, no daemon, no bar widget. The
~600 ms cost is fine on demand and wrong for a polling bar, so when a
real bar consumer lands it gets its own spec — a TTL cache, or an
[[adr0012]]-style read-only broadcast under [[adr0014]] reader-loop
discipline ([[cat002]]). Building either now would be speculative.

Attribution and bucketing are covered by tests against captured
fixtures of the three inputs, so the joins are verifiable without live
agents in a given state.

### conventions

**Two layers, and the split is load-bearing.** A *probe layer* owns
every shell-out — `claude agents --all --json` per account, `tmux
list-panes`, `ps`, the [[ft001]] registry read. A *pure transform
layer* (`bucket-state`, `build-pane-index`, `resolve-project`,
`shape-rows`) takes those structures as arguments and returns
structures. No transform function reaches for the world. That is what
lets the tests drive real logic from fixtures without arranging live
agents in a given state, which is otherwise impossible to do
repeatably.

**Probe failures degrade, they do not abort.** A missing account
directory contributes zero rows. A dead tmux server yields an empty
pane index, and attribution falls through to the `cwd` path. A missing
`projects.yaml` yields an empty registry, and everything unattributable
lands in `unknown`. The census always completes and exits 0.

**Nushell throughout**, per [[adr0001]]: this is a structured pipeline
in the workflow-tooling layer that completes and exits. [[adr0002]]
supplies no bash trigger — not bootstrap, not the tmux outer shell, not
a sub-50 ms one-liner. [[adr0003]] is unmet — no listener, no stream
proxying, no hot path — so no Go helper.

**Action lands on `PATH` as a shim**, matching `wm-ipc.nu`,
`project-picker` and the `tmux-*` actions: `nushell/dot.yaml` links
`actions/agent-census` to `~/.local/bin/agent-census` so a
non-nushell consumer invokes one exec.

### anti-patterns

- **Never guess an ambiguous attribution.** [[adr0017]] is binding
  here: "absence of evidence must never be encoded as evidence of
  absence", and "I cannot tell" is a first-class verdict. The registry
  holds colliding paths (`auctions`/`iac`,
  `mindtime`/`mindtime-python`); a `cwd` tie routes to `unknown` with
  the path shown. Picking the first match would make the table look
  complete while being wrong, which is the failure mode the ADR exists
  to prevent.
- **Never edit a captured fixture to accommodate an upstream change.**
  Per [[adr0023]]'s principle, a fixture is a historical record of what
  the tool actually emitted. When `claude agents --all --json` changes
  shape, add a new fixture next to the old one; rewriting the old one
  makes it assert something that never happened.
- **Never drop an unrecognised state.** Anything outside the known set
  goes to `other` and stays in `total`. Silent dropping makes the
  counts disagree with reality in exactly the case that signals the
  tool needs updating.
- **Never read `~/.claude-*/jobs/**/state.json` or
  `~/.claude-*/sessions/*.json`.** Undocumented on-disk format, and the
  sessions registry is mostly stale dead pids. The supported
  `claude agents --all --json` surface already reports origin `cwd` for
  worktree-isolated jobs, which was the only thing those files offered.
- **No daemon, no cache, no background loop.** Out of scope by
  decision; see known limitations.
- **No `panic`-equivalents on probe paths** — no bare `open` on a file
  that may not exist, no unguarded `from json` on possibly-empty
  output. Every probe wraps in `try` and yields its empty value.

### known limitations

- One invocation costs ~600 ms, dominated by `claude agents --all
  --json` at ~600 ms per account (measured; `tmux list-panes` is 4 ms
  and `ps` is 10 ms). Running the two account probes concurrently keeps
  wall time at roughly one probe. This is fine on demand and wrong for
  a bar polling on a timer — a TTL cache or an [[adr0012]]-style
  read-only broadcast under [[adr0014]] reader-loop discipline is a
  separate spec, to be written when a real bar consumer exists.
- An ungrouped tmux session has an empty `session_group`. Attribution
  falls back to the session name with a trailing `_<N>` stripped, then
  to the `cwd` path.
- Accounts are discovered as `~/.claude-*` config directories. A
  non-standard `CLAUDE_CONFIG_DIR` outside that pattern is not counted.
- A background agent that has never had a pane is attributed by `cwd`
  only, so it inherits the registry's ambiguity and may land in
  `unknown`.

## tasks

Success criteria bind to [[us022]]'s `## acceptance_criteria`,
referenced below as AC1-AC7 in their listed order:

1. per-project idle / working / blocked / done counts
2. every configured account counted
3. pane attribution wins over a shared filesystem path
4. unattributable agents reported as such with `cwd`, never guessed
5. structured output consumable without parsing a table
6. completes with zero agents, no tmux, or a missing account
7. an unrecognised state is still counted, not dropped

### Task 1: Fixture capture and pure-layer test runner

#### type
test-infrastructure

#### effort
4h

#### depends
none

#### files_touched
- `tests/agent-census/fixtures/*` (new)
- `tests/agent-census/run-tests.nu` (new)

#### success_criteria
- `nu tests/agent-census/run-tests.nu` runs green on a machine with no
  tmux server and no claude agents at all, proving the suite drives the
  pure layer from fixtures rather than the live system (underwrites
  AC6).
- `fixtures/agents-personal.json` and `agents-work.json` are verbatim
  captures of real `claude agents --all --json` output from two
  different config directories, together containing at least one
  `interactive` record with a `pid`, one `background` record without
  one, and one record whose job is worktree-isolated yet reports the
  repo root as `cwd` (underwrites AC2, AC3).
- `fixtures/projects.yaml` contains at least two distinct project names
  mapped to one identical path, reproducing the real registry collision
  (underwrites AC4).
- `fixtures/agents-unknown-state.json` carries a state string outside
  the documented set (underwrites AC7); `agents-empty.json` is an empty
  list and `panes-empty.txt` is an empty file (underwrite AC6).
- The runner reports per-case pass/fail with the case name, and returns
  a non-zero exit status when any case fails, so it is usable as a
  gate.
- Every fixture file carries a header comment recording the command
  that produced it and the date, so a later shape change is diagnosable
  against a known origin.

#### edge_cases
- Fixture files containing paths from the capturing machine — the
  runner must not assume `/home/jan`; cases parameterise the registry
  root so the suite passes under a different `$HOME`.
- A fixture with CRLF line endings (captured through a Windows-side
  pipe) must not silently produce a pane index with trailing `\r` in
  project names.
- Empty file versus absent file are distinct cases and both are
  covered — `panes-empty.txt` exists and is empty; a separate case
  passes a path that does not exist.

#### test_plan
The runner itself is the deliverable, so the meaningful check is that
it fails when it should. Verify by mutation: temporarily break
`bucket-state` to map `blocked` to `idle` and confirm a named case goes
red; break `resolve-project` to return the first registry match on a
tie and confirm the collision case goes red. A suite that stays green
under both mutations is not testing anything and is rejected. Record
both mutation results in the task notes as the evidence that the suite
has teeth.

### Task 2: Pure transform layer — bucketing, attribution, row shaping

#### type
feature

#### effort
6h

#### depends
Task 1

#### files_touched
- `nushell/actions/agent-census` (new)
- `tests/agent-census/run-tests.nu` (extend)

#### success_criteria
- `bucket-state` maps exactly per [[ft012]]'s `## data_model` table:
  `busy`/`working` to `working`; `idle`/`shell` to `idle`;
  `waiting`/`blocked`/`failed` to `blocked`; `done` to `done`; every
  other string to `other`. Driven from `agents-unknown-state.json`, the
  unrecognised state appears in `other` and in `total`, and the row's
  four named buckets plus `other` sum to `total` (AC1, AC7).
- `build-pane-index` turns `panes.txt` plus `ps.txt` into a
  `pane_pid → project` map, and `resolve-project` walks an agent pid's
  ancestors to a pane, returning that pane's `session_group`. Asserted
  against a fixture agent whose pid is two levels below its pane_pid
  (AC3).
- Given `fixtures/projects.yaml` with its colliding path, an agent with
  a pane resolves to the pane's project, while an agent with the same
  `cwd` and no pane resolves to `unknown` — the same path yielding two
  different verdicts is the assertion that pane attribution genuinely
  takes precedence (AC3, AC4).
- The `unknown` row carries `project: "unknown"`, `path: null`, and a
  `cwds` list containing each unattributed agent's working directory
  (AC4).
- `shape-rows` output matches [[ft012]]'s `## data_model` field-for-
  field, including the `accounts` breakdown, and the sum of every row's
  `total` equals the number of input agent records — no agent
  double-counted across projects, none lost.
- No function in this layer invokes an external command; verified by
  the suite running with `PATH` emptied for the transform cases.

#### edge_cases
- Ancestor walk reaches pid 1 without finding a pane → fall through to
  the `cwd` path rather than looping or erroring.
- A `ppid` cycle in a malformed `ps` fixture → the walk is depth-bounded
  and returns "no pane" rather than hanging.
- `cwd` exactly equal to a registry path versus a deeper subdirectory —
  both attribute to that project; a sibling directory sharing a name
  prefix (`/repos/auctions-old` against registered `/repos/auctions`)
  must NOT match, which is the difference between prefix matching on
  strings and on path components.
- Empty `session_group` (ungrouped session) → strip a trailing `_<N>`
  from the session name; if nothing remains, treat as no pane.
- Two registry entries where one path is a subdirectory of the other →
  longest prefix wins, unambiguously, and this is not a collision.
- Zero agents in → an empty row set, not a row of zeros.
- Project name or path containing spaces or non-ASCII characters
  survives the pane index round-trip intact.

#### test_plan
Each criterion above is a named case in `run-tests.nu` driven from the
Task 1 fixtures. The tests that matter are the discriminating ones, and
they are named for the bug they catch: `pane-beats-colliding-cwd`
(same `cwd`, two verdicts), `prefix-match-is-path-component-wise`
(`auctions-old` must not match `auctions`), `unknown-state-still-
counted` (buckets plus `other` equal `total`), `no-agent-lost-or-
double-counted` (row totals sum to input length). Assertions are on
values, never on a function merely existing or returning non-null.

### Task 3: Probe layer — dual-account fan-out, pane index, degradation

#### type
feature

#### effort
5h

#### depends
Task 1

#### files_touched
- `nushell/actions/agent-census` (extend)
- `tests/agent-census/run-tests.nu` (extend)

#### success_criteria
- Accounts are discovered by globbing `~/.claude-*` config directories,
  and `claude agents --all --json` runs once per discovered account
  with `CLAUDE_CONFIG_DIR` set to it, each returned record tagged with
  its account name. Against the two live accounts this yields strictly
  more agents than a single ambient invocation returns (AC2).
- The two account probes run concurrently, and measured wall time for
  the full census is within 25% of a single account probe rather than
  the sum of both. Recorded as a before/after timing in the task notes.
- A configured account directory that does not exist contributes zero
  rows and no error; the census still exits 0 (AC6).
- With no tmux server reachable, the pane index is empty, attribution
  falls through to `cwd`, and the census exits 0 (AC6).
- With `projects.yaml` absent, the registry is empty, every agent lands
  in `unknown` with its `cwd`, and the census exits 0 (AC4, AC6).
- Zero agents across all accounts yields an empty row set and exit 0,
  not an error and not a fabricated zero row (AC6).
- Every probe is individually wrapped so that one failing probe cannot
  abort the others; asserted by pointing each probe at a deliberately
  broken command in turn and confirming the remaining output is still
  produced.

#### edge_cases
- An agent's `pid` dies between the `claude` probe and the `ps` probe →
  the ancestor walk finds nothing, and it falls through to `cwd`
  instead of erroring on a vanished pid.
- `claude agents --all --json` emitting empty output or non-JSON (a
  version mismatch, an auth prompt) → that account contributes zero
  rows and the census continues; the failure is visible in `--detail`
  rather than silently indistinguishable from "no agents".
- `tmux list-panes` returning a non-zero status because no server is
  running → empty index, not an abort.
- A `~/.claude-*` glob match that is a file rather than a directory
  (`~/.claude.json`, `~/.claude.json.backup` both exist on this
  machine) → skipped, not probed as an account. This is a real hazard,
  not hypothetical.
- `HOME` unset or pointing somewhere without config directories → zero
  accounts, empty output, exit 0.

#### test_plan
Probe-layer tests use stub commands on a temporary `PATH` rather than
the real `claude`/`tmux`, so failure modes are arranged deterministically:
a stub that exits non-zero, one that prints non-JSON, one that prints
nothing. Named cases: `broken-account-probe-does-not-abort-others`,
`no-tmux-falls-through-to-cwd`, `claude-json-file-not-treated-as-
account` (the `~/.claude.json` hazard above), `missing-registry-yields-
unknown`. The concurrency claim is verified by timing, not by reading
the code — a `par-each` that silently serialises passes a code review
and fails this test.

### Task 4: CLI surface — flags, output shaping, PATH link

#### type
feature

#### effort
4h

#### depends
Task 2, Task 3

#### files_touched
- `nushell/actions/agent-census` (extend)
- `nushell/dot.yaml` (edit)
- `tests/agent-census/run-tests.nu` (extend)

#### success_criteria
- Bare `agent-census` prints a table with one row per project plus the
  `unknown` row when one is warranted, columns matching [[ft012]]'s
  `## api_surface` (AC1).
- `agent-census --json` emits valid JSON parsing to the same rows;
  asserted by piping through `jq` and comparing against the table run's
  values, so the two surfaces cannot drift (AC5).
- `agent-census --project <name>` restricts to one row, and an
  unregistered or agent-free name yields an empty result with exit 0 —
  not an error (AC1, AC6).
- `agent-census --detail` emits one row per agent with `project`,
  `account`, `kind`, `state`, `bucket`, `name`, `cwd`, `pid`, and the
  row count equals the sum of the count view's totals — the two views
  cannot disagree (AC1, AC5).
- `nushell/dot.yaml` gains `actions/agent-census:
  ~/.local/bin/agent-census` under the linux section; after `rotz
  link`, `agent-census --json` runs from a non-nushell shell as a
  single exec (AC5).
- Exit status is 0 for every completing census including the empty one;
  a non-zero status is reserved for the action being unable to run at
  all (AC6).

#### edge_cases
- Output piped to a non-tty → the table renders without ANSI escapes so
  a consumer capturing stdout is not handed control characters.
- `--json` combined with `--detail` → detail rows as JSON; the flags
  compose rather than one silently winning.
- `--project` given a name that exists in the registry but has no
  running agents → empty result, exit 0, distinct from a name that does
  not exist at all, which also gives empty and exit 0 but says so in
  `--detail`.
- A project name containing a character that breaks naive table
  alignment (non-ASCII, or one long enough to wrap) still emits correct
  JSON.
- `rotz link` on a platform without the linux section → no broken
  symlink left behind.

#### test_plan
Surface tests run the assembled action end-to-end against stubbed
probes, so the assertions are about the contract rather than about live
system state. Named cases: `json-and-table-agree` (parse both, compare
values — catches a shaping change applied to one surface only),
`detail-rows-sum-to-counts` (catches a bucketing bug that a
counts-only test would hide), `empty-census-exits-zero`,
`flags-compose`. The `rotz link` criterion is verified by running the
link and executing the shim from bash, not by inspecting the yaml.
