# Spec [[cat002]] [[board]]

## solves
[[us030|camera-keyboard-focus-exposure]]

## problem
The phone now has three cameras the overlay can open: the imx766 wide
(new 2026-11-26, nothing-pmos imx766/ driver, its own AK7377 lens), the
s5kjn1 ultrawide and the imx471 front. The overlay shows one camera, fixed
by the machine file's `camera.id` (today the wide, because its colours
look better), and its focus ladder (`far + 12.9 x dioptres`, measured on
the ultrawide's dw9719) barely moves the wide's 12-bit lens. Switching
camera means editing the machine file and restarting quickshell.

Wanted (user decisions 2026-11-26/27):

- In the camera layer, `c` toggles wide <-> ultrawide and a second key
  switches to / from the front camera; both are step keys that stay in
  the layer ([[adr0041]]).
- Switching is seamless: the new camera starts with the same focus
  DISTANCE (dioptres, not lens codes), exposure mode + time, ISO rung,
  and the old white-balance gains, after which auto-WB re-adapts to the
  new sensor. The front camera has no lens: focus is kept and restored on
  the way back.
- The readout shows the active camera (W / UW / F).
- Unchanged from [[us030]]: closing the overlay leaves nothing stuck; the
  next open starts on the default camera at default focus and auto
  exposure.

Shape agreed at idea time:

- Machine file ([[adr0037]]): `camera` becomes a `cameras` list of
  `{id, label, focusFar, focusSlope}`, the first entry the default; the
  single `camera.id` / `focusFar` migrates.
- LibCamera QML module ([[ft019]], widened): a per-camera `focusSlope`
  next to `focusDefault`, focus get/set in dioptres, and read/write of the
  current exposure time, gain and colour gains so the overlay can carry
  them. The overlay owns the carry-over state; `cameraId` already switches
  cameras live and `rotation` already comes per camera from libcamera.
- Calibration: the wide's `focusFar` and `focusSlope` from the chart rig
  at 2-3 known distances (daylight).

Supersession vs refresh: same story, widened AC; [[im015]] gets a body
refresh at spec-retro, no supersession. No ADR is overturned.

Out of scope: running two cameras at once (libcamera's simple pipeline
streams one camera per media device, tested 2026-11-26), colour tuning of
the imx766.

## solution
The overlay owns the shot settings; the LibCamera QML module ([[ft019]],
widened) gains value setters and a per-camera focus calibration. Category
[[cat002]].

- Keys ([[ft011]], [[adr0041]]): the camera layer gets an `l` step bind via
  `cameraStepBinds` - plain `l` toggles the rear cameras (wide <-> ultrawide),
  reverse (Alt / Shift) switches to / from the front camera, reset (Ctrl)
  returns to the default camera. Each runs `qs-overlay.sh
  camera-lens|lens-front|lens-default`, an IPC call into CameraOverlay; like
  the other step keys it stays in the layer and is a no-op while closed or
  capturing.
- Machine file ([[adr0037]], [[adr0038]]): `camera` becomes `cameras: [{id,
  label, focusFar, focusSlope, wbRatio}]`; list order defines the rear toggle,
  the front camera is the entry libcamera reports as facing front, the first
  entry is the default. The single `camera.id` / `focusFar` migrate. Starting
  values: wide focusFar ~250, focusSlope ~270 codes/dioptre (rough sweep
  2026-11-27, low code = far); ultrawide 385 / 12.9; WB gain ratio
  wide/ultrawide ~R 1.55, B 1.04 (one white-wall capture).
- Module ([[ft019]]): `focusSlope` replaces the fixed 12.9 in the focus
  ladder; focus is also readable / settable as a distance (`focusDioptres`);
  absolute `setExposureTime(us)` (manual) and `setIso(rung)`; read-only
  `colourGains` and `setColourGains(r, b)`, which applies the gains with AWB
  off and hands back to auto after a short hold (the mechanism the still
  capture already uses). Switching keeps using `cameraId`, which restarts the
  stream on the new camera; rotation already comes per camera.
- Overlay (CameraOverlay.qml): before a switch it snapshots {focusDioptres,
  autoExposure, exposureTime, iso, colourGains}; after the new camera's first
  frame it re-applies them - focus only when the new camera has a lens (the
  front camera keeps the value for the way back), WB gains scaled by the
  cameras' `wbRatio`. The readout shows the camera label (W / UW / F).
- Unchanged: closing resets everything and every open starts on the default
  camera ([[us030]]); a failed switch shows the error and is not retried
  ([[adr0014]]); the overlay keeps owning kwi3's mode ([[adr0042]]).

Trade-offs: WB and focus carry-over are only as good as the rough machine
file numbers (refinable later without code); the carry-over state lives in
QML, so other module consumers do not get it (none exist today).

## plan
Two repos. libcamera-qml (b3tchi/libcamera-qml, worked on the phone clone
`~/.local/src/libcamera-qml`, built and installed by `rotz install camera`)
carries the module side ([[ft019]], widened). The dotfiles carry the machine
file, the overlay and the keys ([[ft011]]). Story [[us030]] (AC 6-8 are this
spec's); implementation card [[im015]]; category [[cat002]].

File tree (touched):

```

  src/controlutil.{h,cpp}      focusLadder(far, slope, min, max), dioptre helpers,
                               isoClamp helper
  src/camerasource.{h,cpp}     focusSlope, focusDioptres, setExposureTime, setIso,
                               colourGains, setColourGains
  tests/tst_controlutil.cpp    ladder / dioptre / iso-clamp cases
  tests/exposure_smoke.{qml,sh} setter round trip on the phone
  README.md                    API list
dotfiles/
  quickshell/machines/nothing-spacewar.json   cameras: [...]
  quickshell/config/Common/Session.qml         machine.cameras normalisation
  quickshell/config/Common/CameraReadout.js    metres(pos, far, slope), label
  quickshell/config/CameraOverlay.qml          lens switch, snapshot / re-apply,
                                               IPC lens / lensFront / lensDefault
  quickshell/qs-overlay.sh                     camera-lens|camera-lens-front|
                                               camera-lens-default
  quickshell/config/Common/ModeBarTheme.qml    camera / -reverse / -reset strips
  quickshell/test-camera-readout.{qml,sh}      slope + label cases
  hotkeyd/cmd/hotkeyd/config.go                cameraStepBinds: l
  hotkeyd/cmd/hotkeyd/host_phone_test.go       l binds in the camera layer
```

Conventions:

- Machine data lives in the machine file ([[adr0037]], [[adr0038]]); QML
  never hard-codes a camera id, a focus calibration or a WB ratio.
- Step keys stay in the camera layer ([[adr0041]]); the switch keys are step
  keys (`l` plus the layer's reverse / reset modifiers), never repeat.
- One attempt, no retry ([[adr0014]]): a failed switch leaves `cam.error`
  on screen; the next key press is the retry.
- The overlay keeps owning kwi3's mode until it closes ([[adr0042]]).
- Dioptres are the camera-independent focus unit: code = far + slope x D.
- Module setters clamp to the CURRENT camera's limits and report the value
  applied through the existing NOTIFY signals; they never throw or block.

Anti-patterns (reject in review):

- applying focus to a camera with `focusAvailable == false`;
- scaling WB by a guessed ratio when a camera has no `wbRatio` (no ratio =
  carry the raw gains, i.e. today's behaviour);
- re-applying settings before the new camera's first exposure metadata
  (the module resets exposure on every start);
- retry loops or timers that re-issue a failed switch;
- blocking calls (sleep, synchronous process runs) in IPC handlers;
- changing the focus ladder of the ultrawide (slope 12.9 must keep its
  current rungs bit-for-bit).

Known limitations:

- WB ratios come from one white-wall capture and focus calibration of the
  wide from one rough sweep (2026-11-27); both are machine-file numbers,
  refinable without code.
- Only one camera streams at a time (libcamera simple pipeline); a switch
  is a stop/start of ~1 s with the last frame on screen.
- The front camera has no lens: focus is not applied there and its value is
  kept for the way back.

## tasks

### Task 1: Per-camera focus slope and dioptre focus in the module
#### type
feature
#### effort
5h
#### depends
none
#### files_touched
libcamera-qml: src/controlutil.h, src/controlutil.cpp, src/camerasource.h,
src/camerasource.cpp, tests/tst_controlutil.cpp, README.md
#### success_criteria
- `focusLadder(far, slope, min, max)` returns `far + round(slope * D)` for
  D in {0, 0.5, 1, 2, 3, 5, 8, 12, 20, 25}, clamped to [min, max],
  ascending, duplicates dropped; slope 12.9 / far 385 gives exactly today's
  rungs (regression case in tst_controlutil)
- `CameraSource.focusSlope` (rw real, default 12.9) rebuilds the ladder on
  change; values <= 0 are ignored and keep the previous slope
- `CameraSource.focusDioptres` (rw real): reading gives
  (focusPosition - focusDefault) / focusSlope, >= 0; writing moves the lens
  to far + slope x D clamped to the lens range; no-op without a lens or
  without a focus default ([[us030]] AC 7 groundwork)
- `ctest --test-dir build` passes on the phone
#### edge_cases
- slope <= 0 or NaN; far below lens minimum; ladder fully clamped to one
  rung; writing negative or NaN dioptres (clamped to 0 / ignored); no lens
  (focusAvailable false); focusDefault -1 (no machine default)
#### test_plan
- tst_controlutil: `ladderUltrawideUnchanged` (12.9 / 385 equals the old
  constant-based rungs), `ladderWide` (270 / 250 within 0..4095),
  `ladderClampsAtMax`, `ladderRejectsBadSlope`, `dioptresRoundTrip`
  (far + slope x D back to D within one code), `dioptresClampNegative`
- a mutant that keeps the 12.9 constant must fail `ladderWide`
#### sre
granularity 5h ok; implementability: files + signatures named; success
criteria 4, measurable, tied to us030 AC 7; deps none; safety: clamps, no
throw (plan anti-patterns); edge cases listed; red flags none; tests name
scenarios and include a mutant check.

### Task 2: Value setters and colour gains in the module
#### type
feature
#### effort
6h
#### depends
none
#### files_touched
libcamera-qml: src/controlutil.h, src/controlutil.cpp, src/camerasource.h,
src/camerasource.cpp, tests/tst_controlutil.cpp,
tests/exposure_smoke.qml, tests/exposure_smoke.sh, README.md
#### success_criteria
- `setExposureTime(us)` switches to manual exposure at that time, clamped
  to the camera's ExposureTime range; `exposureTime` reports the applied
  value from metadata within 5 frames; `autoExposure` reads false
- `setIso(iso)`: 0 = auto ISO; otherwise the nearest ISO rung whose gain the
  camera supports (same rule as `isoStep`, new pure helper `isoClamp`);
  `iso` reports the applied rung
- `colourGains` (ro, [r, b]) mirrors the last free-running AWB gains the
  module already keeps; `setColourGains(r, b)` stores them as the carried
  gains so the next configure locks them for kAwbHoldFrames and then
  releases AWB (existing lcq::awbPlan path; no new state machine)
- exposure_smoke.sh on the phone: set 20000 us -> metadata 20000 +- 1 line;
  set ISO 800 on the ultrawide -> gain 8.0; setColourGains(1.5, 1.2) +
  restart -> first frames report those gains, AWB free after the hold
  ([[us030]] AC 7)
#### edge_cases
- exposure above the camera maximum / below minimum (clamped); ISO beyond
  the gain range (nearest supported rung, or auto when none); gains <= 0 or
  NaN (ignored); setters while stopped (stored, applied on start: exposure
  is applied after the start's reset, see Task 4); setters while capturing
  a still (stored, applied after the still)
#### test_plan
- tst_controlutil: `isoClampInsideRange`, `isoClampAboveMax`,
  `isoClampNoManualGain` (returns 0)
- exposure_smoke.sh scenarios as listed in success_criteria, each
  asserting on frame metadata, not on property echo
#### sre
granularity 6h ok; implementability: reuses named existing paths
(awbPlan, isoStep, resetExposure); 4 measurable criteria tied to us030 AC
7; deps none; safety: clamps, ignore invalid input; edge cases listed; no
placeholders; tests assert on metadata (non-tautological).
