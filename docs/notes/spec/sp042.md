# Spec [[cat002]] [[board]]

## solves
[[us026]]

## problem
[[pn001|developer]] wants the phone camera ([[ft019]], LibCamera module,
shipped by [[sp041]]) to save real stills: v1 saves the newest 1280x720
preview frame, while the s5kjn1 back sensor delivers 4080x3072 natively
(2x2-binned; up to 8152x6144 remosaic). Acceptance in [[us026]] (approved
2026-11-22): upright 3072x4080 JPEG, preview paused with a `capturing`
indicator and resumed automatically, <= 6 s per shot, fallback to the
preview frame (with `error`) when no larger still size exists.

Measured constraints (2026-11-22, libcamera 0.8.0):
- the `simple` pipeline refuses a viewfinder + still pair ("Failed to get
  default stream configuration"): a still means stop -> reconfigure the
  single stream (StillCapture, 4080x3072 ABGR8888) -> let AE settle over a
  few frames -> grab -> reconfigure back to the 1280x720 viewfinder;
- `cam` grabbed 10 frames at 4080x3072 in ~6 s including start-up, so one
  settled still should land in ~3-4 s;
- autofocus is impossible for now: no Af/LensPosition controls and no
  lens-focus link on the s5kjn1 node (out of scope, us026 AC).

Touches [[ft019]]'s api_surface (`capture` semantics, new `capturing`,
maybe `stillSize` read-only) and its consumers: quickshell CameraOverlay
(indicator, [[ft009]] hint strip unchanged), the standalone app,
[[ft007]] clipboard copy of a 12.5 MP PNG (size/time to check). Category
[[cat002]]; bound by [[adr0014]] (no retry loops: a failed reconfigure
sets `error`, no automatic re-open loop) and [[adr0040]] (the camera
layer's keys already exit; a slow snap must not need the layer held).

## solution
Story-backed extension of [[ft019]] (no new feature; [[cat002]]). Inside
the LibCamera module's `CameraSource`, `capture(path)` gains a still path
for cameras whose largest still size exceeds the viewfinder:

1. set `capturing = true` (new read-only property) and stop the viewfinder;
   the QVideoSink keeps the last frame, so the preview freezes on screen;
2. reconfigure the single stream as StillCapture at 4080x3072 (the
   s5kjn1's native binned mode; the `simple` pipeline allows one stream);
3. drop N settle frames for AE (N set by the PoC, start 4), copy the next;
4. reconfigure back to the 1280x720 viewfinder and resume streaming;
5. rotate upright, save JPEG on the pool thread, emit `captured(path, ok)`,
   `capturing = false`.

A camera without a larger still size keeps today's preview-frame path and
notes it in `error`. Any failed reconfigure sets `error`, restores the
viewfinder once, never loops ([[adr0014]]). Consumers: CameraOverlay and
the standalone app show "capturing…" while `capturing`; the hotkeyd camera
layer is unchanged — its keys already exit on press ([[adr0040]], [[ft011]]);
the clipboard copy stays image/png for [[ft007]].

Trade-offs: a 3-4 s preview pause per shot instead of a parallel still
stream (unsupported by the pipeline); no autofocus (no lens driver).
Unproven: the <= 6 s budget (settle frames + two reconfigures + 12.5 MP
JPEG, then the PNG for the clipboard) — confidence gate below.
