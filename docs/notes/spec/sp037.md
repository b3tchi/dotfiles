# Spec [[cat001]] [[board]]

## extends
[[ft013]]

## problem

[[ft014]] is `accepted` and live-proven: the `pi-worker` CLI ships 22 verbs,
hosts named workers as windows in the linked tmux project group, and carries
peer-addressed envelopes with a typed result. [[ft013]] was written before any
of that existed, so its consumers still hedge against it. `plan-scrum-master`
returns `unsupported-runtime: plan-scrum-master multi-worker dispatch requires
[[sp028]] or another Pi adapter` — but [[sp028]] shipped. The transport is
ready and the lifecycle refuses to use it.

Two problems, one spec, because the second is why the first keeps coming back.

**1. Pi is conditional where it should be a path.** The Pi branch across
`plan-scrum-master`, `plan-supervised`, `work-do`, `meta-patterns/runtime-adapter.md`
and `meta-bootstrap` is written as deferral — "available once [[ft014]] is
installed", "defer multi-worker retry to [[sp028]]". Two contract tests
(`plan-scrum-master-workspace/test_orchestration_runtime_contract.py`,
`lifecycle-contract-workspace/test_runtime_selection_contract.py`) assert that
hedging as the contract, so the text cannot move without them. Under Pi the
pipeline should run at full parallelism — the same concurrency limits, waves
and modes the Claude branch has — because the bus is peer-addressed and
bounded-block already. `unsupported-runtime` keeps exactly one real case:
neither `AI_AGENT=pi` nor a Claude native surface.

**2. The process is told twice, so it drifts.** Runtime leaks into the prose.
`plan-scrum-master/SKILL.md` carries "Claude native branch only:" paragraphs at
the dispatch, reviewer and retry steps, each with a Pi rider bolted on;
`work-do` and `plan-supervised` repeat the shape; the Pi verb table lives in
`plan-scrum-master` rather than in the shared contract. [[ft013]] promised that
a new runtime branch is added in one place. That is currently true of runtime
*selection* only, not of the operations, so every skill body is a second place.

The refresh splits the two parts the lifecycle actually has:

- **Process, single.** Each skill body describes the pipeline once in abstract
  operations — dispatch, send work, await, reject/resume, accept and clean,
  tear down, inspect — with no tool or CLI name in it. Stage order, gates, the
  two-strikes rule `work-audit` owns, the completion envelope, bd-as-contract:
  stated once, true on both runtimes.
- **Implementation, one table per runtime.** `meta-patterns/runtime-adapter.md`
  grows from runtime selection into the binding: one row per abstract
  operation, one column per runtime — Claude native (`Agent`, `SendMessage`,
  `TaskStop`, `ListAgents`) and Pi (`pi-worker spawn|send|wait|resume|accept|
  stop|workers`). Skills cite a row name and never spell a command. A third
  runtime becomes one column and zero skill edits.

Claude Code keeps working, unchanged and provably so: the two contract tests
are rewritten to assert the pair — native dispatch semantics intact, Pi branch
concrete — rather than the hedge. A third assertion, that no skill body names a
runtime-specific tool outside the binding table, is what stops the drift
returning.

Proof is a reusable pipeline smoke, not a one-off run. A template mints a fresh
bd task per invocation (write `docs/notes/lab/smoke-<ts>.md` with a fixed
header); the run is real — commit on `bd-<id>.<N>`, `work-audit` closes,
`work-merge` lands and reaps — and a checker asserts branch name, landed file,
closed task with audit evidence, gone worktree, and a typed bus result per
[[adr0027]]. The branch-name assertion earns its place: `dotfiles-41fr`, the
existing hand-run sample, landed on `wk-timestamp-file.0` instead of its bd
branch and the deviation was only caught by reading the notes. The checker
takes the runtime as an argument and runs identically on both branches, so it
is the compat regression rather than a Pi-only test.

Binding decisions the refresh must respect: [[adr0028]] — tmux displays
workers and never transports messages, so nothing in the process may read a
pane; [[adr0031]] — the transport interprets nothing, so no lifecycle
vocabulary may be pushed back into [[ft014]]; [[adr0027]] — completion is a
typed field, never prose; [[adr0024]] and [[adr0025]] — Pi worker liveness
comes from process state, `bd` and bus envelopes, never from Claude agent
records; [[adr0017]] — only a component's own evidence may trigger automatic
recovery, which bounds what the orchestrator may reap; [[adr0033]] — a bus
breaking change is a hard cutover with a protocol bump, not a compatibility
shim. [[im002]] remains the tmux dispatch shape to reuse rather than bypass.

Out of scope. [[ft016]] and the agent-monitor display are untouched.
[[ft014]]'s mutual `wait --block` deadlock stays a recorded known limit — the
60s bound is the entire mitigation — because full parallelism inherits it
rather than creating it. Reconciling the Pi bridge against a live Pi 0.84.4 is
already filed as `dotfiles-ea0g` and stays separate. No new `ft###`, and no
`us###` or `im###` lineage is invented: [[ft013]] was minted by [[sp027]] as a
feature-add, so this is a feature-refresh of an accepted Feature.

## solution

Refresh [[ft013]] in place. No new `ft###` is minted and [[ft014]] is not
touched: the transport already provides every operation the lifecycle needs,
and [[adr0031]] forbids pushing lifecycle vocabulary back into it. Consuming
`pi-worker` as a CLI is consumption, not bus code, so [[ft013]]'s rule that the
only thing it contributes to a Pi session is its own extension still holds.

**The binding table becomes the contract.** `meta-patterns/runtime-adapter.md`
keeps its runtime-selection section verbatim and gains an operation binding:
one row per abstract operation — dispatch, send work, await, reject/resume,
accept and clean, tear down, inspect — and one column per runtime. The Pi verbs
that live in `plan-scrum-master/SKILL.md` today move into that column
(`pi-worker spawn|send|wait|resume|accept|stop|workers`), alongside the Claude
column (`Agent`, the dispatch payload, the completion notification,
`SendMessage`, the work-merge worktree sweep, `TaskStop`, `ListAgents`). A
third runtime becomes one more column and zero skill edits, which is what
[[ft013]] promised and what is currently true of selection only.

**Skill bodies go runtime-neutral.** `plan-scrum-master`, `plan-supervised`,
`work-do`, `plan-scrum-master/references/architecture.md` and `meta-bootstrap`
lose every "Claude native branch only:" paragraph and the Pi rider bolted onto
it. Each delegated step names an operation and cites its row; no skill body
spells a tool or CLI verb. `work-audit` keeps counting rejections on the bd
task, and [[adr0027]]'s typed completion stays a process rule rather than a
transport one.

**Pi runs at parity.** The Pi branch honours the same concurrency limits, waves
and modes as the Claude branch — the bus is peer-addressed and its block is
bounded, so nothing structural stands in the way. `unsupported-runtime` narrows
to its one true case: neither `AI_AGENT=pi` nor a Claude native surface. Worker
liveness reads process state, `bd`, and bus envelopes per [[adr0024]] and
[[adr0025]], never a tmux pane per [[adr0028]]; automatic reaping stays bounded
by [[adr0017]], so the orchestrator may only act on a worker's own evidence.

**Both runtimes asserted, not assumed.** `lifecycle-contract-workspace/test_runtime_selection_contract.py`
and `plan-scrum-master-workspace/test_orchestration_runtime_contract.py` are
rewritten from asserting the hedge to asserting the pair: selection order
intact, native dispatch semantics unchanged, every operation row carrying a
filled Pi cell, and `unsupported-runtime` raised only on the true miss. A
fourth assertion — that no skill body names a runtime-specific tool or verb
outside the binding table — is the anti-drift mechanism, because the drift this
spec removes is exactly what an unasserted convention grows back.

**A reusable smoke proves the pipeline, not a single run.** A nushell harness
under `tests/` ([[adr0001]]) mints a fresh bd task per invocation — write a
lab smoke file with a fixed header — and drives the real pipeline end to end.
Its checker asserts the branch was `bd-<id>.<N>`, the file landed on base, the
task closed with audit evidence, the worktree was reaped, and the bus carries a
typed result per [[adr0027]]. The branch assertion earns its place from
`dotfiles-41fr`, whose hand-run landed on `wk-timestamp-file.0` and was caught
only by reading notes afterwards. The runtime is an argument, so one checker
covers both branches and doubles as the Claude Code compatibility regression.
It is opt-in rather than CI: a real run spends model tokens.

**Trade-offs taken.** Acting on a delegated step now costs one extra read of
`runtime-adapter.md`, accepted because it is precisely what turns a third
runtime into a column instead of an edit sweep across five files. Full
parallelism under Pi inherits [[ft014]]'s mutual `wait --block` deadlock, whose
entire mitigation is the 60s bound; this spec records it rather than fixing it.
The spec stays in [[cat001]], and [[im002]] remains the tmux dispatch shape
reused rather than bypassed.
