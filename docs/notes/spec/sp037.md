# Spec [[cat001]] [[board]]

## extends
[[ft013]]

## problem

[[ft014]] is `accepted` and live-proven: the `pi-worker` CLI ships 22 verbs,
hosts named workers as windows in the linked tmux project group, and carries
peer-addressed envelopes with a typed result. [[ft013]] was written before any
of that existed, so its consumers still hedge against it. `plan-scrum-master`
returns `unsupported-runtime: plan-scrum-master multi-worker dispatch requires
[[sp028]] or another Pi adapter` — but [[sp028]] shipped. The transport is
ready and the lifecycle refuses to use it.

Two problems, one spec, because the second is why the first keeps coming back.

**1. Pi is conditional where it should be a path.** The Pi branch across
`plan-scrum-master`, `plan-supervised`, `work-do`, `meta-patterns/runtime-adapter.md`
and `meta-bootstrap` is written as deferral — "available once [[ft014]] is
installed", "defer multi-worker retry to [[sp028]]". Two contract tests
(`plan-scrum-master-workspace/test_orchestration_runtime_contract.py`,
`lifecycle-contract-workspace/test_runtime_selection_contract.py`) assert that
hedging as the contract, so the text cannot move without them. Under Pi the
pipeline should run at full parallelism — the same concurrency limits, waves
and modes the Claude branch has — because the bus is peer-addressed and
bounded-block already. `unsupported-runtime` keeps exactly one real case:
neither `AI_AGENT=pi` nor a Claude native surface.

**2. The process is told twice, so it drifts.** Runtime leaks into the prose.
`plan-scrum-master/SKILL.md` carries "Claude native branch only:" paragraphs at
the dispatch, reviewer and retry steps, each with a Pi rider bolted on;
`work-do` and `plan-supervised` repeat the shape; the Pi verb table lives in
`plan-scrum-master` rather than in the shared contract. [[ft013]] promised that
a new runtime branch is added in one place. That is currently true of runtime
*selection* only, not of the operations, so every skill body is a second place.

The refresh splits the two parts the lifecycle actually has:

- **Process, single.** Each skill body describes the pipeline once in abstract
  operations — dispatch, send work, await, reject/resume, accept and clean,
  tear down, inspect — with no tool or CLI name in it. Stage order, gates, the
  two-strikes rule `work-audit` owns, the completion envelope, bd-as-contract:
  stated once, true on both runtimes.
- **Implementation, one table per runtime.** `meta-patterns/runtime-adapter.md`
  grows from runtime selection into the binding: one row per abstract
  operation, one column per runtime — Claude native (`Agent`, `SendMessage`,
  `TaskStop`, `ListAgents`) and Pi (`pi-worker spawn|send|wait|resume|accept|
  stop|workers`). Skills cite a row name and never spell a command. A third
  runtime becomes one column and zero skill edits.

Claude Code keeps working, unchanged and provably so: the two contract tests
are rewritten to assert the pair — native dispatch semantics intact, Pi branch
concrete — rather than the hedge. A third assertion, that no skill body names a
runtime-specific tool outside the binding table, is what stops the drift
returning.

Proof is a reusable pipeline smoke, not a one-off run. A template mints a fresh
bd task per invocation (write `docs/notes/lab/smoke-<ts>.md` with a fixed
header); the run is real — commit on `bd-<id>.<N>`, `work-audit` closes,
`work-merge` lands and reaps — and a checker asserts branch name, landed file,
closed task with audit evidence, gone worktree, and a typed bus result per
[[adr0027]]. The branch-name assertion earns its place: `dotfiles-41fr`, the
existing hand-run sample, landed on `wk-timestamp-file.0` instead of its bd
branch and the deviation was only caught by reading the notes. The checker
takes the runtime as an argument and runs identically on both branches, so it
is the compat regression rather than a Pi-only test.

Binding decisions the refresh must respect: [[adr0028]] — tmux displays
workers and never transports messages, so nothing in the process may read a
pane; [[adr0031]] — the transport interprets nothing, so no lifecycle
vocabulary may be pushed back into [[ft014]]; [[adr0027]] — completion is a
typed field, never prose; [[adr0024]] and [[adr0025]] — Pi worker liveness
comes from process state, `bd` and bus envelopes, never from Claude agent
records; [[adr0017]] — only a component's own evidence may trigger automatic
recovery, which bounds what the orchestrator may reap; [[adr0033]] — a bus
breaking change is a hard cutover with a protocol bump, not a compatibility
shim. [[im002]] remains the tmux dispatch shape to reuse rather than bypass.

Out of scope. [[ft016]] and the agent-monitor display are untouched.
[[ft014]]'s mutual `wait --block` deadlock stays a recorded known limit — the
60s bound is the entire mitigation — because full parallelism inherits it
rather than creating it. Reconciling the Pi bridge against a live Pi 0.84.4 is
already filed as `dotfiles-ea0g` and stays separate. No new `ft###`, and no
`us###` or `im###` lineage is invented: [[ft013]] was minted by [[sp027]] as a
feature-add, so this is a feature-refresh of an accepted Feature.

## solution

Refresh [[ft013]] in place. No new `ft###` is minted and [[ft014]] is not
touched: the transport already provides every operation the lifecycle needs,
and [[adr0031]] forbids pushing lifecycle vocabulary back into it. Consuming
`pi-worker` as a CLI is consumption, not bus code, so [[ft013]]'s rule that the
only thing it contributes to a Pi session is its own extension still holds.

**The binding table becomes the contract.** `meta-patterns/runtime-adapter.md`
keeps its runtime-selection section verbatim and gains an operation binding:
one row per abstract operation — dispatch, send work, await, reject/resume,
accept and clean, tear down, inspect — and one column per runtime. The Pi verbs
that live in `plan-scrum-master/SKILL.md` today move into that column
(`pi-worker spawn|send|wait|resume|accept|stop|workers`), alongside the Claude
column (`Agent`, the dispatch payload, the completion notification,
`SendMessage`, the work-merge worktree sweep, `TaskStop`, `ListAgents`). A
third runtime becomes one more column and zero skill edits, which is what
[[ft013]] promised and what is currently true of selection only.

**Skill bodies go runtime-neutral.** `plan-scrum-master`, `plan-supervised`,
`work-do`, `plan-scrum-master/references/architecture.md` and `meta-bootstrap`
lose every "Claude native branch only:" paragraph and the Pi rider bolted onto
it. Each delegated step names an operation and cites its row; no skill body
spells a tool or CLI verb. `work-audit` keeps counting rejections on the bd
task, and [[adr0027]]'s typed completion stays a process rule rather than a
transport one.

**Pi runs at parity.** The Pi branch honours the same concurrency limits, waves
and modes as the Claude branch — the bus is peer-addressed and its block is
bounded, so nothing structural stands in the way. `unsupported-runtime` narrows
to its one true case: neither `AI_AGENT=pi` nor a Claude native surface. Worker
liveness reads process state, `bd`, and bus envelopes per [[adr0024]] and
[[adr0025]], never a tmux pane per [[adr0028]]; automatic reaping stays bounded
by [[adr0017]], so the orchestrator may only act on a worker's own evidence.

**Both runtimes asserted, not assumed.** `lifecycle-contract-workspace/test_runtime_selection_contract.py`
and `plan-scrum-master-workspace/test_orchestration_runtime_contract.py` are
rewritten from asserting the hedge to asserting the pair: selection order
intact, native dispatch semantics unchanged, every operation row carrying a
filled Pi cell, and `unsupported-runtime` raised only on the true miss. A
fourth assertion — that no skill body names a runtime-specific tool or verb
outside the binding table — is the anti-drift mechanism, because the drift this
spec removes is exactly what an unasserted convention grows back.

**A reusable smoke proves the pipeline, not a single run.** A nushell harness
under `tests/` ([[adr0001]]) mints a fresh bd task per invocation — write a
lab smoke file with a fixed header — and drives the real pipeline end to end.
Its checker asserts the branch was `bd-<id>.<N>`, the file landed on base, the
task closed with audit evidence, the worktree was reaped, and the bus carries a
typed result per [[adr0027]]. The branch assertion earns its place from
`dotfiles-41fr`, whose hand-run landed on `wk-timestamp-file.0` and was caught
only by reading notes afterwards. The runtime is an argument, so one checker
covers both branches and doubles as the Claude Code compatibility regression.
It is opt-in rather than CI: a real run spends model tokens.

**Trade-offs taken.** Acting on a delegated step now costs one extra read of
`runtime-adapter.md`, accepted because it is precisely what turns a third
runtime into a column instead of an edit sweep across five files. Full
parallelism under Pi inherits [[ft014]]'s mutual `wait --block` deadlock, whose
entire mitigation is the 60s bound; this spec records it rather than fixing it.
The spec stays in [[cat001]], and [[im002]] remains the tmux dispatch shape
reused rather than bypassed.

### conventions

- **One binding, cited by name.** `meta-patterns/runtime-adapter.md`'s
  `## operation binding` is the only place a runtime-specific tool or CLI verb
  appears in the whole plugin. Every skill body names an operation — *dispatch*,
  *send work*, *await*, *reject/resume*, *accept and clean*, *tear down*,
  *inspect* — and cites the row. A third runtime is a third column.
- **Operation names are the vocabulary.** The seven names above are fixed by
  T1 and used verbatim downstream; a skill that invents an eighth is adding an
  operation the binding cannot answer, which is a T1 change, not a body change.
- **Pi cells are runnable as written.** `spawn` carries `--isolation` (it has
  no default and refuses by name without it) and `--role --subject --skill`;
  `$RUN` is the `run` field of `spawn`'s JSON, and the binding says so. A cell
  that needs a flag the reader has to guess is a broken row.
- **Process is stated once.** Stage order, gates, the two-strikes rule
  `work-audit` counts on the bd task, the completion envelope, bd-as-contract:
  each lives in exactly one skill body and is true on both runtimes.
- **Durable state is unchanged.** `akm`, `bd`, Git. No lifecycle state moves
  into runtime process metadata, and none moves into the bus.

### anti-patterns

- **Do not leave a tool name in a skill body "just as an example."** That is
  how the current drift started: an example became a branch, a branch grew a
  rider, and the rider became a contract test. T4's lint exists for this line.
- **Do not make the lint pass vacuously.** A check that only asserts "no
  forbidden string present" goes green the moment the bodies are clean and
  stays green if the checker itself breaks. T4 carries negative fixtures that
  must be flagged, or it is not a test.
- **Do not let the smoke be the only test of the smoke.** A real run costs
  model tokens, so it will be run rarely; the checker's own assertions are unit
  tested against fixture states in T5.
- **Do not read a tmux pane for state.** [[adr0028]]: tmux displays workers and
  never transports messages. Liveness comes from process state, `bd`, and bus
  envelopes per [[adr0024]] and [[adr0025]].
- **Do not reap on someone else's evidence.** [[adr0017]] bounds automatic
  recovery to a component's own evidence about itself; the orchestrator may
  stop and clean what it spawned, and nothing else.
- **Do not teach the transport a lifecycle word.** No stage name, no role
  vocabulary, no payload shape gating in `pi-worker` — [[adr0031]], and the
  reason [[sp029]] moved that policy here in the first place.

### known limitations

- Full parallelism under Pi inherits [[ft014]]'s mutual `wait --block`
  deadlock: two agents each blocking on the other are saved only by the 60s
  bound. This spec records it; fixing it is [[ft014]]'s side of the line.
- A sender still learns of a lost message only by timing out — the bus has no
  acknowledgement from the agent. The orchestrator's retry is therefore
  timeout-shaped, not ack-shaped.
- The live proof in T6 spends model tokens and needs a human to run it; it is
  opt-in and not part of any CI gate.
- Reconciling the Pi bridge against a live Pi 0.84.4 stays out of scope and
  filed as `dotfiles-ea0g`.

- `test_lint_flags_a_bare_claude_tool` — temp fixture containing `SendMessage`;

- `test_lint_flags_a_bare_pi_verb` — temp fixture containing `pi-worker wait`.

  instruction; the [[adr0028]] half.

- `test_lint_exempts_the_binding_file` — asserts the real

- `test_lint_allows_bd_commands` — asserts `bd show <id>` is not a finding.
- `test_lint_walks_files_not_a_list` — writes a new skill dir into a temp tree
  and asserts the walk finds it; catches the hardcoded-list regression.
- The real skill tree runs through the lint as the live assertion that Tasks 2
  and 3 actually landed clean.

### Task 5: a reusable pipeline smoke, and a checker that is tested without running it

#### type
feature

#### effort
6h

#### depends
Task 1

#### files_touched
- `tests/infinifu/lifecycle-smoke.nu`
- `tests/infinifu/smoke-cases.nu`
- `tests/infinifu/run-tests.nu`

#### success_criteria
- `lifecycle-smoke.nu` mints a FRESH bd task per invocation whose work is to
  write `docs/notes/lab/smoke-<ts>.md` with a fixed header line, then drives
  the pipeline through dispatch, work-do, work-audit and work-merge.
- Its checker asserts five things and names which one failed: the branch was
  `bd-<id>.<N>`; the smoke file landed on base with the header; the bd task is
  closed and carries audit evidence in notes; the worktree and branch are gone;
  the bus carries a typed result with `status`, `summary` and `validation`
  ([[adr0027]]) rather than prose.
- The runtime is an argument, and the same invocation shape works for both, so
  one checker covers Claude and Pi.
- The checker is a pure function over gathered state, so `smoke-cases.nu` can
  exercise it without spawning anything.
- `run-tests.nu` runs `smoke-cases.nu` and matches the shape of
  `tests/pi-worker/run-tests.nu`.
- Nothing in `tests/infinifu/` writes to `claude/marketplace/plugins/pi-workers/`.

#### edge_cases
- A run that fails midway must leave a diagnosable trail — a half-finished run
  is the normal case while the pipeline is new, so the checker reports every
  failed assertion, not the first.
- The smoke file's timestamp name must not collide across two runs in the same
  second, and a leftover file from a previous failed run must not make a later
  run pass.
- `dotfiles-41fr` landed on `wk-timestamp-file.0` instead of its bd branch: the
  branch assertion must compare against the task's own id, not a pattern that
  any `.0` suffix satisfies.
- A worker that never reports leaves the run blocked at the 60s bound; the
  smoke must time out with the blocked worker named, not hang.
- The smoke must not require a human to answer anything, or it cannot be rerun
  unattended on the Claude branch.

#### test_plan
- `smoke-cases.nu` drives the checker over fixture states, one per failure mode
  plus the passing one: correct run (all five pass); wrong branch
  (`wk-timestamp-file.0` — the `dotfiles-41fr` shape verbatim); task left
  `in_progress`; worktree still present; result whose `summary` is prose with
  no `validation` field. Each asserts the checker names THAT failure and does
  not report the others.
- `test_checker_reports_every_failure_not_the_first` — a fixture failing three
  assertions at once; asserts all three are named.
- `test_stale_smoke_file_does_not_satisfy_a_later_run` — a fixture where a
  previous run's file exists but this run's does not.
- `test_branch_assertion_binds_to_the_task_id` — asserts a branch named
  `bd-other.0` fails even though it matches the bd-branch shape.
- The live run itself is Task 6; nothing here spends model tokens.

#### sre
| # | category | verdict |
|---|---|---|
| 1 | granularity | 6h; a harness plus a pure checker plus its cases |
| 2 | implementability | exact paths, exact five assertions, exact fixture list; the `tests/pi-worker/` suite is the shape to copy |
| 3 | success criteria | 6 measurable; the pure-checker criterion is what makes the rest testable |
| 4 | dependencies | Task 1 — the smoke drives operations by their binding rows |
| 5 | safety | the no-write-to-pi-workers criterion keeps [[adr0031]] structural; the timeout criterion keeps a blocked worker from hanging a suite |
| 6 | edge cases | 5; the stale-file and collide cases are what make a rerun trustworthy |
| 7 | red flags | none |
| 8 | test meaningfulness | the fixture set is derived from a real failure (`dotfiles-41fr`'s wrong branch), and the report-every-failure test targets the specific way a five-assertion checker degrades into a one-assertion one |

### Task 6: run the smoke on both runtimes and record what it found

#### type
verification

#### effort
3h

#### depends
Task 4, Task 5

#### files_touched
- none (evidence lands in bd notes)

#### success_criteria
- `lifecycle-smoke.nu` is run once under Pi and once under the Claude native
  branch; both runs are driven end to end without hand-editing state.
- Each run's five checker assertions are recorded verbatim in the task's bd
  notes, pass or fail, along with the bd id the run minted.
- Any divergence between the two runtimes is recorded as a named mismatch with
  the operation row it belongs to — a divergence is a finding, not a failure of
  this task.
- `run-lifecycle-validation.sh` passes, including the new lint.
- Findings that need code are filed as their own bd issues rather than fixed
  inside this task.

#### edge_cases
- A Pi run needs `pi` present and the project trusted; if it is unavailable the
  task reports blocked with the reason rather than claiming a pass from the
  Claude run alone.
- A run that exposes a genuine pipeline defect ends with a filed issue and a
  recorded failure — that is a successful task, since the smoke is a detector.
- Leftover smoke files and any worker window the run did not reap are cleaned
  only if this run spawned them ([[adr0017]]).
- The two runs must mint separate bd tasks; reusing one would hide a
  runtime-specific close-path defect.

#### test_plan
- The smoke IS the test; this task runs it. Evidence is the recorded assertion
  output from both runtimes plus the `run-lifecycle-validation.sh` result.
- A reviewer reproduces by rerunning `lifecycle-smoke.nu` with the runtime
  argument and comparing against the recorded output.

#### sre
| # | category | verdict |
|---|---|---|
| 1 | granularity | 3h of supervised running, no authoring |
| 2 | implementability | one command per runtime; the checker reports what to record |
| 3 | success criteria | 5 measurable; "divergence is a finding" prevents the task being gamed by only running the easy branch |
| 4 | dependencies | Tasks 4 and 5 — the lint and the smoke must both exist |
| 5 | safety | the reap rule is restated because a live run is exactly where an agent is tempted to clean up a window it did not spawn |
| 6 | edge cases | 4; the unavailable-Pi case has an explicit blocked outcome rather than a silent single-runtime pass |
| 7 | red flags | none |
| 8 | test meaningfulness | this is the only task whose evidence comes from real workers doing real work; its value is precisely that it cannot be satisfied by a fixture |
