# Spec [[cat001]] [[board]]

## problem

kwi3 on KWin is replacing SXMO on Sway as the session on the phone's own
screen (nothing-spacewar, postmarketOS, DSI-1 1080x2400 at scale 1.6 =
675x1500 logical). The window manager's CODE is the kwi3 repo's half
(kwi3 sp015: `i3kwin`, the `kwi3keys` plugin, `kwi3-phone-session`). This
spec is the **dotfiles half**: everything that runs inside that session,
every binding, and one meta-package, `meta-phone-kwi3`, that installs the
WHOLE phone session - window manager included - so the phone is set up by
`rotz install meta-phone-kwi3` instead of by hand.

### What runs today, and what does not

Working on the phone screen (2026-10-28): hotkeyd `--input kwin` (phone
build), quickshell bar and overlay (`$mod+d`, `$mod+p`, `$mod+Tab`), foot.
Fixed on the way: `qs-session.sh`, `qs-clip.sh`, `qs-notif.sh` find the
session's quickshell through `quickshell list --all` - processes under the
phone's KWin are non-dumpable, so `/proc/<pid>/environ` is unreadable.

Gaps, each to be provided or dropped by name (Jan's call):

1. **Screenshots** - `Print`, `$mod+Print`, `$mod+Shift+Print`,
   `$mod+Shift+s` run `kwi3-shot` (KWin ScreenShot2) in `host_phone.go`;
   committed, not deployed. `kwi3-shot` itself sits in the kwi3 repo today
   and belongs here.
2. **Notifications** - the phone screen has its own D-Bus with no
   notification server; `$mod+n` opens an empty history.
3. **Clipboard** - the clip store is keyed on X `DISPLAY`; Wayland needs
   its own store (`wl-paste --watch`) and `wl-copy` for paste.
4. **Lock and blank** - `$mod+9` (blurlock) and `i3exit` are absent.
   Candidates: `swaylock` (KWin speaks ext-session-lock) and `swayidle`
   (ext-idle-notify).
5. **Mixer** - `$mod+Ctrl+m` runs `terminal -e alsamixer`; no `terminal`
   on the phone.
6. **Hardware buttons and gestures** - what power, volume and edge
   swipes do, once kwi3 delivers them (kwi3 sp015 gaps 3-4).
7. **Suspend and wake**, **calls and SMS** (ModemManager) - SXMO did both;
   nothing in the new session reacts to the modem.
8. **Bar status** - battery, signal, wifi modules on the phone.

### The meta-package

`meta-phone-kwi3` installs everything, not only the dotfiles' share (Jan,
2026-10-30: no split on the rotz side). It lists:

- the dots the session runs: fonts, foot, quickshell, hotkeyd, sxmo (kept
  installed as the fallback session);
- a dot for the **KWin host itself**, the phone's counterpart of `kwi3`
  (which builds the X11 host from a release tag): it clones kwi3 and runs
  its `i3kwin/install.sh --local` on the phone, which packages and
  installs the i3kwin KWin script, the `kwi3keys` plugin, hotkeyd (phone
  build), `krdp-launch.sh`, `kwi3-phone-session` and the helpers into
  `~/.local`. It builds on the phone (Jan, 2026-10-30), from the
  `kwin-host` branch until that merges - not a release tag like the X11
  dot, because nothing on `kwin-host` is tagged.

None of this installs on postmarketOS today:

- the dots' install commands branch on Arch/Manjaro only (`pacman`);
  packages there are `apk` and need `doas` with Jan's password, so every
  one is a hand-off;
- `install.sh` needs `node` (config.js syntax check, font family) and
  `go` (hotkeyd) on the machine that RUNS it - today the dev box, deploying
  over ssh with hotkeyd cross-compiled `GOARCH=arm64 -tags phone`. Built
  on the phone, both have to be there: `doas apk add nodejs go`, a
  hand-off to Jan;
- `install.sh --local` does not ship `kwi3-phone-session` or `kwi3-shot`
  yet (kwi3 sp015).

### Done means

1. `rotz install meta-phone-kwi3` on the phone links and installs
   everything the session runs (package installs handed to Jan via `doas`).
2. Gaps 1-8 are provided or dropped by name.
3. Together with kwi3 sp015, Jan uses the session as the phone's own for a
   stretch he names.
