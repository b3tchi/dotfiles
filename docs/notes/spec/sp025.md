# Spec [[cat001]] [[board]]

## problem
An agent running detached has no way to reach its operator. When it meets a
decision the task never stated — file format, schema shape, library, naming — it
picks a default and keeps going, and the operator finds out only from the
artifact. The decision was theirs and they never saw it.

[[poc019]] round 5 named the gap precisely: background agents have "no address
and no return path". It proposed solving that with tmux-session dispatch and a
`Stop`-hook message channel.

[[poc020]] invalidated most of that machinery. An agent that launches
`agent-inbox ask` as a `run_in_background` Bash call parks, and the **harness
itself wakes it** when the command exits — no `Stop` hook, no tmux nudge, no
monitor subagent, and no dependence on how the agent was launched. Measured at
49–73 tokens per exchange against ~15 100 through a monitor subagent. Multi-turn
needs no threading (one file per round; a 5-round negotiation converged), four
concurrent agents shared one store with no crosstalk, and the operator side is a
plain directory answered by editing files — no command required.

[[poc021]] settled the second half: the "mode" is a prompt fragment, not a hook.
The agent-asks case needs no hook at all, which retires the unsolved `PreToolUse`
scoping problem. But the instruction must be **hard** — enumerated decision
classes plus an explicit "absence of a stated preference is not permission to
pick a default". Soft guidance is *inert*: `CLAUDE.md` and
`--append-system-prompt` variants guessed identically to a no-instruction
control, while being able to recite the rule verbatim when asked. Knowing the
rule and following it are separate things, so compliance must be verified
behaviourally, never by asking the agent.

Mint one [[ft###]] — `agent-inbox` — comprising the CLI (agent verb `ask`,
operator conveniences, store layout) and the mode instruction that makes agents
reach for it. Category [[cat001]].

A first implementation already exists and is in use: `claude/agent-inbox/agent-inbox`
plus the `detached` agent definition, linked via `claude/dot.yaml`. It is not
lifecycle-hardened — no tests, and the items below are unresolved — so this spec
covers proving and hardening what is installed, not greenfield work.

Constraints and open items:

- Store follows [[adr0013]] — `$XDG_STATE_HOME`, mode 0700, prune-on-write. The
  current 14-day retention for answered exchanges is a guess, not a decision;
  these files quote whatever the agent had in context and the cap deserves its
  own ADR rather than a default chosen here.
- Python per [[adr0015]] (proofs and first MVPs). [[adr0003]] would govern a move
  to a compiled helper; nothing measured needs compiled speed, so it stays open.
- **All evidence is from haiku.** The hard-instruction finding is the load-bearing
  one and may not transfer across models in either direction. Verifying it on the
  models actually used is the first task, not a footnote.
- The **silent deadlock** is the only failure that loses work quietly: given a
  reply that is not an answer, an agent reasoned correctly then ended its turn
  with nothing pending and nothing running, leaving an inbox that reads as
  "finished". The prompt rule mitigates it; a reconciling detector
  (`claude agents --json` `idle` + no pending request) does not exist yet.
- Untested: whether background calls have any duration ceiling (longest real wait
  ~9 min), and behaviour across an hours-long idle gap.

Explicitly deferred, not dependencies:

- tmux-session dispatch from [[poc019]] — the inbox works on any agent regardless
  of how it was launched, so this stands or falls on nesting and addressing alone.
- Permission-prompt routing via the `PreToolUse` gate ([[poc021]]) — real, but it
  carries an unsolved scoping problem and covers harness-initiated prompts, a
  different case from an agent choosing to ask.
- Desktop notification on a new request, where [[ft010]] would fit. The operator
  currently discovers requests by looking.
