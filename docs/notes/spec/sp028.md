# Spec [[cat001]] [[board]]

## problem

Pi needs visible multi-agent execution for the Infinifu pipeline without
replacing Claude Code's native agent orchestration. The current
`plan-scrum-master` assumes Claude-native spawn, message, list, stop,
completion, and transcript-resume operations. Pi intentionally does not
provide built-in subagents, so merely loading the skill cannot execute the
full implementer-to-reviewer-to-merge pipeline.

The capability will provide a Pi runtime adapter that launches named Pi workers
as windows in the existing linked tmux project group. A worker window is shown
as `<worker-name>@<project>`, for example
`impl-dotfiles-7opn.1@dotfiles`; it is not a separate tmux session. Each worker
uses an isolated `bd-<id>.<N>` worktree, a stable Pi session ID, and tmux pane
metadata. `bd` remains authoritative for status and evidence, `akm` remains
authoritative for lifecycle artifacts, Git remains authoritative for source,
and Pi JSONL remains authoritative for conversation history.

[[im002]] is the existing tmux dispatch shape to reuse rather than bypass,
while [[ft001]] supplies existing project identity conventions. [[ft012]] and
its consumer [[im011]] remain Claude-specific census behavior. In particular,
[[adr0024]] and [[adr0025]] prevent this adapter from pretending that Claude
agent records describe Pi workers; Pi worker liveness must come from tmux,
`bd`, and adapter-owned metadata.

The deliverable is intended to mint a separate Feature for visible Pi worker
orchestration in [[cat001]]. Implementer and reviewer windows remain pinned
while active. Rejection resumes the stored Pi transcript. Successful task merge
closes its windows and cleans its worktree while retaining the Pi session ID
and bd evidence for later resume. Completion wakes the Pi scrum-master through
a tmux signal; `agent-inbox` remains the channel for human decisions rather
than becoming hidden orchestration state. Claude Code continues using its
native agent path without behavioral regression.

## solution

Provide [[ft014]] as the Pi worker-orchestration adapter layered on the shared
lifecycle contract in [[ft013]] and categorized under [[cat001]]. The Pi branch
of `plan-scrum-master` invokes a small worker CLI to create named windows in the
existing linked tmux project group, launch stable Pi sessions in isolated
`bd-<id>.<N>` worktrees, record role/task/session/run metadata as tmux pane
options, and signal completions through tmux. For `work-do`, `work-audit`, and
`work-merge` workers, the direct work-content payload is only the bd ticket ID.
The worker reads its contract via `bd show <id>` and inspects dependencies and
linked specs; the orchestrator does not copy or summarize the task body. Role,
session, worktree, and tmux values are transport metadata. This ticket-only
rule does not replace direct instructions plus `akm` document context for
non-work lifecycle stages. Implementer and reviewer windows appear as
`<role>-<bd-id>@<project>`, remain pinned while active or failed, and close only
after a successful task merge. Rejections resume the stored Pi transcript.
`bd`, `akm`, Git, and Pi JSONL retain authority for task, AKM, source, and
conversation state respectively.

The adapter reuses the linked-project tmux shape recorded by [[im002]] and
project conventions from [[ft001]], while Claude Code continues using native
agents. It does not fold Pi workers into the Claude-only census capability
[[ft012]] or its consumer [[im011]], preserving the boundaries established by
[[adr0024]] and [[adr0025]]. This favors visible, inspectable processes over a
hidden SDK worker pool, at the cost of a small tmux coordination CLI and an
explicit completion-signal protocol. [[poc022]] validates linked-group window
visibility, pane metadata, completion signalling, Pi session resume, and scoped
cleanup on Pi 0.84.4.

## plan

implementation spec. It intentionally has no source `us###` and no consumed
`im###` to finalize. [[im002]] is reused as an existing tmux dispatch shape,

### Conventions

- Worker UID: `<role>-<bd-id>-<run-id-short>`.
- Window display: tmux window name `<role>-<bd-id>`; the linked project group
  renders it as `<role>-<bd-id>@<project>`.
- Tmux pane options store reconstructable adapter metadata:
  `@infinifu_worker_uid`, `@infinifu_worker_role`,
  `@infinifu_worker_task`, `@infinifu_worker_session`,
  `@infinifu_worker_run`, `@infinifu_worker_status`, and
  `@infinifu_worker_pinned`.
- Durable authority remains outside the adapter: bd owns task status and
  evidence, AKM owns lifecycle artifacts through `akm`, Git owns source and
  worktrees, and Pi JSONL owns transcript history.
- For `work-do`, `work-audit`, and `work-merge`, the direct Pi worker prompt
  payload is exactly the bd task ID. Role, skill, cwd, tmux target, run ID, and
  session ID are transport metadata, not task-body summaries.

### Anti-patterns

- Do not call Claude `Agent`, `SendMessage`, `ListAgents`, or `TaskStop` in Pi
  mode.
- Do not report Pi workers through [[ft012]] or [[im011]]. Pi worker liveness
  is not Claude agent census data under [[adr0024]] and [[adr0025]].
- Do not duplicate bd task descriptions or AKM bodies into worker prompts.
- Do not treat missing or stale tmux metadata as proof of worker death; follow
  [[adr0017]] and surface `unknown` separately from `failed`.
- Do not close failed, blocked, or rejected worker windows automatically. Keep
  them pinned for inspection and resume.
- Do not hide human decisions in adapter metadata; use `agent-inbox` for human
  choices.
- Do not add a compiled helper unless a later ADR supersedes the current
  language constraints; [[adr0001]] and [[adr0002]] make nushell the default
  for this workflow-tooling CLI, and [[adr0003]] does not apply.

### Known limitations

- The adapter depends on tmux and on an existing linked project group.
- Worker process liveness is visible through tmux/process state, but semantic
  task state remains bd evidence.
- Resume depends on stable Pi session IDs and persisted Pi JSONL history.
- Headless tests can validate command construction, metadata, and cleanup with
  fakes; complete interactive visibility still needs a live tmux integration
  path.

### Binding sanity

- [[ft014]] is the feature implemented by this spec. The task list covers its
  `spawn`, `wait`, `status`, `resume`, and `stop` surface and its pane-option
  data model.
- [[ft013]] remains the runtime-neutral lifecycle contract. `AI_AGENT=pi`
  selects Pi behavior; Claude-native orchestration remains native.
- [[ft001]] supplies project naming conventions only; this spec does not widen
  the project registry.
- [[im002]] supplies the linked tmux project-group shape only; this feature-add
  spec does not back-link itself as an implementation of [[im002]].
- [[adr0001]], [[adr0002]], and [[adr0003]] bind the implementation language
  choice to nushell plus shell wrappers only where already justified.
- [[adr0017]] binds recovery semantics: unknown evidence stays unknown and must
  not trigger destructive cleanup.
- [[adr0024]] and [[adr0025]] bind the census boundary: Pi workers must not be
  folded into Claude-only agent records.

### Task 4: Implement wait/resume/stop and completion signalling

#### type

task

#### effort

7h

#### depends

Task 3

#### files_touched

- `claude/marketplace/plugins/infinifu/scripts/infinifu-worker.nu`
- `tests/infinifu-worker/wait-resume-stop-cases.nu`

#### success_criteria

- `infinifu-worker wait --run <run-id>` blocks until one worker records a
  terminal status and returns its UID, status, task, and session.
- Worker completion wakes the scrum-master through a tmux-visible signal or
  display-message protocol.
- `resume <uid>` reuses the stored Pi session ID and target worktree.
- `stop <uid>` terminates only the addressed worker pane/process and marks
  status `stopped` without deleting evidence.

#### edge_cases

- Worker pane exits before metadata is fully written.
- Multiple workers complete in the same polling interval.
- Resume is requested for an unknown or stale UID.
- Stop is requested for an already terminal worker.
- Failed or rejected workers remain pinned and visible.

#### test_plan

- `test_wait_returns_first_terminal_worker` catches run-level race bugs.
- `test_completion_sets_tmux_status` catches invisible completion.
- `test_resume_reuses_session_and_cwd` catches transcript loss.
- `test_stop_is_uid_scoped` catches killing the wrong pane.
