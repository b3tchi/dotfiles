# Spec [[cat002]] [[board]]

## solves
[[us027]]

## problem
[[pn001]] gets soft stills from the Nothing Phone (1)'s ultrawide camera
(s5kjn1). [[poc027]] found the lens parked near close focus; [[us026]] /
[[sp042]] list autofocus as out of scope because the s5kjn1 node has no
lens driver and no lens-focus link, so libcamera exposes no Af or
LensPosition controls.

Nobody knows yet whether the module even has a focus actuator (VCM).
Until that is known there is nothing to drive. So this spec is a
discovery: identify the actuator (chip, CCI/I2C bus and address) from
the live phone and from downstream sources (LineageOS / vendor device
tree), then either move the lens from userspace and show a sharper
still, or record a fixed-focus limitation.

Where the fix lands: most likely the hardware layer (kernel / device
tree of the postmarketOS port), not libcamera or the QML module. Driver
and DT work is a follow-up story, drafted only if a VCM is confirmed.

Category: [[cat002]] (display-platform; the camera stack's existing
home, same as [[ft019]] and [[im013]]). Candidate consumer: [[ft019]]
(libcamera-qml camera source) — gains either a known-limitation note
(no VCM) or, later, a focus control (follow-up). No ADR binds kernel
or hardware work; [[adr0040]] (hotkeyd camera layer untouched) still
applies to any QML-side change.

## solution
A two-source discovery spike, run as an idea-poc experiment, aimed
at the hardware layer (kernel / device tree) under [[cat002]]:

1. Downstream evidence first: search the Nothing Phone (1) downstream
   sources (LineageOS kernel + device tree, vendor camera module XML)
   for the s5kjn1 module's actuator — a `qcom,actuator` node or an
   `actuatorName` entry. This names the chip, CCI master and I2C
   address.
2. Live phone: check `media-ctl -p` / `v4l2-ctl` for any lens entity,
   then probe the s5kjn1's CCI bus with `i2cdetect` while the sensor
   streams (the VCM is only powered then). Probe the address the
   downstream sources name, not a blind full-bus scan.
3. If a VCM answers: drive it with raw `i2ctransfer` writes during
   streaming, capture stills at several lens positions, and compare
   100% crops with today's soft still ([[poc027]]).
4. Outcome lands in a poc### zettel. VCM present: draft a follow-up
   story (kernel driver + DT node + `lens-focus` link on the sensor, so
   libcamera sees the lens). No VCM: record a fixed-focus known
   limitation in [[ft019]].

Trade-offs: the raw-I2C lens move is throwaway proof, not product; a
mainline driver for the chip may not exist, which the follow-up story
would have to cost. No QML change here; [[adr0040]] applies only if a
later story exposes focus in [[ft019]].

Evidence: [[poc028]] validated the approach. The VCM is a DW98xx at
i2c-18 `0x0c` (id `0xf2`), unpowered because nothing consumes the DT's
`vreg_camu_vaf_1p8`; powered by hand, it moves the lens and pos ~100-250
sharpens a scene the parked lens blurs.
