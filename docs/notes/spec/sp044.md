# Spec [[cat002]] [[board]]

## solves
[[us028]]

## problem
[[pn001]] gets soft and badly exposed stills from the Nothing Phone (1)'s
ultrawide (s5kjn1). [[poc028]] (spike for [[us027]], [[sp043]]) found
why and what is needed:

- A Dongwoon DW98xx focus actuator sits at CCI `i2c-18` `0x0c` (id
  `0xf2`). Its supply `vreg_camu_vaf_1p8` (regulator-fixed, TLMM gpio 71)
  is already in the DT but has no consumer, so the VCM is never powered
  and the lens hangs loose. There is no actuator node and no
  `lens-focus` link on the sensor, so libcamera sees no lens.
- The kernel ships `dw9719.ko`, which lists `dongwoon,dw9800k`; the
  downstream part is a `dw9800w` (same family, register map to verify).
- Calibration by eye: `pos = 377 + 18.9 / metres` (infinity ~377, 1 m
  396, 0.3 m 440, 4 cm 840). The module EEPROM (`18-0051`, 0x92) holds
  564 / 396 / 408, which line up with the 0.1 m and 1 m codes.
- Manual exposure (`ae-enable=false`, exposure time, analogue gain) works
  live on the softISP pipeline; auto-exposure over-exposes bright scenes
  (no AE tuning for the s5kjn1). EV compensation is untested.

The problem stops at the kernel / libcamera layer: libcamera must see a
lens it can drive, the lens must default to a sharp far focus, and
exposure must be tunable through the camera API. Exposing focus or
exposure in the QML module ([[ft019]], which lists exposure controls as
a non-goal) is a later story. [[ft019]] and [[us026]]'s stills must keep
working. [[adr0040]] (hotkeyd camera layer untouched) binds any QML-side
change; none is planned here. Device-tree changes land through the
nothing-pmos dtb fix, outside this repo.

## solution
Hardware layer plus a thin default, under [[cat002]]. The changes land in
the nothing-pmos repo (dtb build, boot services), not in this one.

1. Device tree: a `.dts` patch through `spacewar-dtb-build.sh` (new
   nodes and phandles are beyond `fdtput`) adds `actuator@c` on the
   s5kjn1's CCI bus: `compatible = "dongwoon,dw9800k"`, `vdd-supply =
   <&vreg_camu_vaf_1p8>`, and `lens-focus = <&actuator>` on `camera@2d`.
   The mainline `dw9719` driver binds it (its dw9800k path skips the ID
   check and sets the SAC mode); runtime PM powers the VCM only while the
   lens subdev is in use, which covers the "motor off when idle" AC.
2. Default far focus: the driver's `FOCUS_ABSOLUTE` defaults to 0, which
   is beyond infinity (blurred). A boot-time hook sets `focus_absolute`
   on the lens subdev to the infinity code, 377 from [[poc028]] (later
   derived from the module EEPROM). The driver stores the value and
   ramps to it on every resume. Fallback if a camera start resets it: an
   out-of-tree `dw9719` patch with a DT default position, built through
   the nothing-pmos kmod path.
3. Camera API: libcamera's `CameraLens` maps the lens subdev to the
   `LensPosition` control. If the simple pipeline does not expose it or
   does not forward it, patch the simple pipeline (upstreamable).
4. Exposure: `ExposureTime` / `AnalogueGain` with AE off already work
   live ([[poc028]]); EV compensation needs verifying, and a softISP AGC
   fix only if it turns out to be a no-op.

No QML change: [[ft019]] keeps working as is and stays out of scope;
[[adr0040]] is untouched. Trade-offs: a fixed far default instead of
autofocus; the dw9800w is driven as a dw9800k (register map matched
in [[poc028]]); libcamera may need a patch. Unproven: whether the simple
pipeline exposes `LensPosition` and keeps the default across a camera
start, and whether EV compensation works — confidence gate below.

Evidence: [[poc029]] validated the DT actuator (driver binds, lens
moves, a pre-set focus survives camera start) and found three gaps:
no `LensPosition` from the simple pipeline, EV ignored by the softISP
AGC, and the VCM powered whenever a libcamera client holds the lens
open. Those need decisions before refinement.
