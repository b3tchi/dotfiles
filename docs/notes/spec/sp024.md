# Spec [[cat002]] [[cat001]] [[board]]

## solves
[[us019|programmable-global-keybinds]]

## problem
[[sp023]] migrated the `screenshot-drag` phase off i3 and onto a
hotkeyd External layer, but explicitly kept the aiming-phase `mode
"screenshot" {}` block in `i3/config.common` -- its own anti-pattern
list named deleting it a reviewer-reject-on-sight violation AT THE
TIME, because retiring it without a replacement would strand two
consumers: `quickshell/config/Bar.qml`'s hint-strip paint (subscribed
to i3's mode-change IPC for \"screenshot\") and
`quickshell/qs-focus-border.py`'s aiming-phase ring colour
(`COLOR_MODES = {'"'"'screenshot'"'"'}`, also i3-mode-IPC-driven).

That constraint no longer holds. Investigation for this delta found
both consumers already generalized past `screenshot-drag`-specific code
when [[im010]] shipped [[sp023]]:

- `Bar.qml:333`'s `activeMode` is `daemonLayer !== \"default\" ?
  daemonLayer : i3Mode` -- a GENERIC preference for any non-default
  hotkeyd layer over i3's own mode, not special-cased to
  `screenshot-drag`. If hotkeyd reports a `\"screenshot\"` layer, the bar
  paints it with ZERO code change.
- `qs-focus-border.py`'s `layer_colours_ring` already colours the ring
  for ANY non-default, non-suppressed hotkeyd layer (the general rule
  Task 6 built) -- `\"screenshot\"` would colour automatically the same
  way `\"nav\"`/`\"resize\"` already do.
- `qs-region.py`'s existing `screenshot` -> `screenshot-drag` transition
  on press already works unmodified: [[im010]]'s `SetExternalLayer`
  (Task 2) only refuses a request while a CHORD-entered layer is
  active, not an external-to-external transition. Two External layers
  handing off to each other was already a supported shape, just never
  exercised until now.

What still needs to move (files, not architecture): `config.go` gains a
second `External: true` declaration (`\"screenshot\"`); `qs-screenshot.sh`
calls `hotkeyd set-layer screenshot` instead of `i3-msg mode
screenshot`; the `mode \"screenshot\" {}` block and its Escape/q
bindsyms delete from `i3/config.common`; `qs-focus-border.py`'s now-dead
i3-mode-IPC half (`COLOR_MODES`, `i3_mode_colored`, the OR-fold logic
feeding `mode_colored`) retires, leaving `layer_colored` as the sole
source -- mirroring exactly how Task 6 retired `SUPPRESS_MODES` for
`screenshot-drag`.

The safety property that justified keeping this block
(\"[[dotfiles-ux1]] failure class\": Escape stays as a dead-overlay
fallback while the selector holds a real X grab) does not need
replacing, it dissolves: an External layer holds ZERO grabs and
shadows nothing ([[sp023]] plan decision 1), so i3 never actually
enters a real custom mode any more. There is no \"stuck mode\" for
Escape to unstick, because i3 stays in default the whole time -- the
same proof [[sp023]] already established for `screenshot-drag`, now
extended to the aiming phase.

Migration story: [[im010]] is already `status: accepted` (unlike
[[sp023]]'s entry-gate wait on ylmp.20, there is no blocking human-only
gate here -- the daemon and both consumer mechanisms are already live
and proven). Frame as a BODY REFRESH of [[im010]]'s `api_surface`
(second `External` layer) and of [[ft011]]/[[ft006]]/[[ft009]] at this
spec's retro, not a supersession -- same discipline [[sp023]] used.

Human confirmed FULL migration scope (not a raw i3-block deletion):
daemon layer + script re-point + i3 delete + qs-focus-border cleanup +
docs, all in the cutover commit, mirroring [[sp023]]'s
anti-pattern rule (never leave the old signal beside the new one).

## solution
Declare `"screenshot"` as a SECOND `bind.Layer{External: true}` in
[[im010]]'s compiled table (`hotkeyd/cmd/hotkeyd/config.go`, beside
`"screenshot-drag"`), then move the aiming-phase signal onto that layer
and delete the i3 mode in the same commit. This mints no new decision:
[[adr0022]] already fixed the shape (compile-time-declared, channel-
separated, refused by name otherwise) and this is the second instance of
it, so [[adr0012]]'s read-only state socket, [[adr0021]]'s compile-time
discipline and [[adr0014]]'s reader-retry split are all untouched. No
new `im###` either — [[im010]] is `accepted` and already owns this
surface; the delta lands as a BODY REFRESH of its `api_surface` at retro,
per [[sp023]]'s discipline.

Four files move, no architecture does:

- `hotkeyd/cmd/hotkeyd/config.go` — `+ "screenshot": {External: true}`
- `quickshell/qs-screenshot.sh` — `wm_msg mode screenshot` becomes
  `hotkeyd set-layer screenshot`; the clear path already runs
  `set-layer default` on every exit
- `i3/config.common` — the `mode "screenshot" {}` block and its
  Escape/`q` bindsyms DELETE (this retires the last live i3 custom mode;
  the `zz-fallback-binds.conf` modes exist only under panic)
- `quickshell/qs-focus-border.py` — the now-dead i3-mode-IPC colour half
  retires: `COLOR_MODES`, `i3_mode_colored`, the `_recompute_colored`
  OR-fold and the mode-event branch (with `"mode"` off its subscribe
  list), leaving `layer_colored` as the sole colour source — exactly how
  [[sp023]] Task 6 retired `SUPPRESS_MODES`

Consumes [[ft011]] (the surface extended), [[ft006]] (region capture —
`qs-screenshot.sh`'s owning feature), [[ft009]] (mode-bar hint strip) and
[[ft003]] (i3-config layering — the block being deleted). Under
[[cat002]] / [[cat001]]. `Bar.qml`, `qs-region.py` and `ModeBarTheme.qml`
need ZERO change: `Bar.qml:333`'s `activeMode` already prefers any
non-default `daemonLayer`, and `SetExternalLayer` already permits the
external-to-external `screenshot` → `screenshot-drag` handoff on press.

Three constraints refinement must carry, sharpening `## problem`:

1. `Bar.qml` KEEPS its i3 mode-change subscription. It goes inert in
   normal operation once no live i3 mode remains, but it is the PANIC
   fallback: hotkeyd dead means `daemonLayer` is `default`, and
   `zz-fallback-binds.conf`'s real `nav`/`resize`/`$mode_system` modes
   are what paints then. `qs-focus-border.py`'s branch is a different
   case — `COLOR_MODES` never held those names, so retiring it loses
   nothing under panic either.
2. The deleted mode branch also called `refresh_focused()`. That
   side-effect must be SHOWN already covered by `_set_layer_state`
   (which does colour, refresh and `queue_draw` off the layer feed), not
   assumed.
3. Residual risk once Escape/`q` die: a SIGKILL'd `qs-screenshot.sh`
   strands a `"screenshot"` layer — a stuck hint strip and a red ring.
   Pixels, never keys, because an External layer holds zero grabs
   ([[sp023]] plan decision 1); `hotkeyd.sh restart` clears it. Identical
   exposure to the one `screenshot-drag` has carried since [[sp023]],
   which is why the [[dotfiles-ux1]] escape hatch dissolves rather than
   needing a replacement.

## plan
Extends [[im010|go-hotkey-daemon-rewrite]]'s shipped tree in place —
additive declaration plus a channel cutover, not a correction. [[im010]]
is already `status: accepted`, so unlike [[sp023]] there is NO entry
gate: the daemon, the `set-layer` verb, `SetExternalLayer` and both
consumer mechanisms are live and proven. [[im010]]'s body refresh (and
[[ft011]]/[[ft006]]/[[ft009]]'s) happens at this spec's retro, not
here. Consumes [[ft011]] (surface extended), [[ft006]] (the calling
feature), [[ft009]] (the hint strip painted), [[ft003]] (the config
layer the mode leaves). Binding decisions walked per task: [[adr0022]]
(this is instance TWO of its exact shape — compile-time-declared,
channel-separated, refused by name; nothing here mints or overturns a
decision), [[adr0012]], [[adr0021]], [[adr0014]], [[adr0017]].

Facts verified against the tree, so no task has to re-derive them:

1. **The handoff is permitted but unpinned.** `SetExternalLayer`
   (`hotkeyd/internal/layer/engine.go:706`) checks the authority guard
   against the CURRENT layer only (`e.layerName != DefaultLayer &&
   !e.isExternal(e.layerName)`), so external → external is allowed by
   construction and its doc comment says so — but every test fixture
   declares exactly ONE External layer, so no test exercises two. Task 1
   pins it before the cutover leans on it.
2. **The consumers are already generic.** `Bar.qml:333`'s `activeMode`
   is `daemonLayer !== "default" ? daemonLayer : i3Mode`;
   `ModeBarTheme.resolve("screenshot")` matches by NAME regardless of
   which source carried it; `qs-focus-border.py`'s
   `layer_colours_ring` colours ANY non-default, non-silent,
   non-suppress layer. A `"screenshot"` layer paints both surfaces with
   zero consumer change.
3. **Constraint 2 evidence (the `refresh_focused()` side-effect).** The
   mode branch being deleted (`qs-focus-border.py:301-331`) recoloured
   and refreshed on every mode event. `_set_layer_state`
   (`qs-focus-border.py:444-472`) already does the same off the layer
   feed: it recomputes colour and runs `refresh_focused()` +
   `queue_draw()` whenever the colour state changed or a suppression
   lifted — and every aiming enter/exit IS a colour flip, so the
   deleted branch's refresh is covered, not assumed. Task 2's pytest
   cases assert it.
4. **The i3 comment surface is larger than the block.** Besides
   `i3/config.common:151-154`, three doc surfaces would become FALSE
   after cutover and reconcile in the same commit:
   `i3/config.common:126-186` (documents the mode as deliberately
   retained, "that block and its Escape/q fallback stay"),
   `i3/config.d/zz-fallback-binds.conf:329-334` ("it never left
   config.common"), and `engine.go:687-700` (the SetExternalLayer
   divergence rationale claims the drag signal ALWAYS arrives with
   `i3Mode == "screenshot"` — after cutover i3 stays in `default`
   through the whole gesture). `config_test.go:420-423`'s
   `externalLayerName` ("the one External layer the shipped table
   declares") reframes too.
5. **The Go test suite is generic over the External set.**
   `TestRealTable_ExternalLayersAreSignalOnly`, `…HoldsZeroGrabs`,
   `…NoChordEntersAnExternalLayer` and the golden-dump exclusion all
   iterate `externalLayerNames(Layers)`, so the second declaration
   passes them unmodified — only a per-name existence proof (the
   `TestRealTable_ScreenshotDragIsDeclaredExternal` mirror) is new.

Conventions:

- The cutover is ONE commit (Task 2): declaration, script re-point, i3
  deletion, qs-focus-border retirement, doc reconciles and the pytest
  re-point land together — no transition window where both channels are
  live, and no window where the suite is red ([[sp023]]'s anti-pattern
  rule, inherited verbatim).
- Consumer spawn discipline unchanged: `qs-screenshot.sh` invokes
  `"$HOME/.dotfiles/hotkeyd/hotkeyd" set-layer …` directly —
  same spelling as its existing clear at line 103 and as
  `qs-region.py` — guarded `>/dev/null 2>&1 || true` under `set -e`
  (a signal failure must never fail a capture).
- Frozen contracts no task may change: state-socket wire format +
  replay-on-connect ([[adr0012]], [[ft009]]); `--health` codes
  ([[adr0017]]); `set-layer` exit codes 0/1/2/3 ([[ft011]]); the panic
  path ([[ft003]]); reader loops fail fast, retry outside ([[adr0014]]).
- Stdlib only; `go.mod` require block stays empty ([[adr0021]]).
- Docs and spec prose hard-wrap at 80.

Anti-patterns — reviewers reject on sight:

- leaving `wm_msg mode screenshot` / `wm_msg mode default` (or the
  now-unused `wm_msg` helper) beside the new verb "for safety" — a
  signal in two channels is the double-fire class [[ft011]] exists to
  kill
- deleting `Bar.qml`'s i3 mode-change subscription — it is the PANIC
  fallback (hotkeyd dead → `daemonLayer` `default` →
  `zz-fallback-binds.conf`'s real nav/resize/`$mode_system` modes paint
  via `i3Mode`); retiring it is over-reach and a regression
  (`## solution` constraint 1)
- inventing an escape hatch for a stranded `"screenshot"` layer — a
  daemon-side timeout, a new bind, a watchdog. The exposure is pixels,
  never keys, identical to `screenshot-drag`'s since [[sp023]]
  (`## solution` constraint 3); document, don't build
- any behavioral field on the `"screenshot"` declaration (R28 refuses
  by name; `{External: true}` and nothing else)
- a "register a layer at runtime" surface, or any acceptance of a name
  not compiled in ([[adr0022]], [[adr0021]])
- touching the state socket's read path ([[adr0012]])
- editing `Bar.qml`, `qs-region.py` or `ModeBarTheme.qml` — including
  their stale comments; those are retro's body-refresh scope
- bd ids annotated in this file (spec-ready's job)

Known limitations, accepted up front:

- **Degraded-mode strip loss.** With hotkeyd absent (panic linked, sway
  session, daemon dead) the entry `set-layer screenshot` fails under
  `|| true`: the capture works — the selector's own seat grab owns the
  keys in-process — but NO hint strip and NO ring paint anywhere,
  because after cutover no `mode "screenshot"` exists for i3 to enter
  either. Previously the i3 mode painted them even daemon-less.
  Accepted: pixels-only, and the panic fallback still paints the modes
  that matter (nav/resize/system) via `Bar.qml`'s kept subscription.
- **Stranded layer.** A SIGKILL'd `qs-screenshot.sh` strands
  `"screenshot"`: stuck hint strip + red ring until `hotkeyd set-layer
  default` or `hotkeyd.sh restart`. Zero grabs held ([[sp023]] plan
  decision 1), so pixels, never keys — the [[dotfiles-ux1]] escape
  hatch dissolves rather than needing a replacement.
- **Stale comments in zero-change consumers.** `qs-region.py:39,
  301-318` and `ModeBarTheme.qml:102-118` describe the i3 aiming mode;
  they go slightly stale but the files are on the do-not-modify list.
  Retro's [[ft006]]/[[ft009]] body refresh owns them.
- [[us019]] is `status: done`; per `## problem` this is [[ft011]]
  surface growth with NO new AC line. Tasks cite the existing AC they
  genuinely bind to: AC1 (state feed, not bind side effects), AC4
  (validated + refused by name), AC5 (session stays usable when the
  owner dies), AC6 (migration changes nothing).
