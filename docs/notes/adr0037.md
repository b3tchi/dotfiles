# ADR [[cat002]] [[product]]

## title
quickshell bar layout is per-machine data, a JSON file rotz links by hostname

## context
One quickshell config serves every session: the desktop, the xrdp
sessions and, since kwin-host, kwi3 on the Nothing Phone's own screen.
Bar layout knobs (split bar, height, font, insets, density) were env vars
set by each session's launcher, so the phone's split bar lived in
kwi3-phone-session in the kwi3 repo. But the layout follows the SCREEN,
not the session: the phone's panel is 675x1500 logical whichever session
draws on it, and the same session script on another phone would need
other values. A per-screen env var does not scale past one screen, and a
config.js-style script was not wanted.

## decision
Bar layout is per-machine data: `quickshell/machines/<hostname>.json` in
the dotfiles, which quickshell's rotz dot links to
`~/.config/quickshell-machine.json` when one exists for `uname -n` (and
unlinks otherwise). `Session.qml` reads it once with a FileView. Every
setting resolves env var > `screens[<screen name>]` > top level >
built-in default, so a session can still override and a multi-head
machine keys values by output name (`DSI-1`). Session launchers set no
layout values any more (kwi3-phone-session runs plain `QS_RDP=1
quickshell`). Under kwi3 the row height and font still come from kwi3's
grid, not this file.

## consequences
A new machine's bar is one JSON file and a `rotz install quickshell`;
nothing in a launcher changes. Values are data, so a bad file is one
console warning and the built-in defaults, never a broken bar. The cost:
the file is keyed by hostname, so a renamed host silently loses its
layout until the file is renamed too, and the link only appears after
rotz has run on that machine. Env vars stay supported, which keeps two
ways to set the same thing; the lookup order above is the contract.
