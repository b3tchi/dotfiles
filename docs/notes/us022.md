# Story [[keyboard]] [[display-platform]] [[product]]

## role
[[pn001|developer]]

## want
to be told when a running hotkeyd is older than the bind table in my
working tree, instead of discovering it as a feature that silently does
nothing

## because
binds compile into the binary ([[adr0021]]), so a merge that changes the
table changes nothing about the running session until someone rebuilds
and restarts — and there is no signal anywhere that the two have
diverged. [[sp024]] shipped green on every headless surface and then did
not work on the live session: `set-layer screenshot` returned "no such
layer" because the daemon was three days older than `config.go`. The
half-deployed state is also actively confusing, because previously
declared names keep working — the drag phase painted while the aiming
phase did not, which reads as a bug in the new code rather than as a
stale process. Worse, one display had been running a daemon so old it
predated the control socket entirely, so `set-layer` could not have
worked there at all and nothing said so.

## acceptance_criteria
- a running daemon can be asked whether its compiled table matches the
  source tree it was built from, and answers without needing a rebuild
  to find out
- the answer distinguishes "same table", "older table" and "cannot tell"
  rather than collapsing the last two into a single failure
- a name refused by `set-layer` reports whether the name is unknown to
  THIS BINARY versus unknown to the source tree, so a half-deployed
  cutover is named as such at the point of failure
- `--health` continues to answer "is this daemon SERVING" and does not
  silently start failing on a merely-stale daemon; staleness is a
  separate verdict from unhealthiness
- whatever reports staleness costs nothing at dispatch time — the hot
  path must not stat the tree on every keystroke
