# ADR [[cat001]] [[product]]

## title
while alpha, bus breaking changes are hard cutovers with a protocol bump for diagnosis

## context
Collapsing the envelope vocabulary ([[adr0032]]) broke stored data. Readers
validate every record they load from disk, so retiring `inbox`/`result`/`error`
/`identity` meant ~185 durable identity records and every queued bus envelope
would be refused on read.

Two migration shapes were available. A dual-accept window has writers emit only
the new vocabulary while readers tolerate both, with aliases deleted once no
old record can be in play. A protocol bump raises the version and keeps a
read-only bridge for the old one — the pattern already in the module, which
carries a `V1_PROTOCOL = 1` import bridge for records that predate the current
build.

Both cost real work, and the project is pre-release with a single operator and
one machine. Against that, the session had just spent hours paying for a
DIFFERENT compatibility artifact: two envelope shapes had been shipped under
one protocol version, so `protocol` could not distinguish them and a validator
dispatching on a field only one shape carried failed on the first envelope of
the other. The version field existed the whole time and was simply never
bumped when the shape diverged.

## decision
While the project is alpha, breaking changes to the worker bus are HARD
CUTOVERS. No dual-accept read window, no compatibility bridge, no aliasing of
retired names. Stored records that no longer validate are purged deliberately,
with the operator's explicit approval, after verifying nothing live depends on
them.

`PROTOCOL_VERSION` is still bumped on every breaking change — not for
compatibility, since nothing reads the old version, but for the failure
message. A stale record then fails with `unknown protocol version 2: this
build speaks version 3 only` rather than `unknown envelope kind 'identity'`,
which reads like corruption instead of staleness and sends the next person
debugging in the wrong direction.

A cutover lands only while nothing is live. A worker spawned before and still
running after finds its own identity record unreadable, so `pi-worker ps` is
checked immediately before landing.

## consequences
The change that prompted this shipped in one commit instead of two, with no
alias table to delete later and no window during which both vocabularies were
legal — which is itself a class of bug, since a reader tolerating both cannot
tell a correctly-migrated envelope from a stale one. The `V1_PROTOCOL` import
bridge became dead weight under this policy and was removed with it.

The cost is paid in data, and it is not theoretical: 185 identity records were
deleted to make `worktrees-reclaim` work again, and the two workers whose
records went with them now render as `unknown` in the roster forever. That is
correct behaviour under [[adr0017]] — `unknown` is an observation, not a guess
— but it is permanent, and it is the shape of every future cutover.

This policy is explicitly scoped to alpha and has an expiry it cannot enforce.
The moment a second machine, another operator, or any data worth keeping
enters the picture, a cutover stops being cheap and this ADR needs superseding
rather than stretching. Nothing in the code will notice that moment; a human
has to. Recording the scope here is the only guard.

The protocol bump surviving a decision that makes it useless for compatibility
is deliberate. It costs one constant and buys a diagnosable failure, and the
version field going unbumped through a breaking change is exactly the omission
that cost this project a day.
