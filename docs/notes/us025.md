# Story [[cat001]] [[product]]

## role
[[pn001|developer]]

## because
[[sp033]] gave the operator an inbox — mail addressed to them is marked, counted
and answerable inside [[ft016]]. It did not give them a doorbell. The count only
exists while the monitor is on screen and being looked at, so a message that
arrives while the operator is in an editor, in another window, or away is
discovered whenever they next happen to glance at the TUI.

This is the asymmetry the whole [[sp033]] problem statement opened with, and
half of it is still open: a Pi session gets PUSHED delivery — the extension's
bus watcher injects each envelope into the live agent — while a human gets a
number on a pane they may not be watching. An agent that asks a question and
waits is blocked for as long as the operator does not look.

The in-TUI-only scope was a deliberate choice at spec time, not an oversight;
the terminal bell and a desktop notification through [[ft010]] were both
considered and declined for that iteration. This story carries the remainder.

## want
To be told when mail arrives for me, without having to be looking at
agent-monitor.

## acceptance_criteria
- A message whose `to_addresses` carries my address raises a notification I can
  see while agent-monitor is not the focused window, and while it is not
  running at all.
- The notification names the sender's rendered label and enough of the body to
  decide whether to act now, without requiring me to open anything to find out
  who it was from.
- Pipeline chatter never raises one: only envelopes addressed to me do, on the
  same address comparison [[ft016]]'s for-you marker already uses — never a
  label match.
- Nothing raises a second notification for a message I have already read.
- With no registered operator, nothing is raised and nothing errors — the
  current product is unchanged for anyone who has not run `pi-worker register`.
- The mechanism is [[ft010]]'s existing notification stack rather than a second
  notifier: one daemon owns `org.freedesktop.Notifications` on the user bus,
  and a second owner would silently lose one session's notifications.
