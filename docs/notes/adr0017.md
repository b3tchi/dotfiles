# ADR [[cat001]] [[product]]

## title
Only a component's own evidence about itself may trigger automatic recovery

## context
[[sp020]] produced four separate reports of the same shape, close enough
together to be one lesson rather than four: the tool answered a weaker question
than the operator was asking.

- `status` reported "running" for a daemon that had lost half its grabs
  (dotfiles-hwds.41, .42).
- `status` reported "running" for a daemon whose X server had died
  (dotfiles-hwds.28).
- `status` reported "running" while an exclusive keyboard grab held by another
  client bypassed every chord (dotfiles-hwds.30) — a locked screen, which does
  that by design.
- The heartbeat that fixed the first two then reported every daemon predating
  it as WEDGED, because absence of a beat is indistinguishable from a missed
  one by age alone (dotfiles-hwds.29).

The fourth is the dangerous one. A patch that made `start` reap a daemon whose
heartbeat looked stale was written and deliberately NOT merged; had it landed
with the heartbeat, upgrade day would have killed two healthy daemons. The
false alarm was survivable on its own — wired to automatic recovery it was not.

## decision
A verdict that triggers automatic recovery must rest on the component's OWN
evidence about ITSELF. Everything else is reported and acted on by a human.

Concretely, health verdicts are separated by who the evidence is about and what
it licenses:

| verdict | evidence | reapable |
|---|---|---|
| the run loop stopped beating | the daemon, about itself | **yes** |
| the display did not answer ME | the caller, about the caller | no |
| another client holds the keyboard | a third party | no |
| grabs are missing vs the table | the daemon, about itself, but a restart is the cure | no — fix, don't kill |
| the daemon predates the heartbeat | nothing — the question is unanswerable | no |

"I cannot tell" is a first-class verdict with its own exit code, distinct from
"it is dead". Absence of evidence must never be encoded as evidence of absence,
and a caller's missing X authority must never read as a dead server.

## consequences
More exit codes than a boolean, and each has to be justified rather than
reused: sharing a code between "dead" and "cannot tell" is precisely the bug
this prevents.

Every future health probe inherits two obligations — say WHICH probe failed,
because a bare non-zero exit during an outage ends the investigation instead of
directing it; and, when the cure lies outside this component, do not print
advice that points back at it (a status line that says "restarting cannot fix
this" and then suggests a restart sends the reader round a loop).

Deliberately conservative: a daemon that is actually wedged and predates the
marker will not be auto-recovered until it is restarted once by hand. That
direction is chosen — withholding a verdict costs a manual restart, inventing
one costs a working session.

Supersedes nothing, but constrains [[adr0014]]'s fail-fast posture: fail fast
on your own evidence, degrade honestly on everyone else's.
