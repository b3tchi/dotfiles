# Feature [[cat001]] [[product]]

## providing

Visible, resumable Pi implementer and reviewer workers hosted as named windows
inside an existing linked tmux project group, consumed by Infinifu's automated
execution skills.

## api_surface

`infinifu-worker` is a nushell CLI linked into `~/.local/bin` by
`install.sh worker`. Its verbs are `spawn`, `send`, `wait`, `ack`, `status`,
`inspect`, `workers`, `resume`, `accept`, `stop` and `doctor`; output is JSON
because every consumer is another program. `wait` prints nothing when there is
no mail, so it reads correctly in a shell conditional.

`spawn` allocates a `bd-<task>.<N>` worktree, records the identity envelope, and
only then starts Pi in a tmux window named `<role>-<subject>@<project>`.
Evidence precedes the process deliberately: a worker that dies during startup
still leaves a cwd and a resume command behind. The window carries
`remain-on-exit`, so a crashed worker's error stays on screen. Worker identity
reaches the extension as window-scoped environment
(`INFINIFU_RUN`/`UID`/`ROLE`/`BRANCH`/`SESSION`/`SKILL`/`WINDOW`), because the
extension must know which inbox is its own before any message can arrive.

`wait` is non-destructive and redelivers until `ack`; `ack` is a delivery
receipt and never acceptance. `accept` is the only verb that cleans up, and it
refuses a worker that is not `complete`, one holding uncommitted or untracked
work, or one with no identity. `stop` closes the window and keeps the worktree,
since a stopped worker may hold unmerged commits. `resume` sends reviewer
feedback to the ORIGINAL session as an AKM-shaped message; a second rejection
returns `escalate: true` and parks the worker at `waiting_human`. `workers`
reconstructs a whole run from the bus alone, so nothing about a run lives only
in the orchestrator's conversation.

For `work-do`, `work-audit` and `work-merge` the message payload is only the bd
ticket id; the worker resolves its contract with `bd show <id>`. Other stages
receive direct instructions plus artifact ids. Role, skill, cwd and session are
trusted transport configuration carried in system context, never in the user
message.

A stage may report `complete` only with the verdict its own discipline
produces, read from the typed `validation` field and never from the summary;
`spec-refinement` must carry `SRE PASS` ([[adr0027]]). Every completion
envelope carries result, validation verdict, worker window, Pi session id and
the exact `pi --session <id>` resume command.

Tmux hosts and displays worker processes and nothing else — no `send-keys`,
`wait-for`, pane options or `display-message` as transport ([[adr0028]]).
Completed workers remain visible until explicit `accept`; failed, blocked and
rejected workers remain visible for inspection and resume.

## data_model

Transient bus data lives under
`$XDG_RUNTIME_DIR/infinifu-worker/<run-id>/<worker-uid>/` in `inbox/`,
`outbox/` and `identity/` boxes, as versioned, monotonically sequenced JSON
envelopes. Directories are created `0700` with `mkdir -m` (a mkdir-then-chmod
window is long enough for a concurrent writer to correctly refuse the tree) and
envelope files are `0600` before they are linked into place. Writes go to a
scratch name and are renamed, so a reader sees a whole envelope or no file; a
sequence slot is claimed with `link(2)`, which fails if taken, so racing
writers cannot both win. Envelopes cap at 64 KiB and completion summaries at
4 KiB. Addressing is the directory path, which makes cross-run isolation
structural rather than a filter someone can forget.

Envelope kinds are `inbox`, `result`, `error` and `identity`. Persisted worker
states are `created`, `running`, `waiting_human`, `blocked`, `failed`,
`complete`, `protocol_error`, `accepted` and `stopped`, with `complete →
accepted` the only edge into `accepted`. States granted from outside the worker
are recorded as marker files beside its envelopes — `accepted`, `stopped`,
`waiting_human`, and `reopened`, which records WHICH result a rejection sent
back so a reopened worker reads as `running` even though its last envelope
truthfully still says `complete`. Marker precedence is accepted, stopped,
waiting_human, reopened, then the newest result. `unknown` is an observational
verdict, never persisted, and never a licence to stop, accept or delete
([[adr0017]]).

An agent that settles without calling the typed result tool produces a
`protocol_error` envelope, never a completion. Durable task evidence stays in
bd, source state in Git, AKM state behind `akm`, and conversation history in Pi
JSONL; bus state is reconstructable from its envelopes and contains no copied
bd task body.

## sample

```text
infinifu-worker spawn --run run-42 --uid impl-dotfiles-7opn.1-a1 \
  --role impl --project dotfiles --cwd <worktree> --session <uuid> \
  --skill work-do
infinifu-worker send impl-dotfiles-7opn.1-a1 --text dotfiles-7opn.1
infinifu-worker wait --run run-42 --json
# {"sequence":7,"status":"complete","validation":"PASS",
#  "resume":"pi --session <uuid>","window":"impl-dotfiles-7opn.1@dotfiles"}
infinifu-worker ack --run run-42 --sequence 7
```

## known_limitations

Pi's event names, its `sendUserMessage` signature and its agent-state
vocabulary are carried from this Feature's design and have not been compiled or
run against a live Pi — the Pi package is not a dependency of this repo. Every
host call is feature-detected and degrades to a logged no-op rather than
throwing during host startup, and an unrecognised agent state defers rather
than delivering, so a wrong assumption costs a redelivery instead of a
corrupted turn. The README carries a seven-step live operator checklist that
reconciles them; until it is run, the Pi-side bridge is unproven while the bus,
worktree, window and cleanup layers are covered by 243 automated cases.
