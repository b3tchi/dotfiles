# Feature [[cat001]] [[product]]

## providing

Visible, resumable Pi workers hosted as named windows inside an existing
linked tmux project group, reachable over a peer-addressed message bus: every
agent on the bus is an address, envelopes carry `from`/`to` with an opaque
`content`, and a typed result goes to whoever commissioned the reporting agent
([[adr0029]]).

Transport only, and now literally so. The transport interprets no flow: it
carries any consumer's vocabulary and gates on none of it, including the shape
of what it carries. Under Pi that consumer is [[ft013]], which owns the
review-process judgments — rejection counting, escalation, what payload a
stage may send — that used to live here; nothing in this Feature depends on it.

## api_surface

`pi-worker` is a nushell CLI ([[adr0001]], [[adr0002]]) linked into
`~/.local/bin` by the plugin's installer; output is JSON because every consumer
is another program. `wait` prints nothing when there is no mail, so it reads
correctly in a shell conditional. Eighteen verbs in four groups:

- peer messaging: `send`, `wait`, `result`, `settled`
- lifecycle and authority: `spawn`, `resume`, `accept`, `stop`, `rm`,
  `reclaim`, `respawn`
- observation: `status`, `inspect`, `workers`, `ps`, `liveness`, `timeline`
- setup: `doctor`

Messaging is symmetric; authority is not. `send --as <from> --to <address>
--content <opaque>` writes to any address from any address, never gated on
lineage. `wait --as <address> [--block] [--timeout <s>]` means "mail addressed
to me": it returns every unread row for that address and marks it read in the
same call. There is no acknowledgement step, no redelivery window and no
sequence arithmetic — `ack`, `--sequence` and `--after` are gone, and so is
`--run`, which had become a caller-supplied grouping that every spawn minted
for itself anyway. Recovery after a crash is `inspect` / `workers`, which
rebuild a worker's state and last reported result from its durable identity
record rather than from what was not yet marked read.

`accept`, `stop`, `rm` and `reclaim` destroy worktrees, branches and addresses,
so they stay with whoever ALLOCATED the resource — ownership is mechanism, and
"the orchestrator" is a flow. Cleanup is project-scoped: each resolves the
project from the caller's own cwd, so a call inside one project cannot reach a
same-named uid in another.

`spawn` mints a fresh run and, unless `--uid` is given, a uid that is unique
across the whole PROJECT — not within one run. The distinction is not
cosmetic: uniqueness was once scoped to a single run directory, which every
spawn created empty, so every ordinary spawn of a role minted `<role>-1` and
two live workers silently shared one queue and one CLI address
(`dotfiles-bg65`). An address is taken by a single `mkdir` without `-p`, so two
spawns racing for the same lowest-free uid cannot both win; the loser is
refused and re-mints.

`spawn` then places the worker, records the identity envelope, and only then
starts Pi in a window named `<role>-<subject>@<project>`, addressed thereafter
by the `window_id` recorded at creation ([[adr0030]]). Evidence precedes the
process deliberately: a worker that dies during startup still leaves a cwd and
a resume command behind. The window carries `remain-on-exit`, so a crashed
worker's error stays on screen, and `@pinned`, so this repo's own tmux
housekeeping does not reap a detached worker — a display-host hint carrying no
message, completion signal or coordination state. An isolated worker owns
branch `wk-<task-or-subject>.<N>`; a worker sharing the operator's tree gets a
commit guard instead. Identity reaches the extension as window-scoped
environment (`PI_WORKER_RUN`/`UID`/`ROLE`/`BRANCH`/`SESSION`/`SKILL`/`WINDOW`).

An agent nobody spawned self-registers: the extension claims `self-<hex>` and
gets the same identity envelope and queue a spawned worker gets, which also
makes it visible to the observation verbs. The inbox watcher runs in EVERY
session rather than only in worker mode, which is what makes an orchestrating
session reachable at all. It stays idle-gated: a message reaches an `idle`
agent as an ordinary user turn, every other state defers, and at most one
message is delivered per poll with the agent state re-read for each. A delivery
is what starts a turn, so a batch judged against one reading loses everything
after the first, and a mid-turn steer cannot be confirmed and is therefore
never chosen.

`resume <uid> --feedback` sends feedback to the ORIGINAL session as an ordinary
addressed message — same session, same worktree, same context. It is otherwise
unremarkable: no rejection count, no `escalate` flag, nothing written about it
to the bus. Two-strikes-then-a-human is unchanged as a review flow, but it is
now enforced by `work-audit` counting prior rejections on the bd task itself.

`accept` is the only verb that reclaims work, and every refusal is collected
BEFORE anything is touched — a refusal costs nothing, so a declined acceptance
can be retried once its cause is fixed. It refuses a worker that is not
`complete`, one holding uncommitted or untracked work, the main worktree, and a
branch whose commits are reachable from no other ref. It is idempotent, and a
tree or branch already gone is the finished state rather than an error. `stop`
closes the window and keeps both tree and branch, since a stopped worker may
hold unmerged commits. `rm --uid <uid>` releases an address only once its
worker is `stopped` or `accepted`, and releases it PROJECT-wide — placement
record, `.index` pointer, address claim and queue — resolving the project from
the durable `.index` slug rather than from a cwd `accept` may already have
deleted. `reclaim` sweeps trees and branches no live worker owns, locally or
with `--remote`; `respawn` brings a reclaimed worker back on its own Pi session
under a new uid carrying `respawned_from`, because `accepted` has no outgoing
edge and history stays literally true.

`result --as <uid> --status --summary --validation` and `settled --as <uid>`
are the worker's own side, reached through a typed result tool the Pi extension
registers; a session that ORCHESTRATES workers drives every verb through one
`pi_worker` tool. A stage may report `complete` only with the verdict its own
discipline produces, read from the typed `validation` field and never from the
summary ([[adr0027]]). Every completion envelope carries status, validation
verdict, worker window, Pi session id and the exact `pi --session <id>` resume
command. `settled` writes a `protocol_error` only for an agent that was
commissioned; an uncommissioned agent settling produces nothing and exits 0.

Tmux hosts and displays worker processes and nothing else — no `send-keys`,
`wait-for` or `display-message` as transport ([[adr0028]]).

## data_model

Bus data is PROJECT-scoped, not run-scoped, because an address is now
project-wide. Transient message state lives under
`$XDG_RUNTIME_DIR/pi-worker/<project-slug>/bus/` in two boxes: `messages/<id>`
holds one envelope per message, and `queue/<uid>` holds one queue row per
addressee. Fan-out stages the message first and publishes the queue rows last,
so a reader never sees a row pointing at an envelope that is not there yet, and
an incomplete fan-out is refused rather than half-delivered. Message ids are
lexically sortable, so ordering does not depend on a sequence counter.

Durable placement lives in state home, which survives the logout that wipes
`$XDG_RUNTIME_DIR`: `$XDG_STATE_HOME/pi-worker/<project-slug>/agents/<run>/<uid>/`
carries the identity envelopes and marker files,
`.../<project-slug>/addresses/<uid>` is the address claim, and
`$XDG_STATE_HOME/pi-worker/.index/<run>/<uid>` is the slug pointer that lets a
uid be resolved back to its project without guessing from a path. The `<run>`
level is vestigial now that uniqueness is project-scoped — two unrelated
workers can co-tenant one run id harmlessly — and is kept only because every
reader and writer is still shaped around it.

Directories are created `0700` with `mkdir -m` at every level, not just the
leaf (a mkdir-then-chmod window is long enough for a concurrent writer to
correctly refuse the tree), and envelope files are `0600` before they are
linked into place. Writes go to a scratch name and are renamed, so a reader
sees a whole envelope or no file. `content` caps at 64 KiB and completion
summaries at 4 KiB, with a separate bound on total envelope bytes so the cap
moving to `content` did not leave the envelope itself unbounded.

Envelope kinds are `message`, `result`, `error` and `identity`. A `message` is
`{from, to, content}` with content opaque; a `result` keeps its typed `status`
/ `validation` / `summary` / `session` / `resume` fields; `error` and
`identity` are bus-authored. Persisted worker states are `created`, `running`,
`waiting_human`, `blocked`, `failed`, `complete`, `protocol_error`, `accepted`
and `stopped`, with `complete → accepted` the only edge into `accepted`. States
granted from outside the worker are marker files beside its envelopes —
`accepted`, `stopped`, `waiting_human`. `unknown` is an observational verdict,
never persisted, and never a licence to stop, accept or delete ([[adr0017]]).

Durable task evidence stays in bd, source state in Git, AKM state behind `akm`,
and conversation history in Pi JSONL; bus state is reconstructable from its
envelopes and contains no copied bd task body.

A legacy run/uid message tree still exists alongside the above.
`bus-result`, `bus-settled` and `bus-identity` are ADDITIVE dual-writers: the
typed result travels as a peer message AND is still written to the old
`claim-slot`-numbered `run/<uid>/outbox`, because `derive-state`,
`worker-accept` and `bus-status` read only that tree. So a result is an
ordinary message in what gets DELIVERED and not yet in what gets STORED. The
read-side migration is an open decision (`dotfiles-a34y`) that blocks retiring
both `claim-slot`/`next-sequence` (`dotfiles-v1zt`) and the `legacy-bus-*`
readers (`dotfiles-hp6v`).

## sample

```text
pi-worker spawn --role peer --subject ada --project peerdemo --isolation main
# {"run":"r5","uid":"peer-2","window":"peer-ada@peerdemo","window_id":"@78",
#  "session":"5a60f174-...","live":true,...}
pi-worker spawn --role peer --subject bo --project peerdemo --isolation main
# {"run":"r6","uid":"peer-3",...}   <- same role, no --uid, distinct address

# the commissioner's address is the `run` its own spawn reply carried back
pi-worker send --as r5 --to peer-2 --content 'ask peer-3 what did not become symmetric'
pi-worker wait --as r5 --block --timeout 60
# [{"kind":"inbox","from":"peer-2","content":{"status":"complete",
#   "summary":"...","validation":"received 01M25GFV..., 01M25GG7..."}}]

# peers address each other directly; no dispatcher relays a word
pi-worker send --as peer-2 --to peer-3 --content '<question>'
pi-worker wait --as peer-2 --block --timeout 60

pi-worker stop peer-2 ; pi-worker rm --uid peer-2
```

## known_limitations

The Pi-side bridge is no longer unproven — it has been run against a live Pi
repeatedly, and doing so is what found the delivery defects the surface above
now describes (`dotfiles-nhit`, `dotfiles-c4kh`, `dotfiles-uddc`). Automated
coverage is 429 protocol cases plus 207 bridge cases, and neither can
substitute for the live run: a fake host that answers `idle` to every state
query cannot expose a message lost because delivering the previous one started
a turn, and it was a live run that caught spawned workers reading only the
legacy inbox while the new bus queue filled up unread.

Peer addressing added a hazard it does not prevent: two agents can each
`wait --block` on the other and deadlock. This is survivable only because the
block is bounded at 60s; the bound is the entire mitigation.

Three earlier limits remain. A mid-turn steer stays unusable until Pi tells a
caller whether one was accepted, so an urgent message waits for the agent to
settle rather than interrupting it. `settled` writes its `protocol_error` only
when nothing has been reported yet, so a worker that goes quiet in a LATER
round leaves no evidence on the bus at all. And a sender learns of a lost or
ignored message only by timing out, because the bus has no acknowledgement from
the agent — and since `wait` now marks on delivery, it has none from the
transport either: a caller that dies between `wait` returning and acting on the
row does not get that row back.

Two gaps are known and tracked rather than fixed. Fixture workers spawned by
the live-tmux suite are not always reaped, leaving live `pi` processes holding
windows with no bus identity — and per [[adr0017]] nothing may then clean them
up automatically (`dotfiles-6nvx.25`). And the legacy dual-write described in
`## data_model` means the storage model is mid-migration.
