# Feature [[cat001]] [[product]]

## providing

Visible, resumable Pi implementer and reviewer workers hosted as named windows
inside an existing linked tmux project group, consumed by Infinifu's automated
execution skills.

## api_surface

`infinifu-worker spawn` accepts a run ID, worker UID, role, project group,
worktree, Pi session ID, and skill name; it starts the worker in a named tmux
window and returns its identity. `infinifu-worker send` atomically appends an
addressed JSON message to the worker inbox. The Pi extension consumes that
message with `pi.sendUserMessage()` and exposes a typed result tool that invokes
`infinifu-worker result` to write the worker's outbox envelope atomically.
`infinifu-worker wait --run <id> --json` returns the next unacknowledged result
to the initiating agent;
`ack` confirms delivery without accepting the work. `status`, `inspect`,
`resume`, `accept`, and `stop` address a stable worker UID.

For `work-do`, `work-audit`, and `work-merge`, the direct message payload is
only the bd ticket ID; the worker resolves instructions with `bd show <id>`.
Role, skill, cwd, and session are trusted transport configuration injected by
the extension, never copied task prose. Other AKM stages receive direct stage
instructions and artifact IDs, then resolve documents through `akm`. Every
successful completion envelope includes result, artifact or task ID, commit
when applicable, validation verdict, worker window name, Pi session ID, and an
exact `pi --session <id>` resume command.

Tmux only displays and hosts worker processes. It does not carry messages,
completion signals, or orchestration state: no `send-keys`, `wait-for`, or pane
options are used as the bus. Completed workers remain visible until explicit
`accept`; failed, blocked, or rejected workers remain visible for inspection
and resume.

## data_model

Transient bus data lives under
`$XDG_RUNTIME_DIR/infinifu-worker/<run-id>/<worker-uid>/` as versioned,
monotonically sequenced JSON inbox and outbox envelopes written by atomic
rename with directory mode `0700` and file mode `0600`. Each envelope is at
most 64 KiB and a completion summary is at most 4 KiB. Persisted worker states
are `created`, `running`, `waiting_human`, `blocked`, `failed`, `complete`,
`protocol_error`, `accepted`, and `stopped`; `unknown` is an observational
verdict, not persisted state. Only `complete` may become `accepted`.
`waiting_human`, `blocked`, `failed`, `complete`, and `protocol_error` may
resume to `running`; invalid or conflicting transitions fail closed.

The Pi extension bridges inbox messages into the session and writes result
envelopes through a typed tool. A settled agent that did not call the tool
becomes `protocol_error`, never a successful completion. `wait` is
non-destructive and may redeliver after an initiator crash; only `ack` marks an
envelope delivered.

Durable task evidence stays in bd, source state stays in Git, AKM state stays
behind `akm`, and conversation history stays in Pi JSONL. Bus state is
reconstructable from its envelopes and contains no copied bd task body.

## sample

```text
infinifu-worker spawn --run run-42 --uid impl-dotfiles-7opn.1-a1 \
  --role impl --project dotfiles --cwd <worktree> --session <uuid> \
  --skill work-do
infinifu-worker send impl-dotfiles-7opn.1-a1 --text dotfiles-7opn.1
infinifu-worker wait --run run-42 --json
# {"sequence":7,"status":"complete","validation":"PASS",
#  "resume":"pi --session <uuid>","window":"impl-dotfiles-7opn.1@dotfiles"}
infinifu-worker ack --run run-42 --sequence 7
```
