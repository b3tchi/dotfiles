# Feature [[cat001]] [[product]]

## providing

Visible, resumable Pi implementer and reviewer workers hosted as named windows
inside an existing linked tmux project group, consumed by Infinifu's automated
execution skills.

## api_surface

`infinifu-worker spawn` accepts a role, bd task ID, project group, worktree,
Pi session ID, and skill name; it returns the tmux target. `infinifu-worker
wait` blocks until one worker in a run completes and returns its recorded
status. `infinifu-worker status`, `resume`, and `stop` address workers by stable
UID. Window names follow `<role>-<bd-id>@<project>` through tmux's existing
`#W@#{session_group}` display convention. For `work-do`, `work-audit`, and
`work-merge`, the worker's direct work-content payload is only the bd ticket
ID; it resolves instructions with `bd show <id>` and reads dependencies and
linked specs itself. Role, project, worktree, session, and skill selections are
transport metadata. The adapter must not copy or summarize the ticket body
into the worker prompt. Other AKM stages continue to use direct instructions
and resolve referenced AKM documents through `akm`.

## data_model

Tmux pane options carry worker UID, role, bd task ID, Pi session ID, run ID,
status, and pinned state. Durable task evidence stays in bd, source state stays
in Git, AKM state stays behind `akm`, and conversation history stays in Pi
JSONL. Adapter metadata is reconstructable and contains no duplicated task or
AKM body.

## sample

```text
infinifu-worker spawn --role impl --task dotfiles-7opn.1 \
  --project dotfiles --cwd <worktree> --session <uuid> \
  --skill work-do
# worker prompt payload: dotfiles-7opn.1
# worker resolves contract: bd show dotfiles-7opn.1
# tmux status: impl-dotfiles-7opn.1@dotfiles
```
