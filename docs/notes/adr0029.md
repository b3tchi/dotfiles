# ADR [[cat001]] [[product]]

## title
the worker bus addresses peers and encodes no flow

## context
[[ft014]] was built as a star. `run/<uid>/{inbox,outbox}` had exactly one
privileged reader: the initiator wrote a worker's inbox, the worker wrote its
outbox, and `wait --run` returned "the oldest unacknowledged result across the
run" — a query that only read correctly because exactly one process ever asked
it. A result was owed to "the initiator", which is a role, not an address.

That shape had two costs. The first was reachability: the Pi extension's inbox
watcher was gated on worker mode (`PI_WORKER_RUN`/`PI_WORKER_UID`, set by
`spawn`), so a worker could be reached and the session driving it could not.
Nothing could tell an orchestrating session that its worker had reported; it
had to ask, and `wait --block` is capped at 60s by design because it runs
inside a host tool call.

The second was vocabulary. The transport had grown opinions about the flow
running on top of it: `resume` counted rejections and returned
`escalate: true` on the second one, the bus authored a `rejection` entry in
its own `RESERVED_STAGES`, and a stage registry gated `payload: ticket` versus
`payload: instructions`. Each of those is a judgment about a review process,
living in a component whose own documentation promised to "carry any
consumer's vocabulary and interpret none of it".

The motivating case was a worker that converses with the human in its own
harness window — brainstorming, design review, anything where the human is the
counterparty — decides for itself that the conversation is finished, and
reports back so the initiating agent runs the next stage. No new stage kind was
needed; the consumer's registry already expressed it as `isolation: main`. What
was missing was a way for that report to REACH an agent that was not listening.

## decision
Every agent on the bus is an address, and the bus interprets nothing about the
flow those addresses run.

Addressing is symmetric. Envelopes carry `from` and `to` with an opaque
`content`; `send` takes `--as`/`--to`; `wait --as <address>` means "mail
addressed to me" rather than "oldest in the run"; a request records a reply-to
and the typed result goes there. An agent nobody spawned self-registers to get
the same uid, identity envelope and queue a spawned worker gets, which also
makes it visible to the observation verbs. The inbox watcher runs in every
session, still idle-gated: a message reaches an `idle` agent as an ordinary
user turn and every other state defers.

Authority does NOT become symmetric. `accept`, `stop`, `rm` and `reclaim`
destroy worktrees and branches, so they stay with whoever ALLOCATED the
resource — ownership, which is mechanism, not "the orchestrator", which is a
flow. Messaging is never lineage-gated: any address may write to any other.

Only two envelope kinds carry peer traffic. A `message` is `{from, to,
content}` with content opaque. A `result` keeps its typed `status` /
`validation` / `summary` / `session` / `resume` fields, because [[adr0027]]
exists precisely so completion is never read out of prose; symmetry does not
soften that. `error` and `identity` remain bus-authored.

Flow vocabulary leaves the transport. Rejection counting and escalation move
to the consumer ([[ft013]], enforced in `work-audit`'s own instructions); the
bus-authored `rejection` stage and the `payload` gate are deleted outright. A
transport that cannot interpret `content` cannot gate on its shape, so that
check belongs to the consumer at send time. The bus keeps `send`, addressing
and the size cap.

Delivery and marking collapse into one call: `wait` returns every unread row
addressed to the caller and marks it read before returning. There is no
separate acknowledgement step and no redelivery window, so `ack`,
`--sequence` and `--after` are gone. Recovery after a crash comes from
`inspect` / `workers`, which rebuild a worker's state and last result from its
identity record, never from "what was not yet marked read".

The human is NOT an address. The human converses in the Pi harness, at the
worker's window. `waiting_human` keeps its current meaning — the human is
needed at a harness, not that mail waits for them.

## consequences
An orchestrating session becomes reachable, which is what the motivating case
needed: a brainstorm worker talks to the human, decides it is finished, and its
typed result lands in its commissioner's queue without the commissioner
polling.

Two agents can now each `wait --block` on the other and deadlock. This is
survivable only because the block is bounded at 60s, and it is a real hazard
rather than a theoretical one — in the live demo of this decision, the peer
asked to name the biggest risk of mutual blocking named exactly this. No
mechanism prevents it; the bound is the whole mitigation.

Dropping redelivery moves a burden onto the caller: an orchestrator that dies
between `wait` returning and acting on the row does not get that row again.
That is why `inspect`/`workers` reconstruct from the identity record — the
durable evidence, not the queue, is the recovery path.

Losing the `payload` gate means a consumer can now send a worker a shape its
own discipline forbids, and the bus will carry it. That check has to be
re-implemented consumer-side or it is simply gone; moving it was deliberate,
but it is a real capability the transport no longer provides.

[[adr0028]] is untouched by this: the file bus is the transport in both
directions, and tmux still only hosts and displays. [[adr0025]] is also
untouched — [[ft012]] agent-census stays bound to the supported
`claude agents --json` surface and Pi workers are not in that population.

Retiring the legacy run/uid message tree did NOT land with this decision.
`bus-result`, `bus-settled` and `bus-identity` ship as ADDITIVE dual-writers:
the typed result travels as an ordinary peer message AND is still written to
the old `claim-slot`-numbered outbox, because `derive-state`, `worker-accept`
and `bus-status` still read only that tree. The read-side migration is a
separate open decision (`dotfiles-a34y`), and until it is made, "a result is an
ordinary message" is true of what is delivered and not yet true of what is
stored.
