# Feature [[cat001]] [[cat002]] [[product]]

## providing
A census of running agents grouped by project and bucketed by state.
One nushell action on `PATH` joins `claude agents --all --json` — run
once per account, since the command is scoped to a single
`CLAUDE_CONFIG_DIR` — with the tmux pane→project assignment, and emits
one row per project carrying `idle` / `working` / `blocked` / `done`
counts. It observes only; rendering belongs to its consumers (a
quickshell bar widget, the project picker, the tmux status line,
`claude/statusline.sh`), each of which wants the same numbers shaped
differently. Complements [[ft001]], which registers and navigates
projects but does not report what runs inside them.

The census covers two runtimes, not one: claude sessions (via `claude
agents --all --json`, or the `--fast` state-file read below) and pi
workers (via [[ft014]]'s `pi-worker workers`). Every row — count or
`--detail` — carries a `runtime: claude | pi` field, so a consumer
never has to infer which probe produced it from column shape alone. A
project running both shows up as one merged count row, not two.

## api_surface
Nushell action at
[nushell/actions/agent-census](../../nushell/actions/agent-census),
linked to `~/.local/bin/agent-census` by `nushell/dot.yaml` — the same
`PATH` shim pattern as `wm-ipc.nu` and `project-picker`, so non-nushell
consumers invoke it as a single exec.

- `agent-census` — table of per-project counts, one row per project
  plus an `unknown` row when attribution failed. Human-facing default.
- `agent-census --json` — the same rows as JSON, for external
  consumers.
- `agent-census --project <name>` — restrict to one project. Emits an
  empty result (not an error) for a name with no running agents, and
  likewise for a name that is not registered at all.
- `agent-census --detail` — one row per agent instead of counts:
  `{ project, account, kind, state, status, bucket, name, cwd, pid, how,
  runtime, uid, role, branch }`. `state` and `status` are separate
  columns; see the data model below. `uid`, `role` and `branch` are
  pi-only concepts (claude rows carry them empty; a claude row's
  identity is its session `name`/`pid` instead) — present on every row
  regardless of runtime so the two kinds concatenate into one table.
- `agent-census --all` — include records whose process is gone or whose
  job has finished. Mirrors the upstream flag name. Governs the claude
  side only: `pi-worker workers` has no historical/live split of its
  own, so pi rows are unconditional.
- `agent-census --fast` — read the accounts' own `sessions/<pid>.json`
  and `jobs/<id>/state.json` files directly instead of calling `claude
  agents --all --json`: ~60x cheaper (~0.025 CPU-s vs ~0.65 CPU-s per
  account), at the cost of depending on an internal layout nothing
  upstream promises. Predates this spec — shipped as `dotfiles-ah7q` —
  and is opt-in only: a bare `agent-census` invocation, and any consumer
  that never passes the flag, still reads only the supported CLI.
  Authorised narrowly by [[adr0029]], which supersedes [[adr0025]]'s
  "supported surface only" rule for exactly this one path and requires
  a standing live parity guard as the condition of that carve-out. That
  guard (`tests/agent-census/probe-cases.nu`) is currently RED on a
  real disagreement between the persisted and live status of one
  session (`dotfiles-v1in`) — adr0029 discloses this; the fast and CLI
  probes are not yet proven to agree in production.
- `agent-census --if-changed <stamp>` — path to a stamp file. Before
  probing anything, the action fingerprints every session/job file it
  would otherwise read; if the fingerprint matches what `stamp` last
  recorded, it prints **nothing** and exits 0. Silence means unchanged,
  **never** "no agents running" — a consumer that redraws from empty
  output would blank itself on every unchanged tick, which is exactly
  why `Common/Census.qml` treats an empty read as "keep the last map".
  Also predates this spec, shipped alongside `--fast`. The gate is
  scoped to the claude state files `--fast` reads; a pi worker's state
  changing does not reopen it (a known, accepted limitation, not this
  task's contract to close).

Flags compose: `--json --detail --all` yields detail rows, as JSON,
including historical records; `--fast --if-changed <stamp>` is the
shape a 1s-cadence poller actually runs.

Exit status is 0 whenever the census completes, including when zero
agents are running. A missing account directory is skipped silently;
tmux not running degrades to the `cwd` path rather than failing.

Output is plain text when stdout is not a terminal — nushell colours
its tables even into a pipe, so the action strips escapes explicitly
rather than handing a consumer control characters.

## data_model
Count row:

```
{ project: string          # tmux session_group, or projects.yaml name
  path: string             # registry path; null for tmux-only groups
  idle: int, working: int, blocked: int, done: int, other: int
  total: int
  accounts: { personal: int, work: int }
  cwds: list<string> }     # populated only on the `unknown` row
```

`cwds` is present on **every** row and empty where attribution
succeeded: a nushell table needs uniform columns, so it cannot be a
field that exists only on the `unknown` row.

The source carries two independent axes, and conflating them is the
mistake this feature exists to avoid ([[adr0024]]):

| field | means | present |
|---|---|---|
| `state` | the JOB's lifecycle — working / blocked / done / failed | background records only, survives the process |
| `status` | the PROCESS's activity — busy / idle | both kinds, ONLY while a process exists |

The job axis decides the bucket when both are present:

| upstream                       | bucket    |
|--------------------------------|-----------|
| `busy`, `working`              | `working` |
| `idle`, `shell`                | `idle`    |
| `waiting`, `blocked`, `failed` | `blocked` |
| `done`                         | `done`    |
| anything else                  | `other`   |

`other` exists so a state added upstream is surfaced rather than
silently dropped from the totals.

**Which records count.** Per [[adr0024]], an agent is running when a
process exists (proven by the presence of `status`) and its job state
is not `done` or `failed`. Everything else is reachable via `--all`.
The `done` bucket therefore only fills under `--all`.

**pi rows' status axis.** A pi row's `state` is the bus's own persisted
job state ([[ft014]]'s `WORKER_STATES`); its `status` is populated from
that same feature's `presence` column — the worker's own self-report of
what it is doing right now, published by the worker and read via
`pi-worker workers`. Unlike a claude row, `status` is never a bucketing
fallback here: `pi-worker workers` always returns a `state` (defaulting
to `"unknown"` rather than omitting it), so there is no "job axis
absent" case the way an interactive claude session has none, and the
bucket comes from `state` alone. `status` is present for visibility
only. Per [[ft014]], the value is the reported state when the reading
is within a 90s freshness bound, `"unknown"` when it is older (or the
clock moved backward), and empty when the worker never published
presence at all.

pi detail rows carry `branch: ""` today — `pi-worker workers` exposes
no branch field, so agent-census has nothing supported to read (its
contract is that one verb and nothing else). Tracked as `dotfiles-ycaz`;
until it lands, a consumer wanting a pi worker's branch has to look
elsewhere.

**Deduplication.** A resumed session appears twice upstream — one live
record plus a historical leftover sharing its `sessionId`. Records are
collapsed on `sessionId`, live twin winning, before counting. Keying on
`name` would be wrong: two genuinely different sessions can share one.

Attribution resolves in order:

1. Agent has a `pid` → walk process ancestors until one matches a tmux
   `pane_pid` → project is that pane's `session_group`. Authoritative,
   and it disambiguates registry paths that collide.
2. Otherwise → longest-prefix match of the agent's `cwd` against the
   [[ft001]] registry, by PATH COMPONENTS rather than string prefix.
3. Tie or no match → the `unknown` row, `cwd` preserved ([[adr0017]]).

An ungrouped tmux session reports an empty `session_group`, so the pane
probe also requests `session_name` and strips a trailing `_<N>`.

The `cwd` path is sound for background agents because
`claude agents --all --json` reports the *origin* project root, not the
isolation worktree.

**The `--if-changed` stamp file.** Two lines: a fingerprint token over
every `sessions/<pid>.json` and `jobs/<id>/state.json` file the `--fast`
probe would read (file count plus max mtime, per account, joined), then
the unix seconds the run happened at. Written **before** the census
runs rather than after, so a run that dies partway through cannot leave
the stamp claiming a state it never actually reported — the cost of
being wrong in that direction is one skipped update, not a badge stuck
claiming a stale state forever. A stamp that is missing, unparseable, or
whose token doesn't match the freshly-computed one means run for real;
so does one whose recorded age is negative (clock stepped backward) or
`>= 30s` (`GATE_MAX_STALE_SEC`) — the ceiling exists because the token
only covers claude's state files, while the output also depends on
tmux panes and the `ft001` registry, so the gate can only ever make an
answer *late*, never permanently wrong.

## components
- `nushell/actions/agent-census` — the action. Probe layer (shells out
  to `claude` per account, `tmux`, `ps`, the [[ft001]] registry) and a
  pure transform layer (`bucket-state`, `build-pane-index`,
  `parse-ps-table`, `dedupe-sessions`, `live-agents`, `resolve-project`,
  `shape-rows`, `detail-rows`). No transform function reaches for the
  world, which is what makes the joins testable.
- `nushell/dot.yaml` — `actions/agent-census: ~/.local/bin/agent-census`
  under the linux section.
- `tests/agent-census/` — 87 cases across four files: `harness.nu`
  (assertions, case runner, fixture loading, stub sandboxes),
  `run-tests.nu` (orchestration + harness self-tests),
  `transform-cases.nu`, `probe-cases.nu`, `cli-cases.nu`. Driven from
  captured fixtures and stub executables on a bare PATH, so the suite
  passes with no tmux server, no claude on PATH and a foreign `$HOME`.
  Fixtures are sanitised; the repository is public.

Consumes the [[ft001]] registry for the `cwd` fallback; reads tmux and
`ps` directly. Holds no state — every invocation is a fresh sample,
costing ~600 ms dominated by one `claude` call per account, run
concurrently.
