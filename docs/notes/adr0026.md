# ADR [[cat001]] [[product]]

## title
AKM lineage is declared by section, never inferred from a prose mention

## context
A spec's story lineage — its source `us###` and consumed `im###` — is declared
in the dedicated `## solves` and `## implements` sections. Every zettel type
also mentions other ids freely in prose, and the survey discipline in
[[idea-feature]] and `spec-writing` actively *requires* it: a feature-add spec
names neighbouring capabilities in `## problem` precisely to record them as
NON-dependencies. [[sp027]] does exactly that with `[[im004]]` and `[[im011]]`.

The archive finale shipped with lineage inference that scanned the whole spec
body for the first `[[us###]]` / `[[im###]]`. The two readings are
indistinguishable at the text level: a wikilink recording "this is not my
dependency" looks identical to one recording "this is my implementation".

The failure was found while archiving [[sp027]] itself. Two modes, one silent:

- One id present in prose → the shape resolves to half-story-backed, and the
  finale refuses to run. Loud, recoverable, blocks delivery.
- Both present → the finale runs on the story-backed path and flips an
  unrelated `us###` to `done` and its `im###` to `accepted`. Silent corruption
  of a third party's lineage, discovered only because a regression test was
  written for the first mode.

The same unsafe extraction was documented for callers in `work-merge`'s Step 4,
so the pattern was being taught, not merely used once.

## decision
Tooling that resolves AKM lineage reads only the sections that declare it —
`## solves` for the source story, `## implements` for the consumed
implementation — and treats every other mention of an id as prose. A wikilink
outside a declaring section never establishes a relationship.

Where lineage is genuinely absent, that absence is the answer: a feature-add
spec has no `us###` and no `im###`, and the correct shape is resolved from its
unique proposed `ft###`. Absent lineage is a shape, not a gap to be filled by
guessing.

This binds any tool that classifies a zettel's lifecycle shape, not only
`archive-epic.sh`.

## consequences
Inference is narrower and can now return nothing where the old scan returned a
wrong answer. That is the intended trade: the failure mode moves from silent
mutation of an unrelated artifact to a fail-closed block the caller can fix by
classifying explicitly.

A spec that neglects to fill `## solves` / `## implements` will be classified
as feature-add and blocked when no unique proposed `ft###` exists. The block is
loud and local to the spec being archived, so the cost lands on the author who
can fix it rather than on an unrelated zettel.

Prose citations are now free. A spec can name any number of `us###` / `im###`
ids to record contrast, prior art, or explicit non-dependencies without
changing how it archives — which is what the survey discipline wanted in the
first place.

The alternative — dropping inference entirely and requiring every caller to
classify — was rejected because the caller doing the classifying is exactly the
grep that got this wrong. Reading the declaring sections puts the answer where
the schema already keeps it.

Regression coverage lives in `work-merge-workspace/test_archive_epic.py`:
a feature-add spec citing both an unrelated `us###` and `im###` must take the
feature path and leave both untouched.
