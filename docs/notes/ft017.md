# Feature [[cat001]] [[cat002]] [[product]]

## providing

One way to start a program in the user's graphical session, used by every
caller - a key binding, `wm-state restore`, a launcher menu, a window
manager's spawn-at - so a process started by restore is indistinguishable
from one started by hand: same parent (the session's reaper), its own
session, no inherited fds, the session's canonical environment, cwd $HOME.
Two entry points (terminal, GUI) over one per-host detach core chosen by
probing: X11 (i3, kwi3-X11) `setsid -f`; KWin/systemd `systemd-run --user
--slice=app.slice`; Windows `Start-Process`. A host with no usable backend
is refused by name, never retried.

## api_surface

```
wm-launch-terminal <term_cmd> [--workspace W] [--session S] [--class C]
    no flags: today's behaviour (focused workspace -> tmux target)
wm-launch-gui <cmd...> [--class C]
wm-launch-detach <argv...>      # the shared core; callers normally use the two above
exit 0 once the child has started; non-zero + named reason otherwise
```

## data_model

Canonical environment per host: X11 - a snapshot written by the session's
start script (xinitrc / kwi3-session-env.sh shape); KWin - systemd user
manager env; Windows - user env. The caller's own environment is not
passed through.

## sample

```
wm-launch-terminal st --session dev --class wm-slot-dev-ed
wm-launch-gui firefox --class Firefox
```

## components

- `~/.dotfiles/nushell/actions/wm-launch-terminal` (extended)
- `~/.dotfiles/nushell/actions/wm-launch-gui` (new)
- `~/.dotfiles/nushell/actions/wm-launch-detach` (new)
