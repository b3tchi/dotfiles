# Spec [[cat001]] [[board]]

## extends [[ft014]]

## problem

[[ft014]] is a star, not a bus. `run/<uid>/{inbox,outbox}` has one privileged
reader: the initiator writes a worker's inbox, the worker writes its outbox,
and `wait --run` hands back "the oldest unacknowledged result across the run",
which only reads correctly because exactly one process ever asks. A result is
owed to "the initiator" — a role, not an address. The Pi extension's inbox
watcher is gated on worker mode (`PI_WORKER_RUN`/`PI_WORKER_UID`, set by
`spawn`), so a worker can be reached and the session driving it cannot. Nothing
can tell an orchestrating session that its worker has reported; it must ask,
and `wait --block` is capped at 60s by design because it runs inside a host
tool call.

The motivating use case is a worker that converses with the human in its own
harness window — brainstorming, design review, anything where the human is the
counterparty — decides for itself that the conversation is finished, and
reports back so the initiating agent runs the next stage. That case needs no
new stage kind: the consumer's stage registry already expresses it as
`isolation: main`. What it needs is for the report to REACH an agent that is
not listening.

The fix is the addressing the Feature's own words already promise — a
transport that "carries any consumer's vocabulary and interprets none of it".
Every agent on the bus is an address. Every envelope carries `from`, `to` and
an opaque `content`. `send` takes `--to`/`--from`; `wait` means "mail addressed
to me" rather than "oldest in the run"; `ack` is per addressee; a request
records a reply-to and the typed result goes there. An agent nobody spawned
self-registers to get the same uid, identity envelope and inbox a spawned
worker gets, which also makes it visible to the observation verbs. The inbox
watcher runs in every session, still idle-gated: a message reaches an `idle`
agent as an ordinary user turn and every other state defers, so the existing
`followUp`/`defer` decision is un-gated rather than rewritten.

Authority does not become symmetric with addressing. `accept` deletes
worktrees and branches, so it stays with whoever ALLOCATED the resource —
ownership, which is mechanism, not "the orchestrator", which is a flow.
Messaging is never lineage-gated. Observation needs no change: `status`,
`inspect`, `workers`, `ps`, `liveness` and `timeline` read the run directory
and are already flat; a self-registered agent is missing from them only
because it has no identity envelope, so fixing identity fixes monitoring.

Flow-agnostic also means evicting the flow vocabulary still living in the
transport, out to the consumer ([[ft013]]): `resume`'s rejection counting and
its `escalate: true` on the second rejection, the `RESERVED_STAGES`
`rejection` entry the bus authors itself, and the stage registry's
`payload: ticket|instructions` gate — a transport that cannot interpret
`content` cannot gate on its shape, so that check belongs to the consumer at
send time. The bus keeps `send`, addressing and the 64 KiB cap.

Two envelope kinds carry peer traffic, and only two. A `message` is
`{from, to, content}` with content opaque. A `result` keeps its typed
`status` / `validation` / `summary` / `session` / `resume` fields, because
[[adr0027]] exists precisely so completion is never read out of prose;
symmetry does not soften it. `error` and `identity` remain bus-authored.
[[adr0028]] is untouched — this is the file bus in both directions, and tmux
still only hosts and displays.

Scope boundaries, decided deliberately:

- The human is NOT an address. The human converses in the Pi harness, at the
  worker's window, as today. A human inbox is future work; `waiting_human`
  keeps its current meaning — the human is needed at a harness, not that mail
  waits for them.
- [[sp025]] agent-inbox stays a separate workstream. Its content is the hard
  prompt instruction that makes an agent ask at all, plus an operator-answerable
  store; that is a different problem from addressing. This bus may later back
  its transport.
- [[ft012]] agent-census is not extended. [[adr0025]] binds it to the supported
  `claude agents --json` surface and Pi workers are not in that population. A
  joint pi+claude view stays out.

Supersession call: [[ft014]] gets a body refresh with a widened
`## api_surface`, not a new `ft###` — one capability, wider surface. `wait`'s
run-scoped semantics change, so consumer skills move with it. There is no
`us###`/`im###` lineage to adjust: ft014 is feature-add lineage ([[adr0026]] —
declared, not inferred), so this spec adjusts the Feature directly.

Deferred to spec-retro: a new `adr####` recording "the bus addresses peers and
encodes no flow", which is the decision this spec acts on.

Known risk to carry into task breakdown, not a design change: two agents each
`wait --block`ing on the other deadlock, survivable only because the block is
bounded at 60s. Category [[cat001]].

## solution

Deliverable is [[ft014]] itself — a body refresh with a widened
`## api_surface`, not a new Feature. No `ft###` is minted and no `us###` /
`im###` lineage is fabricated to fit the story-backed path ([[adr0026]]).
Where this section and `## problem` disagree on shape, this section governs:
the problem sketched per-agent mailboxes with reply-to routing, and the
approach below replaces that with a single thread.

**One bus, one queue per agent.** `<project>/bus/messages/` is a flat set of
messages every participant in the project can read, and each agent has a queue
naming the ones addressed to it. An agent takes what its queue points at, reads
the message and reacts according to its own standing instructions plus that
content. The transport never says what the reaction should be. This is the
shape [[ft014]] already claims for itself — "carries any consumer's
vocabulary and interprets none of it" — carried through to addressing.

**Envelope.** `from`, `to` (a list — one message may address several agents),
and an opaque `content`. Protocol `1 -> 2`, unknown versions still fail
closed. No migration: the bus lives in `$XDG_RUNTIME_DIR`, so the bump costs
at most an in-flight project thread. The 64 KiB cap stays; a message
addresses work and never carries it.

**No sequence, and no ordering to depend on.** A message id is a sortable
timestamp plus a random suffix, so concurrent posters never contend for a
slot: the `link(2)` claim, the "lowest unused slot" rule and the no-gap
`1..n` invariant all retire. There is no total order, and none is needed —
two posts in the same instant are ordered as observed.

**The bus is shared; a queue is not.** The sender resolves `to` once, rather
than every reader re-deriving it on every poll: `<project>/bus/queue/<uid>` is
a file of fixed-width rows, and a row holds a message id and never content. A
sender appends one row per agent it names; the owning agent marks a row read
in place, changing `<id>` to `<id>-read`. Unread is a row with an unmarked
suffix, so `wait --as <uid>` reads one small file of its own and never scans
the log.

Fixed width is what makes both safe at once. An id is a fixed length by
construction and every row reserves a five-byte suffix zone — `-read` once
read, blank until then — so marking is a single same-length write at that
row's own offset, while appends go to the end with `O_APPEND` and disturb
nothing. Many writers therefore need no lock: every sender appends, the owner
overwrites only bytes it already owns. What would be unsafe is
read-modify-writing the whole file, which drops any append that landed in
between; in-place marking of a fixed row does not. It is also why a row
carries an id rather than content.

Fan-out is all-or-nothing without a lock, by ordering: the message is written
to a scratch name, every queue row is appended naming its final id, and the
message is published by a rename LAST. Die anywhere before the rename and
every row names an id that never appears — inert, and ignored by a reader that
finds no message. A published message therefore always has its fan-out
complete behind it.

A row is marked at the moment of the `sendUserMessage` CALL rather than on its
return, the property the bridge already documents: a message delivered but
lost mid-turn counts as read, deliberately, because double-delivery is worse
than a rare loss. A message may be pruned once no queue holds an unmarked row
for it. Rows are read as a set; their order carries nothing, and the whole
project directory is transient runtime state, so growth is bounded by the
session rather than by compaction.

One consequence, accepted: recipients are fixed when a message is sent. An
agent added to a conversation later sees no back-mail and must be re-sent what
it needs. With contacts arriving in instructions rather than from a registry,
that is consistent — there is no late joiner who was expected to catch up.

**Everyone reacts at once.** A message naming three agents wakes all three,
each in its own idle window; nothing in the transport serializes them. Two
agents that were both named may both act — that is what a team thread is for,
and whether a particular kind of work tolerates it is the agents' business,
not the bus's.

**Every agent is an address, including one nobody spawned.** A spawned worker
is handed its uid as today. A session with no `PI_WORKER_UID` takes one for
itself at session start — env cannot be injected into a live session after the
fact, so the session claims its own address rather than being told — and starts
the same watcher and queue. It writes no placement record, because it
placed nothing; its peers learn its address from the instructions it gives them
when it starts them. A CLI verb covers non-Pi peers.

**The thread's scope is the project, and it is derived rather than minted.**
Today a run id is the lowest free `r<n>` at the bus root, minted by an
initiator and handed to every verb — which an agent that claims its own
address cannot be handed. The scope becomes the project: a slug of the
repository, so every agent working on it reaches the same bus, in tmux or
not, without being told an id. It is the MAIN
worktree that names the project, never `git rev-parse --show-toplevel` from
the agent's cwd, because a worker stands in a `wk-*` worktree and that reading
would make every worker its own project; `main-worktree` already resolves it.
The tmux session group is rejected as the key: it is empty outside tmux, and
it falls back to the session NAME, so this repo's per-shell `local_<n>`
sessions would split one project across threads — the exact discovery failure
deriving the id was meant to fix. It stays what it is in [[ft014]] today, a
window-placement input. An agent standing in no repository gets a named
refusal rather than an arbitrary thread.

Two unrelated efforts in one project therefore share a thread. That is
accepted: mentions filter what an agent must react to, and a shared project
thread is the point. Cross-project addressing stays structurally impossible —
one directory per project. The confidentiality boundary is the user account,
not the addressee: one `0700` thread means any agent of this user can read
every message in the project, which is stated rather than implied. Whether
the `--run` flag keeps its name now that its value is a project is a naming
question for spec-refinement, not a shape question.

**Delivery.** The inbox watcher runs in every session, not only in worker
mode, and keeps its conservative shape: a message reaches an `idle` agent as
an ordinary user turn, every other state defers, one message per poll with
the state re-read each time. A mid-turn steer stays unchosen because Pi
cannot confirm one. Being one watcher per session rather than one per worker,
each is bounded per [[adr0014]] — fail fast when the project directory vanishes,
a sleep floor on every iteration, respawn by a timer outside the loop; that
ADR was written for a fork bomb in exactly this shape. Still a file bus in
both directions: tmux hosts and displays and transports nothing
([[adr0028]]).

**Flow lives in what agents say, not in the transport.** The stage registry
retires as a gate. It bought one real property — nothing silently lands in
the operator's shared tree — and that survives as an explicit `spawn
--isolation worktree|main` with no default, refused when absent. The
`payload: ticket|instructions` gate goes (a transport that cannot interpret
`content` cannot gate its shape), and so do `RESERVED_STAGES` and stage names
as transport vocabulary; a stage becomes a label inside `content` if an agent
wants one. `resume` collapses into an ordinary message: its rejection
counting, its `escalate: true` on a second rejection and the escalation to
`waiting_human` are review policy and move to the agents' own instructions
([[ft013]]). `settled` narrows to the commissioned case — an agent spawned to
report a verdict that ends its turn without one still produces a
`protocol_error`, while an uncommissioned peer that finishes a turn is simply
done talking.

**The typed result survives, narrowed.** When an agent claims it completed
commissioned work, the verdict is a typed `status` / `validation` / `summary`
/ `session` / `resume` message kind, never prose ([[adr0027]] binds and is
not softened by symmetry). It is one message kind in the thread rather than
the bus's purpose, and an agent nobody commissioned owes no result. `error`
and `identity` stay bus-authored.

**No address book — contacts come from instructions.** An agent is told who
its contacts are when it is started, so `to` names peers it already knows and
the bus keeps no registry to discover them from. Discovery was the last reason
for a directory of agents on the bus, and it is gone.

**What survives is a placement record, and it is not part of the bus.**
`spawn` places worktrees and branches, and `accept` / `reclaim` DELETE them;
they decide what to delete by asking which trees a live agent still holds.
With no record on disk, an orphaned `wk-*` tree is indistinguishable from one
a working agent is sitting in, and the mistake lands on the destructive side.
So the record survives — uid, Pi session id, cwd, branch and the allocator,
plus `accepted` and `stopped`, which are verdicts about an agent that the
agent cannot write about itself.

It lives under `$XDG_STATE_HOME/pi-worker/<project>/agents/<uid>/`, not beside
the messages, and the move fixes a real gap rather than tidying a directory: a
worktree outlives a login session, while `$XDG_RUNTIME_DIR` is wiped at logout
([[adr0013]] is the precedent for durable state under state-home). Placement
evidence that vanished on logout would leave orphan trees no verb could tell
from occupied ones. It is still written BEFORE the process starts, so a worker
that dies during startup leaves a cwd and a resume command behind.

The rest of the marker table goes with the flow it belonged to. `reopened`
recorded which result a rejection answered and has no writer once `resume` is
an ordinary message; `waiting_human` was review escalation policy, and what
survives is an agent reporting for itself that a human is needed at its
harness. The precedence table shrinks accordingly.

**Authority is resource ownership, never role.** The allocator in that record
is what `accept` / `stop` / `reclaim` check. Messaging is never lineage-gated
and observation stays flat and read-only, which is the [[adr0017]] line: a
peer's observation of another agent never licenses reaping it — only the owner
acts, and only on that agent's own evidence about itself.

**The motivating case, entirely on top.** An agent is spawned with
`--isolation main` and instructions to converse with the human in its own
harness window. The human talks to it there — the human is not an address on
the bus, and `waiting_human` keeps its current meaning of a human being
needed at a harness rather than mail waiting for one. When the agent judges
the conversation finished it posts its typed result naming whoever
commissioned it; that agent's watcher delivers it on its next idle moment,
and it proceeds. No new stage kind, no new channel.

**Deliberately out of scope**, and named so the boundary is a decision rather
than an omission: a human inbox or human bus address (future work);
[[sp025]] agent-inbox, whose content is the hard prompt instruction that
makes an agent ask at all plus an operator-answerable store — a different
problem from addressing, though this bus may later back its transport; and
[[ft012]] agent-census, which [[adr0025]] binds to the supported `claude
agents --json` surface that Pi workers are not part of, so a joint view stays
out.

Implementation stays a nushell CLI plus the Pi extension ([[adr0001]],
[[adr0002]]); nothing here needs a compiled helper. [[ft013]] loses its
stage-registry declaration and its transport-side flow vocabulary, so that
card is refreshed alongside [[ft014]] at retrospective time. Category
[[cat001]].

**Confidence.** No PoC. Idle-gated delivery into a live Pi session is proven
— [[ft014]] records that the bridge has been run against a live Pi
repeatedly and that doing so is what found the delivery defects its surface
now describes, over 339 protocol and 175 bridge cases. One assumption is
untested: injecting a user turn into a session a human is actively typing in.
That is a live-smoke case at task time; only if Pi refuses the injection does
it become a spike.

**Costs accepted.** A sender learns a message went unread only by timing out
— [[ft014]] already lists that gap, and dropping acks makes it structural
rather than accidental. Two agents each blocking on the other still deadlock,
survivable only because the block is bounded. Consumer skills move with
`wait`'s changed semantics and with the evicted flow words.

## plan

### layout

Two trees, deliberately in different lifetimes:

```
$XDG_RUNTIME_DIR/pi-worker/<project>/bus/     # transient, wiped at logout
  messages/<msg-id>              # protocol,id,from,to[],created,content
  queue/<uid>                    # fixed-width rows, one per addressed msg

$XDG_STATE_HOME/pi-worker/<project>/agents/<uid>/   # durable, outlives a login
  identity                       # uid, session, cwd, branch, owner, created
  accepted | stopped             # verdicts granted from outside the agent
```

`<project>` is a slug of the MAIN worktree path. Directories are created
`0700` with `mkdir -m`; message and identity files are `0600` before they are
linked or renamed into place.

A queue row is exactly 32 bytes: a 26-character sortable id, a five-byte
suffix zone (`-read` once read, five spaces until then), and a newline. The
width is load-bearing, not cosmetic — it is what lets an owner mark a row with
one same-length write at a known offset while senders are appending to the
same file.

### files

Paths are relative to `claude/marketplace/plugins/pi-workers/` unless the
row says otherwise.

| path | change |
|---|---|
| `scripts/pi-worker.nu` | bus core, verbs, worktree, placement |
| `scripts/stage-registry.nu` | shrinks to `isolation`, or retires |
| `extensions/pi.ts` | contract, watcher, tools, self-address |
| `extensions/pi.test.ts` | bridge decisions |
| `stages.example.json` | example loses `payload` |
| `install.sh` | module linking if the registry retires |
| repo `tests/pi-worker/*-cases.nu` | every suite except the live pair |
| repo `tests/pi-worker/live-*.nu` + `harness.nu` | live coverage |
| repo `claude/.../infinifu/skills/**` | consumer verbs, instruction |

### conventions

- Nushell for the CLI, bash only where a shell is already the host
  ([[adr0001]], [[adr0002]]); nothing here needs a compiled helper.
- Every verb prints JSON; `wait` prints nothing when there is no mail, so it
  reads correctly in a shell conditional.
- Create-and-rename over mutate everywhere EXCEPT the one deliberate
  exception: marking a fixed-width queue row in place. That exception is
  documented at the write site with the reason (a whole-file rewrite would
  drop a concurrent append).
- A refusal names what is missing and what IS available — the existing habit
  of listing known values rather than only rejecting an unknown one.
- Errors carry the address they concern, so a failure in one project's bus
  cannot be read as another's.

### anti-patterns

- **Read-modify-writing a queue file.** Senders append to it. Read the file,
  edit in memory, write it back and every append between the two vanishes.
  Only same-length in-place marks and appends touch a queue.
- **Publishing a message before its fan-out.** A visible message with rows
  missing is silently undeliverable to whoever was skipped. Rows first,
  publish by rename last.
- **A privileged reader.** Anything shaped like "the oldest unread across the
  project" reintroduces the single-initiator assumption the spec removes.
  Every read is scoped by the reader's own address.
- **tmux as transport** ([[adr0028]]). No `send-keys`, `wait-for` or
  `display-message` carrying a message, a completion signal or coordination
  state; `@pinned` remains the only pane option written.
- **An unbounded reader loop** ([[adr0014]]). One watcher per session
  multiplies the blast radius of the fork-bomb shape that ADR was written
  for: fail fast when the project directory vanishes, a sleep floor on every
  iteration, respawn by a timer outside the loop.
- **Inferring completion.** Not from an idle prompt, an exited pane, or
  assistant prose ([[adr0027]]); a verdict is a typed field or it does not
  exist.
- **Reaping on someone else's evidence** ([[adr0017]]). A peer's observation
  of another agent never licenses stopping, accepting or deleting it.

### known_limitations

- **[[ft014]]'s `## api_surface` contradicts these tasks by design.** The card
  describes the star bus being replaced and is refreshed at `spec-retro`;
  tasks bind to this spec's `## solution`, not to that text. A reviewer
  should not read the mismatch as an ADR or Feature violation.
- **[[ft013]] declares the registry vocabulary** (`isolation`, `payload`), so
  it cannot land after the transport drops the `payload` gate. T8 and T10
  ship together or the consumer's declared surface names a gate that no
  longer exists.
- **[[ft014]] is already `status: accepted`.** `work-merge`'s feature-add
  finale flips a PROPOSED `ft###` to accepted and has no state to flip here.
  `spec-ready` should expect that, rather than a finale inventing lineage.
- **A `wk-*` worktree outlives the v1 bus that recorded it.** Protocol `1 → 2`
  needs no message migration, but placement evidence does, or live trees
  become orphans no verb can distinguish from abandoned ones. T6 carries a
  one-way import.
- **No receipts.** A sender learns a message went unread only by timing out.
  Structural, and already listed on [[ft014]].
- **Recipients are fixed at send time.** Nobody added to a conversation later
  sees back-mail.

#### type

#### effort

#### depends

#### files_touched

#### success_criteria
- `project-dir` resolves to `$XDG_RUNTIME_DIR/pi-worker/<slug>/bus` where
  `<slug>` derives from `main-worktree`, and is byte-identical when called
  from the main worktree and from any `wk-*` worktree of the same repo.

  naming that no project could be resolved; no directory is created.
- `mint-run` and every `--run` parameter are gone from the module's exported

#### edge_cases
- Two worktrees of one repo, and a worktree whose `.git` is a file rather
  than a directory (`git rev-parse --git-common-dir` path).
- A repo path containing spaces, unicode, or a trailing slash — the slug must
  round-trip and must not collide between `/a/b` and `/a-b`.
- `XDG_RUNTIME_DIR` unset (fall back as today) and pointing at a
  non-existent path.
- A submodule and a bare repo, neither of which has a working main worktree.

#### test_plan
- A case asserting the same project dir from main tree and from a `wk-*`
  tree, which is the bug the naive `--show-toplevel` reading would cause.
- A case asserting `/a/b` and `/a-b` slug to different directories.
- A refusal case run with `cd` into `/tmp`, asserting the error text names
  the missing project and that no directory appeared.
- A permissions case asserting `0700` on both created directories.

#### sre
granularity 6h, single module region. implementability paths and function
names named above. success criteria four, measurable, one a `grep` count.
dependencies none. safety: creation modes and the ownership refusal kept;
no destructive path. edge cases enumerated including the worktree reading
that motivated the change. red flags none — no placeholder, no deferred
decision. tests meaningful: each case fails on a specific wrong
implementation (worktree-relative slug, slug collision, silent mkdir).

### Task 2: envelope v2 and message ids
#### type
feature

#### effort
6h

#### depends
Task 1

#### files_touched
- `scripts/pi-worker.nu` (`envelope-for`, `validate-envelope`,
  `validate-inbox-payload`, `validate-result-payload`, `envelope-bytes`,
  new `mint-msg-id`)
- `extensions/pi.ts` (`PROTOCOL_VERSION`, `Envelope`, payload types)
- `extensions/pi.test.ts`
- `tests/pi-worker/schema-cases.nu`

#### success_criteria
- An envelope validates iff it carries `protocol: 2`, a non-empty `from`, a
  `to` list of at least one address, an ISO `created`, and `content`;
  `protocol: 1` is refused with a message naming the version it read.
- `mint-msg-id` returns 26 characters, is lexicographically increasing
  across 10 000 sequential calls, and produces no duplicate in 10 000 calls
  from four concurrent processes.
- `stage` and `task`/`instructions`/`artifacts` payload validation is gone;
  content is validated for size only, refused above 64 KiB with the byte
  count in the message.
- `pi.ts` and the nushell module agree: a test asserts the TypeScript
  `PROTOCOL_VERSION` equals the nushell constant.

#### edge_cases
- `to` containing the sender's own address (legal — an agent may address
  itself), duplicates in `to` (deduplicated, not refused), and an empty `to`
  (refused).
- Content that is valid UTF-8 but 64 KiB + 1 byte, and content that is
  exactly 64 KiB.
- Multibyte content where byte length and character count differ — the cap
  is bytes.
- A clock that steps backwards between two id mints (ids must still be
  unique; ordering is best-effort and documented as such).

#### test_plan
- Property case: 10 000 mints sorted equal the mint order.
- Concurrency case: four `nu` processes mint 2 500 ids each into one
  directory; assert 10 000 distinct.
- Boundary pair at exactly 64 KiB and one byte over, asserting the accepted
  one and the refusal text.
- A cross-language constant case so the two halves cannot drift silently.

#### sre
granularity 6h. implementability: functions and constants named. success
criteria four, each with a number. dependencies Task 1 for paths. safety:
fail-closed on unknown protocol preserved; cap enforced in bytes. edge cases
cover collision, clock regression, and the byte/char distinction. red flags
none. tests meaningful: the concurrency and clock cases fail on a
timestamp-only id, which is the likely wrong implementation.

### Task 3: publish and fan-out ordering
#### type
feature

#### effort
8h

#### depends
Task 2

#### files_touched
- `scripts/pi-worker.nu` (`bus-send` rewritten, `claim-slot` and
  `next-sequence` removed, new `queue-append`)
- `tests/pi-worker/bus-cases.nu`

#### success_criteria
- `send --to a --to b --content <text>` leaves exactly one file in
  `bus/messages/` and one 32-byte row in each of `bus/queue/a` and
  `bus/queue/b`, and the message file's mtime is later than both rows'
  append.
- Interrupting the sender after the rows are written but before the rename
  (fault injected by the test harness) leaves no message in
  `bus/messages/`, and a reader finds rows naming an id that does not
  resolve and reports zero mail rather than erroring.
- Two senders addressing the same recipient concurrently (50 messages each)
  produce 100 well-formed 32-byte rows, no interleaved or truncated row, and
  100 resolvable messages.
- `claim-slot`, `next-sequence` and the no-gap sequence invariant are gone
  from the module.

#### edge_cases
- A recipient whose queue file does not exist yet (created `0600` on first
  append) and one whose queue is a dangling symlink (refused).
- A recipient address that no agent ever claims — the row is written and
  simply never read; sending must not require the recipient to exist.
- Disk full mid-append: the row is partially written. Reader must skip a row
  that is not exactly 32 bytes rather than misparse the next one.
