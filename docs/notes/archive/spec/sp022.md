# Spec [[cat001]] [[cat002]] [[board]]

## problem

[[ft005]]'s display half is a browser. `preview-wv` ([[sp013]]) is a
chrome-less Rust wry/WebKitGTK window loading `/preview<N>`, so every
content type reaches the screen as HTML: an image is an `<img>`, markdown
is goldmark output, code is chroma output, a `.d2` board is a cross-origin
iframe of d2-router. The engine is the cost — [[poc007]] measured 196 MiB
for the first window and ~110 MiB per added one, to show a PNG — against
~155 MiB for a *shared* Qt Quick native runtime. poc007's own
`## recommendation` said so explicitly ("one REUSED webview + Qt Quick
NATIVE renderers ... reserve the web engine only for real HTML"); sp013
built the wry host instead and [[adr0008]] minted a Rust-only-bindings
exception to justify it.

Three years of workaround has accreted around that engine choice. The
wrapper's whole docking design — `prepare-split`, `wait-preview-mapped`,
`finalize-dock`, and `main-show`'s refusal to re-dock a live window —
exists for one reason: a mapped wry window self-closes when i3 reparents
it (dotfiles-bfk, verified on xrdp's GL-limited Xorg). So the wrapper sets
the split *before* the window maps and reorders by moving the launching
terminal, never the webview. `preview-wv` itself carries forced
`GDK_BACKEND=x11`, a raw `XSetClassHint` call to defeat GTK's WM_CLASS
capitalization, and `/proc` Xorg-cmdline scraping to force software GL on
xorgxrdp. Open bugs `dotfiles-38m` (idle death) and `dotfiles-qdl` (WSL
sway `xwayland disable` blocks the forced-X11 window outright) are both
host bugs.

Meanwhile `d2-view` (commits 16d5867, bfb4f02, b1d5b1b) shipped a native
QML viewer — QtSvg + `Image`, pan/zoom, live reload, board tab bar — that
renders 7000px d2 boards better than preview's iframe does. It is a
second, overlapping preview path.

**Entry type.** Feature-side extension of [[ft005]], no backing `us###` —
the [[sp013]] precedent (the base feature entered as sp008, a feature-add
spec). No `im###` exists for this lineage. [[ft005]] gets a body refresh
at spec-retro, not supersession: the capability is unchanged, its display
half is replaced.

**Measured at idea stage** (live xrdp `:10`, the display where wry's death
is verified). A `qml6` `ApplicationWindow` survived every reparent that
kills wry — split + sibling open, `move up`, `move right` + split,
floating enable/disable, cross-workspace move — same window id
throughout, process alive, empty log. Also: `WM_CLASS(STRING) = "qml6",
"Qml Runtime"` (collides with d2-view), `WM_NAME = "preview 1"`
reliable, `xdotool search --pid` exact. Recorded as
[[poc016|qml-window-survives-i3-reparent]], because an uncited
engine-behavior claim is exactly what forced [[adr0009]] to supersede
[[adr0006]].

**Shape (approved at idea stage).**

*Tiers.* `preview-d` broadcasts `{path, type}` instead of a bare "redraw";
a QML `Loader` picks the delegate. Type selection stays server-side in
`render.go` where its tests live — only painting moves to QML. Native:
`image` (`Image`), `svg` (`Image` + QtSvg — `.d2` resolves to svg via a
new raw-svg route on [[ft002]], see `## solution`), `md`
(`Text.MarkdownText`), `code` (`Text` + chroma spans), `video`
(ffmpeg poster, already a PNG). Web tier via a lazily-instantiated
`WebEngineView`: `html`, `akm` (the [[ft004]] graph embed), `stl`. The
web engine must live *inside* the QML process — the requirement is that
hovering across type boundaries swaps content in ONE window with no
open/close, so a separate on-demand web window is disqualified.

*Live type-swap* is the existing `/preview<N>` slot contract and must
survive intact: `POST /preview<N> {path}` → ws push → delegate swap, no
process respawn, no engine reload.

*Process shape.* One `qml6 PreviewView.qml -- <N> <port>` per slot,
mirroring today's one-process-per-window contract; the wrapper's
pidfile / idempotence / `--close` discipline keeps its shape. Deferred: a
single process hosting N windows (saves ~155 MiB per extra window, needs
an IPC add/remove surface — the quickshell `IpcHandler` + `qs-*.sh`
pattern already in the repo). Windows are ~1 in practice.

*Identity.* No `for_window` rule for preview exists in `i3/` or `sway/`,
so the `qml6` / `Qml Runtime` class collision costs nothing externally.
Internal matching moves to `_NET_WM_PID`: `wait-preview-mapped` uses
`xdotool search --pid` (the current class match is commented as flaky),
and `pid-cmdline-matches`' needle becomes `PreviewView.qml` **plus the
slot number** — closing a latent bug where today's bare `preview-wv`
needle lets slot 1's pidfile validate against a recycled pid that is
slot 2's live window.

*Docking collapse.* With reparent survival proven, `prepare-split`,
`wait-preview-mapped`'s class poll, `finalize-dock`'s move-the-terminal
inversion, and `main-show`'s fresh-window-only guard all delete: spawn →
resolve by pid → move the preview window into place, ordinary i3. A
capability arrives free — **re-docking a live window**, so `preview show`
picks dock direction from each image's shape instead of only the first
(today's README limitation).

**Deleted.** `preview-webview/` (Rust crate, 658 lines) · `proxy.go`'s d2
half + `/d2embed/` · `static/shell.html` + `static/app.js` (the ws shell
moves into QML). **Kept.** `stl-viewer.js`, the [[ft004]] akm iframe,
`/file/<path>` as both the web tier's source and the browser fallback,
the path jail, the slot registry, and the [[adr0007]] server-side
reverse-open / highlight channel.

**ADR fallout.** [[adr0008]] is retired outright — `preview-wv` was the
repo's only Rust helper, so the Rust-only-bindings exception loses its
subject; [[adr0003]]'s Go mandate stands unqualified again. [[adr0009]]
narrows to "peers embed inside the web tier only". A new `adr####`
records Qt Quick / QML as [[ft005]]'s native client host with the web
engine as a reserved tier — an extension of the [[adr0015]] family rather
than a replacement for [[adr0008]] (see `## solution`), and poc007's
recommendation taken three specs late. All three land at spec-retro, not
now.

**Dependency cost.** `qt6-base`, `qt6-declarative`, `qt6-svg` and `qml6`
are already installed. `qt6-webengine` is not: 94.5 MiB download /
282 MiB installed from `extra`. It lands only on hosts that opt into
preview — `preview` and `preview-webview` appear in no meta-package, so
this is not a cost every platform pays. ARM is covered:
`qt6-webengine 6.11.1-4` exists in Arch Linux ARM `extra` for `aarch64`
(272 MiB installed), so proot is not blocked. Measured cost of the tier
when it instantiates: **~240 MiB** PSS over an engine-less QML window
(265 MiB settled vs 25 MiB, [[poc018]]). [[poc017]] first reported ~390 MiB
here; that figure double-counted Chromium's helper processes and is
corrected in place.

**Side-effect closures.** The wry host bugs `dotfiles-38m` (idle death)
and `dotfiles-qdl` (sway xwayland) die with their host. `dotfiles-eq8`
(previewing a `.d2` writes an untracked sibling `.svg` into the repo) is a
*candidate* closure, not a claimed one: on the [[ft002]] raw-svg route
preview-d writes no file at all, so the bug closes only if preview-d was
the writer — `d2 --watch` serves over HTTP without writing, so the actual
writer must be identified at spec-refinement before this is claimed.

**Out of scope.** Live video playback (`qt6-multimedia`, not installed —
poster-only ships, the rest is filed). Merging `d2-view` into preview:
the two should share ONE QtSvg pan/zoom QML component or they will drift,
but d2-view keeps its own multi-board tab UX and stays its own tool;
`d2-view/` also has no `dot.yaml`, leaving its `qt6-svg` dependency
undeclared (same shape as `dotfiles-d59`) — both filed, not solved here.
The single-process multi-window sharing described above.

## solution

Replace [[ft005]]'s display half with a **native Qt Quick client, web
engine demoted to a reserved tier**, keeping the daemon as the brain and
the nushell wrapper as the only API ([[adr0001]]).

`preview-d` keeps every job that isn't painting: the path jail, the slot
registry, renderer *selection* in `render.go`, and the [[adr0007]]
server-side reverse-open + `/api/highlight` channel. Its one contract
change is that the `/preview<N>` websocket broadcast carries
`{path, type}` instead of a bare redraw, so the client can pick a
delegate without re-fetching HTML. The live-slot semantics are unchanged
and binding: a cursor move across a type boundary swaps the delegate
inside one window — no process respawn, no engine reload.

The client becomes `PreviewView.qml` under `qml6`, one process per slot.
Native delegates cover `image`, `svg`, `md`, `code` and video-poster on
modules already installed (`qt6-base` / `qt6-declarative` / `qt6-svg`); a
lazily-instantiated `WebEngineView` covers `html`, `akm` and `stl`, which
is where [[adr0009]] survives in narrowed form — [[ft004]] stays a
cross-origin iframe, but only inside that tier. `.d2` leaves the iframe
path for native QtSvg, fed by a new raw-svg route on [[ft002]] so
d2-router's child / watch / recompile machinery is reused rather than
duplicated; [[ft005]]'s `depends_on` on both peers stays intact.

Language: the client is neither compiled nor a daemon, so [[adr0003]]
does not bind it. It lands as an extension of the [[adr0015]] family — an
allowed non-default language justified by an ecosystem binding with
working prior art here (`d2-view`, `quickshell`) — which makes
[[adr0008]]'s Rust-only-bindings exception subjectless once `preview-wv`
is gone, since it was the repo's only Rust helper. Under [[cat002]],
[[adr0005]] and [[adr0004]]'s llvmpipe reality bind rendering too: the
client selects `QT_QUICK_BACKEND=software` on xorgxrdp displays,
mirroring `qs-screenshot.sh`.

The workaround payoff is measured, not assumed: [[poc016]] confirmed a Qt
Quick window survives every i3 reparent that kills wry, on the same xrdp
display where that death was verified, so the wrapper's split-before-map
docking edifice deletes and live re-docking becomes possible. The web
tier's load-bearing assumption is measured too:
[[poc017|webengineview-survives-i3-reparent]] put a live `WebEngineView`
with an actively animating Chromium compositor through the identical
sequence and it survived in both the software and default Qt Quick
backends — its `status: invalidated` refers to its hypothesis (that the
hazard *would* return), which is the outcome this spec needs. So the wry
hazard is specific to WebKitGTK/wry, not to "a web engine on xorgxrdp",
and the in-process web tier stands as specified. `QT_QUICK_BACKEND=software`
is consequently prudent under [[adr0005]] for render cost, not required for
window survival.
Trade-offs accepted: `qt6-webengine` is a 282 MiB dependency on hosts
that opt into preview (it is in no meta-package), [[poc007]]'s heaviest
engine on the three types that need it; live video playback and
single-process multi-window sharing are deferred.

The taxonomy holds without change: the daemon/wrapper half sits under
[[cat001]] workflow-tooling, the display-host half under [[cat002]]
display-platform — the same pair [[sp013]] carried.

## plan

**Refinement findings** (verified during this pass, binding on tasks):

- **dotfiles-eq8 writer identified — it is the `d2 --watch` child.** A live
  run (`d2 --watch --browser 0 --host 127.0.0.1 --port 4999 test.d2`, the
  exact arg vector `d2/router/children.go` `spawnLocked` uses) writes a
  sibling `test.svg` and logs "successfully compiled test.d2 to test.svg".
  preview-d writes nothing. So the raw-svg route ALONE does not close eq8 —
  the child spawn must also gain an explicit output path outside the repo
  (Task 1). The child serves the compiled svg over HTTP at `/<basename>.svg`
  (probed live: 200), which is what the new [[ft002]] route fronts.
- **`qt6-websockets` is a new dependency** (112 KiB dl / 441 KiB installed,
  `extra`): the QML client must subscribe to the `/preview<N>` websocket to
  receive the `{path, type}` push, and pure QML has no other ws client. The
  solution's dependency list missed it; it rides the same "hosts that opt
  into preview" boundary as `qt6-webengine`.
- **`qt6-webengine` is already installed on this host** (6.11.1-4, left by
  [[poc017]]) — Task 5's dot.yaml declaration is still required so fresh
  hosts get it.
- **The `QT_QUICK_BACKEND=software` precedent is `i3/config-xrdp`** (the
  quickshell `$qsenv` line), not qs-screenshot.sh as `## solution` cites; the
  per-display xorgxrdp *detection* precedent is `preview-webview/src/main.rs`
  `is_xrdp_display` (/proc Xorg-cmdline scrape, exact `:N` token match,
  dotfiles-49j). Task 6 ports that detection to the wrapper, since QML cannot
  set its own env before engine init.
- **chroma emits class-based HTML today** (`WithClasses(true)`,
  `render_code.go`) — Qt rich text cannot resolve CSS classes, so the code
  tier needs a new inline-styles fragment mode (Task 3).

**AC substitute (no-story shape).** This spec has no `## solves [[us###]]`
— the [[sp013]] precedent. Every task's `#### success_criteria` binds to
(a) [[ft005]]'s `## api_surface` rows it touches, and (b) the hard
requirement from `## problem`: a cursor move across a content-type boundary
swaps the rendered content inside ONE window with no process respawn and no
engine reload.

**Conventions.**

- The wrapper is the only entry point ([[adr0001]]); `qml6` is invoked
  solely by `nushell/actions/preview` (the `d2-view` wrapper precedent).
  The daemon stays Go ([[adr0003]]); the QML client is neither compiled nor
  a daemon and lands under the [[adr0015]] family (ecosystem binding with
  in-repo prior art: `d2-view/BoardView.qml`, quickshell).
- Type selection stays server-side in `render.go` where its tests live;
  QML only paints. One process per slot: `qml6 …/PreviewView.qml -- <N>
  <port>`, title `preview <N>`, pidfile `~/.cache/preview/wv-<N>.pid`, log
  `wv-<N>.log` (unchanged wrapper-owned lifecycle, [[ft005]] data_model).
- Window identity is `_NET_WM_PID`, never WM_CLASS ([[poc016]]: class is
  `qml6`/`Qml Runtime`, runtime-derived, collides with d2-view). i3 resolves
  via `xdotool search --pid`; sway uses native `[pid=N]` criteria.
- Client QML source lives in-repo at `preview/qml/` and is run from the
  checkout (d2-view precedent — no build, no install step; the wrapper
  resolves the path via `akm-root` with a `~/.dotfiles` fallback, the same
  chain `preview/dot.yaml` uses).
- Pan/zoom is modeled on `d2-view/BoardView.qml` (Image + `sourceSize`
  rasterization, DragHandler/WheelHandler, `0`/`f` keys). The shared-
  component extraction stays filed, not done here (`## problem` out-of-scope).
- Go tests follow the existing table/fake patterns (`preview/*_test.go`,
  `d2/router/*_test.go` fake-child helper); wrapper tests extend
  `nushell/actions/preview-test`'s fake-binary temp-PATH pattern.

**Anti-patterns (ship-blockers).**

- Never SIGTERM a pidfile pid without `/proc/<pid>/cmdline` verification —
  and the new needle must be an exact-argument match: split cmdline on NUL,
  require an element ending `PreviewView.qml` AND an element exactly `<N>`.
  A substring slot match is the latent bug this spec closes (slot `2` is a
  substring of port `4200`).
- No raw client input reaches disk I/O or a subprocess unvalidated — every
  new route (`?native`, `/api/svg`) goes through the existing jail
  (`resolveInRoot` / the registry prefix match) BEFORE any read.
- No panic / no 500 for a problem with the file itself (render.go idiom);
  no unbounded waits — every relay/poll/health probe carries a timeout
  (scoped `http.Client`, the [[adr0007]] discipline).
- Never `GALLIUM_DRIVER=d3d12` anywhere ([[adr0005]]); on xorgxrdp displays
  the wrapper sets `QT_QUICK_BACKEND=software` + `LIBGL_ALWAYS_SOFTWARE=1`
  (prudent per [[poc017]], not load-bearing for survival).
- No consumer calls `qml6`, `preview-d` or the ft002 route directly — the
  wrapper and preview-d are the only clients ([[adr0001]] / [[adr0003]]).
- Do not delete the wry host or its workarounds before the QML client's E2E
  pass (Task 9 gates Task 8's merge order is the reverse: deletion lands in
  Task 8, E2E in Task 9 — Task 8 must therefore keep a revert path: single
  commit, no interleaved refactors).

**Known limitations.** Live video playback stays poster-only
(`qt6-multimedia` not installed — filed, out of scope). Single-process
multi-window sharing deferred (out of scope). sway/Wayland reparent
survival is untested by [[poc016]]/[[poc017]] (X11/i3 only) — Task 9 runs
the WSL sway check; native Wayland Qt removes the forced-X11 constraint
that made dotfiles-qdl, but this is verified, not assumed. The web tier
costs ~240 MiB PSS when instantiated ([[poc018]]) — accepted trade-off.
Qt rich text's HTML subset may render chroma colors imperfectly; the code
tier degrades to readable monospace text, never worse.

#### success_criteria
- `GET /api/svg?path=<abs>` returns the current compiled SVG bytes as
  `image/svg+xml` for a registered `.d2` path, lazy-spawning the child if
  needed — same 400-on-relative / 404-outside-registry semantics as

  writer evidence in `## plan`).

  duplicated — the `## solution` requirement).
- Existing d2-router behavior unchanged: page route, `/watch` ws proxy,
  `/api/resolve`, idle reaper — full existing test suite still green.

#### edge_cases
Child compiled nothing yet (first hit races the initial compile) → bounded
retry/poll before 200, 503 after the deadline, never a hang. d2 compile
error → the route serves the last good svg if one exists, else 503 with the
child's lastError text. Verify the child still serves `/<basename>.svg`
when the output arg is an absolute path elsewhere — if it does not, the
router reads the cache-dir output file directly (fallback mechanism, same
contract). Cache dir missing → created on spawn. Path with spaces →
url-encoded query handled. Registry project removed while child runs →
404 on next fetch, child reaped normally.

#### test_plan
Extend the fake-child helper suite: spawn-args test asserts the explicit
output path is present and repo-sibling write is gone (tmpdir project,
assert no `*.svg` beside the source). Route tests: registered path → 200 +
`image/svg+xml` + expected bytes; relative path → 400; outside registry →
404; wrong method → 405. Recompile test: touch source → fake child updates
its svg → route returns new bytes. Manual: live `d2-router`, real board,
`curl /api/svg` twice around an edit.
