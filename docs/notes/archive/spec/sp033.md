# Spec [[cat001]] [[cat002]] [[board]]

## extends [[ft016]]

## problem
[[ft016]] renders the bus and never writes to it. That was the right shape
while every party on the bus was a process someone spawned — a display cannot
usefully reply on behalf of a worker. It stopped being the right shape the
moment a PERSON became a first-class party: `pi-worker register` (dotfiles-btkt.1)
mints an address with `kind: person`, and a human now receives mail that only
they can answer.

Proven live on 2026-09-18: a spawned Pi worker asked a question of the label
`jan`, jan answered, and the worker relayed the answer to its commissioner with
honest validation. Every leg of that exchange was typed at a shell.
[[ft016]] was open on the same bus throughout and could show the conversation
while being able to do nothing about it.

Four gaps, all of them in the SHELL rather than in what is read. No new data
source appears here: the roster still comes from [[ft012]] and the log from
[[ft014]]'s `messages` verb, and this spec computes neither.

**The monitor does not know who is watching it.** Its only flag is
`--project`. Nothing addressed to the operator can be distinguished from
pipeline chatter, because the operator is not a concept the binary holds.
Identity is taken from the OS user: `pi-worker register` defaults its label to
`whoami`, and the monitor is you when exactly one party has `kind: person`
under that label. Absent that party you never registered, and the two
capabilities below are absent with an honest reason rather than inferred from
a registry that cannot prove identity anyway (dotfiles-btkt.4, and [[adr0017]]
on absent evidence). `--as <label>` stays as the escape hatch for a bus label
that deliberately is not the username.

**Mail addressed to you arrives silently.** A Pi session gets pushed delivery
(`createBusWatcher` injects each envelope into the live agent); a person gets
nothing. [[sp032]]'s `+N new` counter is the closest thing and it counts ALL
arrivals past the cursor, so on a busy bus it says nothing about you. A second,
narrower count — envelopes whose `to` carries your address — renders as a
marker on the row and `N for you` in the pane header. Deliberately in-TUI only:
the terminal bell and a desktop notification through [[ft010]] were both
considered and declined for now.

**The pane cannot be filtered to you.** `FilterMessages` matches `From` alone,
so filtering by a name hides every message addressed TO it — filed as
`dotfiles-1xfo` and subsumed here, since a to-me view is precisely the match
that bug makes impossible.

**The newest message is the furthest away.** The log renders oldest-first,
which is right for a transcript and wrong for a mailbox. The pane flips to
newest-first, and [[sp032]]'s tail-follow inverts with it: a session opens
parked on row 0, `Home`/`g` becomes the return to live, and the new-arrival
counts sit above the cursor rather than below it. This is the expensive item —
every live/scroll invariant sp032 pinned is restated, and the tests pinning
them are rewritten, not merely extended.

**Nothing can be answered.** `a` on the selected envelope opens a composer
below the detail pane; `ctrl+s` sends, `esc` abandons. The reply is addressed
to the selected envelope's `from` ADDRESS and never to its re-resolved label,
because a label two parties share is the one thing resolution correctly
refuses to answer ([[adr0034]]). The body travels opaque — the monitor formats
what it displays and interprets nothing it sends ([[adr0031]]) — as
`kind: message`, whose content is a JSON string by rule ([[adr0032]]).
Composition is in-TUI; handing the buffer to `$EDITOR` is wanted later and is
deliberately out of scope here.

This makes [[ft016]] read-write, so the card's `Read-only: no verb reaches a
worker` is restated rather than dropped. Its stated justification is
destructiveness — `resume` / `stop` / `accept` destroy worktrees, branches and
addresses, and stay with whoever allocated them. `send` destroys nothing and
creates no ownership, so the boundary that always mattered is the one the card
should name: no DESTRUCTIVE verb reaches a worker.

Constraints carried in from the survey: [[adr0030]] admits Go for this TUI on
merits that a composer leaves intact (a foreground process a human starts and
quits, not an unattended daemon); [[adr0014]]'s three reader-loop guards bound
the sampling loops and are not relaxed for a write path; [[cat001]] and
[[cat002]] are the categories [[ft016]] already lives in, unchanged by this
widening.

Consumed features: [[ft012]] is untouched — no roster source changes here.
[[ft014]] IS widened, which this problem first recorded as "none" and the
solution survey disproved: `bus-messages` projects `from`/`to` through
`render-address`, so `messages --json` publishes rendered labels and the
minted addresses never leave the nu side. A reply must be addressed to the
selected envelope's address rather than to a re-resolved label ([[adr0034]]),
so the projection has to carry both.

## solution
Three additive widenings of [[ft014]] on the nu side, and one shell change in
[[ft016]] on the Go side. No new transport, no second copy of the bus layout.

**[[ft014]] publishes what a writer needs.** `messages --json` rows gain
`from_address` and `to_addresses` beside the existing rendered `from`/`to`;
nothing existing changes shape, so every current reader is unaffected. This is
what makes an exact reply possible at all — [[adr0034]] mints addresses and
makes labels a display concern, and `render-address` had already spent the
address by the time a consumer saw the row. A new read verb, `whoami --json`,
answers which party is the current OS user: the registry lookup lives in the
module that owns the registry, so [[ft016]] never re-derives the bus layout in
Go. That duplication is not hypothetical — `dotfiles-3yg4` is the same plugin
paying for a second copy of the runtime layout written in another language,
and the static case pinning `workerInboxDir` against `runs-root` exists
because of it. Finally `register --label` defaults to the OS username, which
is what makes "your label is your username" a property of the system rather
than a convention the operator has to keep.

**[[ft016]] gains an identity, a signal, a filter, an order and a composer.**
Identity comes from `whoami --json` once at startup; absent a `kind: person`
party under that name, the two new capabilities are absent and say why, per
[[adr0017]] — an unregistered operator is an observation, not licence to guess
which party is watching. The for-me signal counts envelopes whose
`to_addresses` carry that address — identity, not a label match — and renders
as a row marker plus `N for you` in the pane header, kept separate from
[[sp032]]'s `+N new`, which counts every arrival past the cursor and so says
nothing about the operator on a busy bus. The filter extends `FilterMessages`
to match `To` as well as `From`, which is `dotfiles-1xfo` and is the match a
to-me view is impossible without. The order flips to newest-first, inverting
[[sp032]]'s live-end from tail to head across `messagesLive`,
`OpenMessagesAtTail`, `deriveScroll` and the pending counts — the expensive
item, and the one whose existing tests are rewritten rather than extended.

**The composer is a second editing mode, not a widget.** `keys.go`'s filter
draft is hand-rolled inside a pure model with no framework imports, which is
precisely why it is testable without a terminal; a `bubbles` textarea would
move editing into a widget and out of that model. The reply draft follows the
same idiom, multi-line, with the paging keys swallowed for the same reason
[[sp032]] named them explicitly. Sending shells out to `pi-worker send`, the
same mechanism `messages.go` already uses to read, dispatched off the render
path as a `tea.Cmd` so that [[adr0014]]'s three reader-loop guards are neither
relaxed nor re-implemented, and a refused send is reported in the view rather
than swallowed. The body travels opaque — the monitor formats what it
displays and interprets nothing it sends ([[adr0031]]) — as `kind: message`,
whose content is a JSON string by rule ([[adr0032]]). [[adr0030]]'s merits for
Go here are untouched: still a foreground process a human starts and quits.

**The stance [[ft016]] has to restate.** Its card says `Read-only: no verb
reaches a worker` and justifies it by what `resume` / `stop` / `accept` do —
they destroy worktrees, branches and addresses, and belong to whoever
allocated them. `send` destroys nothing and allocates nothing, so the line is
rewritten at retro to name the boundary that always carried it: no DESTRUCTIVE
verb reaches a worker. The categories are unchanged: [[cat001]] and
[[cat002]], as [[ft016]] already carries.

Deferred, deliberately and recorded so they are not rediscovered as gaps:
handing the draft to `$EDITOR`, the terminal bell, and a desktop notification
through [[ft010]]. The unauthenticated `--as` (`dotfiles-btkt.4`) is not
touched here — this spec gives the operator a writer, not a stronger identity
claim than the CLI already offers.

## plan

Two halves that can ship independently, and the split is deliberate: T1–T7
give the operator an INBOX (they see what is addressed to them), T8–T10 give
them a REPLY. Everything through T7 leaves [[ft016]] read-only and its card's
current wording true; only T9 makes the binary write to the bus.

### conventions

- **The registry is read in nu, never in Go.** Identity comes from
  `pi-worker whoami --json` and addresses from `pi-worker messages --json`.
  `agent-monitor` never opens `$XDG_RUNTIME_DIR/.../addresses/` itself. This is
  not style: `dotfiles-3yg4` is this plugin paying for a second copy of the
  bus layout written in another language, and `static/the-extension-watches-
  the-inbox-the-bus-writes-to` exists to stop it recurring.
- **Addresses identify, labels display.** Every comparison ("is this mine",
  "who am I replying to") uses an address; every string a human reads is the
  rendered label ([[adr0034]]). A task that compares labels to decide
  something has the wrong field.
- **Every new key goes through `Model`, not through `Update`.** [[sp032]]'s
  rule, unchanged: `Update` maps a `tea.KeyMsg` onto a method and does nothing
  else, which is what keeps the whole key surface testable without a
  `tea.Program`.
- **The reply key is `a`, for answer.** `r`/`R` is force-refresh, in
  [[ft016]]'s key table and at `keys.go:887`; this spec first wrote `r` for
  reply and collided with it. Caught during T8 (2026-09-19) and decided by
  jan: refresh keeps `r`, the composer takes the unbound `a`.
- **The composer is a mode on the pure model.** It follows `handleEditingKey`'s
  existing idiom — an `Editing`-style flag plus a draft the model owns — so it
  stays unit-testable. No `bubbles/textarea`; `viewport` remains the only
  widget in the binary, and only for the detail pane.
- **Additive projection.** T1 adds fields to `messages --json` rows and changes
  none, so `agent-monitor`'s current parse, `render/log.go` and every existing
  case keep working against the same JSON.
- **Silence and absence are answers.** `whoami` on an unregistered user exits 0
  saying so; it does not guess which party is the human ([[adr0017]]).

### anti-patterns

- **Do not resolve a label to an address on the reply path.** The address is in
  the envelope by T1; re-resolving is precisely what `to-address` refuses when
  two parties share a label, and routing a reply to "whichever matched" is the
  misdelivery [[adr0034]] exists to make unrepresentable.
- **Do not infer the operator from the registry** — "the only `kind: person`
  party" is a guess dressed as a lookup, and `dotfiles-btkt.4` is the open
  question of whether `--as` proves anything at all. `whoami` answers about the
  OS user or says nothing.
- **Do not fold `N for you` into [[sp032]]'s `+N new`.** They count different
  things: one is "arrivals past your cursor", the other is "addressed to you".
  Collapsing them loses the signal on exactly the busy bus that motivated it.
- **Do not parse a reply body anywhere.** The composer's draft travels opaque
  ([[adr0031]]); the monitor formats what it DISPLAYS and interprets nothing it
  SENDS. No templating, no auto-quoting the original, no JSON wrapping.
- **Do not send from the render path or from a sampler.** T9 dispatches a
  `tea.Cmd`; a blocking exec inside `Update` freezes the UI, and a send inside
  `RunMessagesLoop` would put a writer inside a guarded reader loop
  ([[adr0014]]).
- **Do not let a failed send look like a sent one.** A non-zero exit from
  `pi-worker send` is reported in the view with its stderr; swallowing it is
  the silent-grave class this bus has already paid for twice
  (`dotfiles-oj4c`, `dotfiles-9oa4`).
- **Do not preserve oldest-first behind a flag in T6.** The order flips; a
  hidden second order means every live/scroll invariant has two spellings and
  the tests stop pinning either.

### known limitations

- **[[ft014]]'s card is already stale before this spec touches it.** It says
  "Nineteen verbs in four groups" and lists none of `register` / `unregister`,
  shipped in `98d52d8e` outside the lifecycle. T2 adds a twentieth-plus verb.
  The retro owes the card both corrections, not just this spec's.
- **`whoami` binds an operator's bus identity to their OS username.** Two
  humans sharing one Unix account are one party to this monitor. Accepted:
  every other party on this bus is scoped to one machine and one user already.
- **The reply proves nothing about who sent it.** `--as` remains an
  unauthenticated string (`dotfiles-btkt.4`); this spec gives the operator a
  writer, not a stronger claim. A worker cannot distinguish a reply the human
  typed from one an agent typed on their behalf.
- **T6 rewrites tests rather than extending them.** Every [[sp032]] case that
  encodes "live means the cursor is on the LAST row" is restated for the head.
  That is the cost of one order, accepted in `## solution`.

#### success_criteria

- A sample that appends nothing: the count is unchanged, not reset.

#### success_criteria
1. A row is FOR YOU when its `to_addresses` contains the resolved identity's
   address — an address comparison, never a label one.
2. The pane header carries `N for you` when N is positive, where N counts
   unread-by-position rows: those for you that arrived while the pane was not
   live, reset by the same return-to-live that zeroes `+N new`.
3. Both segments can be present at once and read distinctly; the header is
   byte-identical to T6's when both are zero.
4. Every for-you row carries a marker, whether or not the pane is live, so the
   conversation is findable after the count has been cleared.
5. No identity (T4 criterion 3): no marker, no segment, header byte-identical

  unregistered and registered again): not yours — the address changed, which is
  the point of minting per session.
- The count's width against the header's budget, with `+N new` also present.
- A for-you row that is filtered out: not counted, since the count describes
  the list on screen.

### Task 8: the composer, as a mode on the pure model

#### type
feature

#### effort
6h

#### depends
Task 6

#### files_touched
- `agent-monitor/internal/tui/keys.go` (composer state + its key handler)
- `agent-monitor/internal/tui/keys_test.go`

#### success_criteria
1. `a` on a focused message opens a composer bound to that envelope, recording
   the recipient ADDRESS from `from_address` at open time — not at send time,
   so a sample arriving mid-draft cannot move the target.
2. While composing, every rune belongs to the draft: `q`, `d`, `/` and `G` are
   text, exactly as they are in a filter draft. `enter` inserts a newline
   rather than committing.
3. `esc` abandons the draft and closes; `ctrl+s` closes and yields the draft
   for sending (T9 performs the send).
4. The paging keys are swallowed while composing, named explicitly rather than
   left to a default arm — [[sp032]] T5's rule, same reason.
5. An empty or whitespace-only draft on `ctrl+s` is a no-op that keeps the
   composer open; nothing is dispatched.
6. `a` with no message selected, or with no identity (T4), does not open a
   composer and says why.

#### edge_cases
- A reply to a message whose `from_address` is an unclaimed address-shaped
  string: allowed (the bus permits it), since refusing would be a policy this
  layer does not own.
- A reply to your own message.
- The underlying message scrolling away, or the filter changing, mid-draft: the
  recorded recipient stands.
- Multi-line drafts longer than the composer region.
- Unicode and wide runes in the draft.

#### test_plan
- `TestComposer_OpensBoundToTheSelectedAddress`.
- `TestComposer_RunesAreTextNotCommands` — types `qd/G` and asserts the draft.
- `TestComposer_EnterInsertsNewline`.
- `TestComposer_EscAbandonsDraft`.
- `TestComposer_CtrlSYieldsDraftAndCloses`.
- `TestComposer_EmptyDraftIsANoOp`.
- `TestComposer_RecipientSurvivesASampleThatMovesTheList`.
- `TestComposer_PagingKeysSwallowed`.

|---|---|---|
| 1 | granularity | 6h: one mode, one key handler, eight cases; no I/O |
| 2 | implementability | `handleEditingKey` is the working template and is named; the composer differs only in being multi-line and in what commit means |
| 3 | success criteria | 6, each an exact key-to-state assertion |
| 4 | dependencies | Task 6, so the composer is built against the final selection semantics rather than re-tested after the flip |
| 5 | safety | criterion 1's open-time binding is the safety property — it makes "reply went to the wrong worker because the list moved" unrepresentable |
| 6 | edge cases | 5, including the list-moves-mid-draft case criterion 1 exists for |
| 7 | red flags | none |
| 8 | test meaningfulness | the recipient-survives case fails any implementation that reads the selection at send time, which is the natural way to write it |

### Task 9: sending, off the render path

#### type
feature

#### effort
5h

#### depends
Task 1, Task 4, Task 8

#### files_touched
- `agent-monitor/internal/source/messages.go` (a `Send` alongside the sampler)
- `agent-monitor/internal/source/messages_test.go`
- `agent-monitor/cmd/agent-monitor/main.go` (the `tea.Cmd` and its result msg)
- `agent-monitor/cmd/agent-monitor/main_test.go`

#### success_criteria
1. `source.Send(from, toAddress, body)` execs
   `pi-worker send --as <from> --to <toAddress> --content <body>` and returns
   the CLI's error verbatim on a non-zero exit.
2. The send is dispatched as a `tea.Cmd`; `Update` never blocks on it, and no
   sampler loop performs it — `RunLoop` and `RunMessagesLoop` are untouched
   ([[adr0014]]).
3. A successful send shows a transient confirmation naming the recipient
   label; the reply itself appears through the ordinary message tick, not by
   being inserted locally.
4. A failed send shows the CLI's stderr and RESTORES the draft, so nothing the
   operator typed is lost.
5. The body is passed as one argument with no shell interpolation; a draft
   containing quotes, `$`, backticks or newlines arrives byte-identical.

#### edge_cases
- A recipient released between open and send: the CLI refuses and criterion 4
  shows it.
- A body of several kilobytes (the envelope size cap refuses it; the refusal is
  shown).
- A body that looks like JSON: sent as a string, never re-encoded ([[adr0032]]).
- `pi-worker` disappearing from `PATH` mid-session.
- Two sends dispatched in quick succession.

#### test_plan
- `TestSend_ArgvShape` — a stub binary records argv; asserts the five flags and
  that the body is ONE argument.
- `TestSend_BodyWithMetacharactersArrivesIntact` — quotes, `$`, backtick,
  newline.
- `TestSend_NonZeroExitReturnsStderr`.
- `TestSend_MissingBinaryIsAnErrorNotAPanic`.
- `TestMain_FailedSendRestoresTheDraft`.
- `TestMain_SendIsNotPerformedInTheSamplerLoop` — asserts the loops' tick
  functions never exec `send`.

#### sre
| # | category | verdict |
|---|---|---|
| 1 | granularity | 5h: one exec, one command, one result path |
| 2 | implementability | `messages.go`'s existing exec is the template; the verb and its flags are quoted exactly from [[ft014]]'s surface |
| 3 | success criteria | 5; criterion 3 pins that the monitor does not fake local state, which keeps one source of truth for what is on the bus |
| 4 | dependencies | Task 1 (the address), Task 4 (the sender), Task 8 (the draft) |
| 5 | safety | criteria 4 and 5 are the safety pair: nothing is lost on failure, and nothing is interpolated on the way out |
| 6 | edge cases | 5, including the released-recipient case that only the CLI can detect |
| 7 | red flags | none |
| 8 | test meaningfulness | the argv and metacharacter cases fail a `sh -c` implementation, which is the tempting shortcut; the loop case fails a send accidentally wired into a tick |
