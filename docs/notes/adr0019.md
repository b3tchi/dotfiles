# ADR [[cat002]] [[product]]

## title
xorgxrdp forces software GL for Qt and swiftshader for Chromium separately

## context
[[adr0004]] put full-desktop WSL remoting on xrdp + xorgxrdp rendering on
llvmpipe, and the wrapper has since forced `QT_QUICK_BACKEND=software` and
`LIBGL_ALWAYS_SOFTWARE=1` on any xorgxrdp display.

[[adr0018]]'s reserved web tier introduced a second, independent GL
consumer: QtWebEngine's embedded Chromium. On xorgxrdp the `stl` tier
failed with `ContextResult::kFatalFailure: WebGL2 blocklisted` from
Chromium's own GPU blocklist, surfacing as "failed to load STL: Error
creating WebGL context."

Measured on a real xorgxrdp display (a private `:NN` started with the same
`/usr/lib/Xorg -config xrdp/xorg.conf` xrdp-sesman uses), the two knobs are
**orthogonal**: with the Qt pair forced OFF, `stl` fails identically. Both
arms fail, both arms recover only when Chromium flags are supplied. The Qt
pair was never the cause, and it degrades nothing.

## decision
On xorgxrdp displays the spawn environment composes **both** policies:

- the existing Qt pair — `QT_QUICK_BACKEND=software`, `LIBGL_ALWAYS_SOFTWARE=1`
- and `QTWEBENGINE_CHROMIUM_FLAGS` carrying
  `--use-gl=angle --use-angle=swiftshader --disable-gpu-compositing`

A caller-set `QTWEBENGINE_CHROMIUM_FLAGS` wins wholesale — the wrapper
defers rather than merging. Non-xorgxrdp displays receive neither policy.

Composition lives in `spawn-env-prefix` in
[nushell/actions/preview](../../nushell/actions/preview), factored as a
testable seam beside `is-xrdp-display` and table-tested.

## consequences
Chromium's GPU stack consults neither Qt variable, so the two policies must
be maintained as separate concerns even though one display condition
triggers both. A future change to the Qt pair says nothing about Chromium,
and vice versa.

[[adr0004]] and [[adr0005]] are extended, not overturned: they scoped
software GL for the Qt/X11 renderer of their day, and never contemplated an
embedded Chromium consumer.

`--enable-unsafe-swiftshader` currently rides along in the same flag set.
An audit measured `stl` rendering correctly **without** it, so it is
believed removable; tracked as bd `dotfiles-xu3p` rather than left as a
silent unsafe default.
