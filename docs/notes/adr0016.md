# ADR [[cat002]] [[cat001]] [[product]]

## title
A hold layer ends by asking the server, not by waiting for a key event

## context
[[ft011]]'s hold layers exist for one gesture i3 cannot express: cycle while a
modifier stays down, commit when it comes up. The obvious mechanism is to grab
the modifier's own keysym and end the layer on its release event.

That mechanism does not work, and the reason is structural rather than a bug to
fix. A layer is entered by a chord that already contains the modifier —
`$mod+Tab` — so `$mod` is physically DOWN before the layer's grabs are
installed. A passive grab installed on a key that is already held never
activates, so the release is delivered to whoever had the focus and never to
the daemon. There is no event to wait for.

Measured on the live xrdp `:10` session across 46 real-client gestures
([[sp020]] Task 8): every single exit logged `trigger=none note=hold-released`,
i.e. the poll, and not one logged a release event. Had the keysym-grab design
shipped, the switcher would have hung open on every use — which is exactly the
symptom that later appeared for the routes the poll did not cover
(dotfiles-hwds.51).

## decision
A hold layer's lifetime is settled by ASKING THE X SERVER whether the modifier
is still down, sampled on the daemon's idle path, never by waiting for a key
event.

Two consequences are part of the decision, not incidental:

1. **The query must be standalone.** The `state` mask carried ON an event is
   pre-event in X, so it cannot answer "is it down now"; a separate round trip
   has no event to be "pre".
2. **The engine's own belief is not consulted.** The modifier was pressed
   before the layer existed, so the daemon never saw the press and its held-set
   is empty. A commit gated on belief would never fire.

The corollary, learned the expensive way: because the exit is a poll rather
than an event, EVERY other route out of the layer has to carry the same
cleanup, or the gesture's side effects outlive it. That is why
[[ft011]] layers declare `on_exit`.

## consequences
The idle path costs one X round trip while a hold layer is up, which is the
price of the only mechanism that works. It bounds how fast a commit can be
observed to the idle sampling interval — measured as unnoticeable for alt-tab,
and the reason the interval is a constant worth re-measuring rather than
tuning by feel.

A hold layer therefore cannot be implemented by a client that only listens to
its own grabs; it needs a query channel to the server. Any future re-write in
another toolkit inherits this constraint.

Forecloses the modifier-keysym-grab design permanently. Anyone reaching for it
again should read the 46-sample measurement in [[sp020]] before spending a day
on it.
