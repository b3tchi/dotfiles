# ADR [[cat002]] [[product]]

## title
A hotkeyd overlay layer's terminal keys exit, its step keys stay, and it has no OnExit

## context
[[adr0040]] (sp041) made every key of hotkeyd's `camera` chord layer run its
overlay command AND ExitLayer, with no OnExit. That fixed a real race: an
OnExit close dispatched in the same instant as a snap key's own command
killed the photo. It also covered the layer's only keys at the time, which
all end the work (snap, close).

[[us030]] / [[sp045]] add focus and exposure step keys to the same layer:
nearer / farther / back to far focus, auto / manual, brighter / darker.
They are pressed many times in a row and held to repeat. Under adr0040 each
step would leave the layer and need $mod+f again, which makes adjusting
unusable. The `controls` layer ($mod+c, [[ft011]]) already has stay-in-layer
step keys that call an external helper (hwctl), so the pattern is known.

The race adr0040 fixed came from an exit command coinciding with a key's
command. A key that stays in the layer dispatches no exit, so it cannot
race. [[adr0022]] (external processes never clear a chord-entered layer,
layers declared at compile time) is not affected.

## decision
In a hotkeyd chord layer whose keys drive an external process (an overlay,
a picker), keys fall into two kinds:

- Terminal keys hand over or end the work (snap, close, confirm): they run
  their command AND ExitLayer, as adr0040 decided.
- Step keys make a repeatable adjustment that leaves the work open (focus,
  exposure): they run their command and stay in the layer; they may set
  Repeat for held keys.

The layer still declares NO OnExit that talks to the same process. The
external process owns its own safety net for an involuntary exit (for
CameraOverlay: the 2-minute auto-close, and every camera start / stop
resets focus and exposure, [[sp045]]). [[adr0022]] stands unchanged.

## consequences
- Step keys are usable: press or hold without re-entering the layer.
- No race returns: step keys never exit, terminal keys still send one
  message, no OnExit anywhere.
- The layer stays grabbed between steps until a terminal key or the exit
  key; if hotkeyd dies meanwhile, the overlay's own timeout and reset
  cover it, as before.
- Each layer's key table must mark which keys are terminal (ExitLayer) and
  which are steps; the hotkeyd engine test pins it (TestCameraKeysDispatch:
  a step key runs exactly one verb and the layer stays `camera`).
- A step command that fails leaves the layer up; the overlay shows the
  error. Only a failed open clears the layer (qs-overlay.sh).
