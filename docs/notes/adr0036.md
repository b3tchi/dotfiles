# ADR [[cat001]] [[product]]

## title
a binding is not shipped until a real keypress reaches it

## context
[[sp033]] T9 built [[ft016]]'s reply-send path: the exec shape, the `tea.Cmd`
dispatch that keeps it off the render path, the draft-and-recipient restore on
failure, and byte-identical delivery of a body containing quotes, `$`,
backticks and newlines. It was implemented test-first, audited independently
against eight stated criteria, and merged.

Pressing ctrl+s did nothing.

`translateKey` — the layer mapping a `tea.KeyMsg` onto the model's own key
vocabulary — had no `tea.KeyCtrlS` case. Every test constructed a `tui.Key`
directly and handed it to the model, so the whole send path was exercised on a
route no keypress could take. The defect survived a test-first implementation
and a deliberately adversarial audit, and was found only when T10 built the
binary and pressed the key in a real tmux pane.

The cause is structural, not careless. The model is decoupled from bubbletea
precisely so the key surface can be unit-tested without a terminal — and that
decoupling is exactly what hides a missing translation. "The model handles K"
and "pressing K reaches the model" are different claims, and only the first was
ever being made.

## decision
A key binding is not shipped until a test drives a REAL `tea.KeyMsg` through
the translation layer into the model. Model-layer tests that synthesise the
model's own key type remain valuable and remain the place to assert behaviour —
they are not sufficient evidence that the binding is reachable.

The two claims are tested separately and both are required:

- behaviour: given key K, the model reaches state S (synthesised key, fast, exhaustive);
- reachability: given a real `tea.KeyMsg` for K, the model receives K at all.

A table-driven reachability test is preferred, provided its failure output
NAMES the key that broke — a failure that says only "table case 7 failed" costs
the reader the thing the test exists to tell them.

## consequences
`dotfiles-ng1w.14` audited every binding this TUI documents and added the
missing reachability coverage: `R`, positive `PgUp`, and the composer's enter,
backspace and paging behaviour were all model-layer-only. No second unreachable
binding existed, so the cost of the policy was five tests, not a redesign.

The general lesson outlived the fix and belongs with it: a test is evidence only
for the property it can FAIL on. The technique that caught this — revert the
implementation, re-run the test cited as proof, and see whether it still passes
— caught three separate defects in [[sp033]] alone: an edge case declared
untestable that was not, bindings tested at the wrong layer, and a headline test
that passed equally well against the implementation it claimed to distinguish.
Reviewers on this project should reach for it by default rather than
rediscovering it per task.

This is a testing policy, not an architectural one. It constrains no runtime
behaviour and forecloses no design; it says what counts as evidence that a
binding works.
