# Implementation [[cat002]] [[cat001]] [[product]]

## solves
[[us019|programmable-global-keybinds]]

## approach
Re-implement [[ft011]]'s per-display daemon in Go, superseding
[[im009|python-hotkey-daemon-cutover]] — which stays unedited as the true
record of what Python shipped, because that shipped shape IS this card's
acceptance criterion. Two structural choices define the rewrite:

1. **Zero external dependencies.** A stdlib-only X11 client owning
   exactly the requests the daemon uses, validated by [[poc015]]
   (1,027 code lines, `CGO_ENABLED=0`, static 3.8 MiB, cross-compiles
   to arm64/arm) against the real `:0` and `:10` sessions. [[poc014]]
   is the recorded rejected alternative (vendored `jezek/xgb` fork —
   stock xgb silently desyncs on GenericEvents and then hangs forever).
   `go.mod`'s require block staying empty is an invariant a test
   asserts, not a preference.
2. **Binds compile into the source**, dwm `config.h` style: no YAML, no
   parser, no `--binds` flag; `go build` is how a bind changes. The
   42-rule runtime validator survives as unit tests plus `--check`, and
   the type system catches what Python could only reject at load time.
   The table expresses a per-display qualifier from day one so
   [[us020]] (shipped in Python first) enters the parity target instead
   of becoming rework.

The language decision is carried by `adr0021` (spec Task 2) on
static-binary / no-interpreter-skew / compile-time-validation merits —
explicitly NOT on [[adr0003]]'s three-condition gate, which this daemon
fails — and resolves the [[adr0003]] wrapper mandate against
[[adr0015]]'s launcher refusal by carving X-session keystroke daemons
out of the `nushell/actions/` mandate: `hotkeyd.sh` / `hotkeyd-panic.sh`
stay shell, per [[ft003]].

Everything consumer-visible is frozen: state-socket wire format and
replay-on-connect ([[adr0012]], [[adr0014]], [[ft009]] consumers),
`--health` exit codes 0/6/7/8/9/10 ([[adr0017]]), the i3-owned panic
path ([[ft003]]), and the hold-layer ends-by-asking-the-server rule
([[adr0016]]). `SIGHUP` table reload is deliberately dropped — reload
becomes rebuild + restart, SIGHUP logs a no-op, and [[ft011]] is
amended to match.

Cutover is per-display because two XI2 grabbers on one chord collide
with `BadAccess` (measured, [[ft011]]): Go took `:10` first (harsher
xrdp environment, lower stakes), Python kept `:0` until the
parameterised suites — the parity contract, `dotfiles-2ats` — passed on
both engines and a live soak cleared. **Shipped end state:** once the
`:0` soak cleared, all eight Python files (`hotkeyd.py`, `binds.py`,
`layers.py`, `state-tail.py`, `live_check.py` and their three test
suites) were deleted from the tree — Go serves both displays, and the
parallel-run engine table `hotkeyd.sh` carried during the transition
window was removed with them (`dotfiles-ylmp.16`). There is no
`HOTKEYD_ENGINE_DEFAULT` fallback path left to fall back to.

**Extended by [[sp023]]:** the compiled table gains a signal-only layer
kind for non-keybind external triggers — a mouse-driven overlay
(`quickshell/qs-region.py`'s screenshot-drag) can now set hotkeyd's
layer state without a chord, over a new control socket, without
reopening [[adr0012]]'s read-only framing for the pre-existing state
socket. Governed by [[adr0022]] (compile-time-declared, channel-separated,
never a general write API — the decision this spec established).

**Extended by [[sp024]]:** a SECOND External layer, `"screenshot"`, moves
the screenshot AIMING phase onto the same channel and retires the last
custom i3 mode in the live config. i3 now declares no `mode` block at all
outside the panic fallback file, so the daemon is the sole owner of every
layer-shaped signal on this machine.

Two consequences fell out of that, neither predicted by the spec:

1. **The dead-overlay escape hatch dissolved rather than moved.** The
   `mode "screenshot" {}` block kept Escape/`q` as a fallback for a
   selector that died holding a grab. An External layer holds ZERO grabs
   and i3 never leaves `default`, so there is no stuck mode to escape
   from — a stranded layer costs a painted hint strip, never keys. The
   guard was deleted, not replaced.
2. **A held chord exposed a launcher race the i3 mode had masked.**
   `$mod+Shift+s` fired on PRESS, so holding it relaunched
   `qs-screenshot.sh` repeatedly; each launch replaced the previous
   SELECTOR but not the previous LAUNCHER, whose unconditional
   `set-layer default` then cleared the layer the newer launch had just
   raised. Fixed by moving the bind to `OnRelease` (matching its
   `$mod+Print` siblings) plus a session-scoped pid ownership token in
   the launcher, so a superseded instance declines to clear
   (`dotfiles-b3d4`). The i3 mode had hidden this because setting the
   same mode twice is idempotent in a way a raise/clear pair is not.

The `OnRelease` change is also the first deliberate divergence from the
frozen Python golden dump; [[adr0023]] records that such divergences are
DECLARED in `config_test.go` rather than absorbed by editing the fixture,
so the record of what Python shipped stays true.

## features
- [[ft011|global-hotkey-layer]] — the capability re-implemented; its
  surface is preserved except `--binds` and `SIGHUP` reload (amended in
  the spec's Task 18)
- [[ft003|i3-config-layering]] — keeps the panic bind and fallback
  table; the recovery path is untouched by design
- [[ft009|mode-bar-control]] — consumer of the frozen state socket; the
  only visible edit is `Bar.qml`'s `state-tail` spawn line at swap
- [[ft006|region-capture]] — **added by [[sp023]]:** `qs-region.py`
  calls the new `set-layer` verb instead of `i3-msg mode
  screenshot-drag`; ft006's own api_surface and output contract are
  unchanged, only the drag-phase signal's transport moved.
  **[[sp024]] widened this to the whole gesture:** `qs-screenshot.sh`
  raises `"screenshot"` for the aiming phase too, the i3 mode block is
  gone, and ft006's api_surface DID change — the bind fires on release
  and the exit contract names a hotkeyd layer rather than an i3 mode

## data_model
Identical to [[im009]]'s: no persistence; per-display runtime files
under `$XDG_RUNTIME_DIR` keyed on the display with the screen suffix
stripped — `hotkeyd-<n>.sock` (JSON-lines state feed, current state
replayed at accept), `hotkeyd-<n>.lock` (flock; line 1 pid, line 2
`heartbeat=1`, mtime is the heartbeat), `hotkeyd-<n>.grabs` (pid-stamped
`{pid, wanted, active, missing[]}` sidecar, atomic rewrite). **Added by
[[sp023]]:** `hotkeyd-<n>-ctl.sock` — the `set-layer` control socket, one
JSON request/reply line per connection, best-effort at startup like the
state socket (bind failure logged, daemon serves without it). In-memory:
layer stack, held-modifier set, and WANTED beside ACTIVE grab sets.
New build artifact: `hotkeyd/hotkeyd`, a static binary built in place
(gitignored) — the tree still runs in place with no links.

## api_surface
Parity with [[ft011]]'s published surface, minus two deliberate cuts:

    hotkeyd [--display :0] [--check] [--health]
    hotkeyd check --ownership
    hotkeyd state-tail --display :0      # replaces state-tail.py

- No `--binds` flag: the table is compiled in; `--help` points at
  `go build`.
- `SIGHUP` is a logged no-op; reload is rebuild + `hotkeyd.sh restart`.
- `--health` keeps one exit code per verdict (0 serving, 6 loop
  stopped, 7 display unreachable to the caller, 8 exclusive foreign
  grab, 9 grabs missing, 10 unanswerable), per [[adr0017]].
- `hotkeyd.sh` / `hotkeyd-panic.sh` keep their verbs unchanged. The
  per-display engine table `hotkeyd.sh` carried during the parallel-run
  window is GONE post-cutover: one engine now, every display resolves
  straight to the Go binary, no Python branch left to select.

**Widened by [[sp023]]:** `set-layer NAME [--display :N]` sets or clears
(`NAME=default`) an EXTERNAL-declared layer over a new per-display
control socket, distinct from the state socket above — a narrow
[[adr0012]] exception per [[adr0022]], never a general write API. Only
names declared `External: true` in the compiled table (plus `default`)
are accepted; refused by name otherwise, both client-side (before
dialing) and daemon-side (against its own compiled table regardless of
what the client checked). Distinct exit codes: 0 ok, 1 refused, 2 usage,
3 daemon unreachable.

**Widened by [[sp024]]:** TWO names are now declared External —
`"screenshot"` (aiming) and `"screenshot-drag"` — and the
EXTERNAL -> EXTERNAL transition between them is a shipped path, not an
accident of the guard: `SetExternalLayer` refuses only while a
CHORD-entered layer is active. `qs-region.py` hands off from aiming to
drag at mouse-press with no intervening clear, and one
`set-layer default` clears whichever is up, so no caller tracks the
phase. Because the table compiles in ([[adr0021]]), a newly declared
name does not exist for an already-running daemon: `set-layer screenshot`
exits 1 "no such layer" until the binary is rebuilt and restarted, while
every previously-declared name keeps working — the signature of a
half-deployed cutover.

## components
Shipped tree (module rooted at `hotkeyd/`, require block empty). The
Python predecessor — `hotkeyd.py`, `binds.py`, `layers.py`,
`state-tail.py`, `live_check.py`, and their three test suites — is
DELETED from the tree; `git log -- hotkeyd/hotkeyd.py` is where it went.
Zero `.py` files remain under `hotkeyd/`.

- `hotkeyd/cmd/hotkeyd/` — `main.go` (CLI), `config.go` (THE table, now
  incl. TWO `bind.Layer{External: true}` declarations — `screenshot`
  ([[sp024]]) and `screenshot-drag` ([[sp023]]) — plus the
  `intentionalDivergences` allowlist in `config_test.go` that keeps the
  frozen python golden dump honest across deliberate bind changes
  ([[adr0023]])), `daemon.go` (run loop, gained the control-socket select
  case), `grabs.go` (GrabManager + DeviceRegistry), `health.go`,
  `ownership.go`, `statetail.go`, `control.go` (daemon side of
  `set-layer`: control-socket listener, `validateControlLayer`, forwards
  into `(*layer.Engine).SetExternalLayer`), `setlayer.go` (the
  `set-layer` CLI verb)
- `hotkeyd/cmd/livecheck/` — live-X assertions, replacing
  `live_check.py`
- `hotkeyd/internal/bind/` — types, chord parser, 42-rule validator,
  display qualifier, `RESERVED_CHORDS`
- `hotkeyd/internal/layer/` — engine (persistent / one-shot / hold /
  sublayer, `on_exit`, 120 ms guard) + state publisher
- `hotkeyd/internal/x11/` — [[poc015]]'s transport (auth, handshake,
  windowed sequence map, read loop) + requests + XI2 subset
- `hotkeyd/internal/i3/` — persistent IPC client as a real interface
  (the `getattr` seams become compile errors)
- `hotkeyd/internal/proc/` — flock lock + heartbeat, grab-report
  sidecar, spawn
- `hotkeyd/hotkeyd.sh`, `hotkeyd/hotkeyd-panic.sh` — stay shell
- `hotkeyd/test-hotkeyd.sh`, `test-launcher.sh`, `test-panic.sh` —
  parameterised on `HOTKEYD_BIN` / `HOTKEYD_PROC_PAT`; the parity
  contract. `test-hotkeyd.sh` stage 18 drives the full two-External
  gesture over the real control socket ([[sp024]])
- `quickshell/test-screenshot-launcher.sh` — **new at [[sp024]]:** stubs
  hotkeyd and the selector to pin the ORDER OF EFFECTS on the layer
  channel across overlapping launches; a superseded launcher must not
  clear a live one's layer (`dotfiles-b3d4`)
