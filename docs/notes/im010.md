# Implementation [[cat002]] [[cat001]] [[product]]

## solves
[[us019|programmable-global-keybinds]]

## approach
Re-implement [[ft011]]'s per-display daemon in Go, superseding
[[im009|python-hotkey-daemon-cutover]] — which stays unedited as the true
record of what Python shipped, because that shipped shape IS this card's
acceptance criterion. Two structural choices define the rewrite:

1. **Zero external dependencies.** A stdlib-only X11 client owning
   exactly the requests the daemon uses, validated by [[poc015]]
   (1,027 code lines, `CGO_ENABLED=0`, static 3.8 MiB, cross-compiles
   to arm64/arm) against the real `:0` and `:10` sessions. [[poc014]]
   is the recorded rejected alternative (vendored `jezek/xgb` fork —
   stock xgb silently desyncs on GenericEvents and then hangs forever).
   `go.mod`'s require block staying empty is an invariant a test
   asserts, not a preference.
2. **Binds compile into the source**, dwm `config.h` style: no YAML, no
   parser, no `--binds` flag; `go build` is how a bind changes. The
   42-rule runtime validator survives as unit tests plus `--check`, and
   the type system catches what Python could only reject at load time.
   The table expresses a per-display qualifier from day one so
   [[us020]] (shipped in Python first) enters the parity target instead
   of becoming rework.

The language decision is carried by `adr0018` (spec Task 2) on
static-binary / no-interpreter-skew / compile-time-validation merits —
explicitly NOT on [[adr0003]]'s three-condition gate, which this daemon
fails — and resolves the [[adr0003]] wrapper mandate against
[[adr0015]]'s launcher refusal by carving X-session keystroke daemons
out of the `nushell/actions/` mandate: `hotkeyd.sh` / `hotkeyd-panic.sh`
stay shell, per [[ft003]].

Everything consumer-visible is frozen: state-socket wire format and
replay-on-connect ([[adr0012]], [[adr0014]], [[ft009]] consumers),
`--health` exit codes 0/6/7/8/9/10 ([[adr0017]]), the i3-owned panic
path ([[ft003]]), and the hold-layer ends-by-asking-the-server rule
([[adr0016]]). `SIGHUP` table reload is deliberately dropped — reload
becomes rebuild + restart, SIGHUP logs a no-op, and [[ft011]] is
amended to match.

Cutover is per-display because two XI2 grabbers on one chord collide
with `BadAccess` (measured, [[ft011]]): Go takes `:10` first (harsher
xrdp environment, lower stakes), Python keeps `:0` until the
parameterised suites — the parity contract, `dotfiles-2ats` — pass on
both engines and a live soak clears.

## features
- [[ft011|global-hotkey-layer]] — the capability re-implemented; its
  surface is preserved except `--binds` and `SIGHUP` reload (amended in
  the spec's Task 18)
- [[ft003|i3-config-layering]] — keeps the panic bind and fallback
  table; the recovery path is untouched by design
- [[ft009|mode-bar-control]] — consumer of the frozen state socket; the
  only visible edit is `Bar.qml`'s `state-tail` spawn line at swap

## data_model
Identical to [[im009]]'s: no persistence; per-display runtime files
under `$XDG_RUNTIME_DIR` keyed on the display with the screen suffix
stripped — `hotkeyd-<n>.sock` (JSON-lines state feed, current state
replayed at accept), `hotkeyd-<n>.lock` (flock; line 1 pid, line 2
`heartbeat=1`, mtime is the heartbeat), `hotkeyd-<n>.grabs` (pid-stamped
`{pid, wanted, active, missing[]}` sidecar, atomic rewrite). In-memory:
layer stack, held-modifier set, and WANTED beside ACTIVE grab sets.
New build artifact: `hotkeyd/hotkeyd`, a static binary built in place
(gitignored) — the tree still runs in place with no links.

## api_surface
Parity with [[ft011]]'s published surface, minus two deliberate cuts:

    hotkeyd [--display :0] [--check] [--health]
    hotkeyd check --ownership
    hotkeyd state-tail --display :0      # replaces state-tail.py

- No `--binds` flag: the table is compiled in; `--help` points at
  `go build`.
- `SIGHUP` is a logged no-op; reload is rebuild + `hotkeyd.sh restart`.
- `--health` keeps one exit code per verdict (0 serving, 6 loop
  stopped, 7 display unreachable to the caller, 8 exclusive foreign
  grab, 9 grabs missing, 10 unanswerable), per [[adr0017]].
- `hotkeyd.sh` / `hotkeyd-panic.sh` keep their verbs unchanged;
  `hotkeyd.sh` gains a per-display engine table for the parallel-run
  window only.

## components
Planned tree (module rooted at `hotkeyd/`, require block empty):

- `hotkeyd/cmd/hotkeyd/` — `main.go` (CLI), `config.go` (THE table),
  `daemon.go` (run loop), `grabs.go` (GrabManager + DeviceRegistry),
  `health.go`, `ownership.go`, `statetail.go`
- `hotkeyd/cmd/livecheck/` — live-X assertions, replacing
  `live_check.py`
- `hotkeyd/internal/bind/` — types, chord parser, 42-rule validator,
  display qualifier, `RESERVED_CHORDS`
- `hotkeyd/internal/layer/` — engine (persistent / one-shot / hold /
  sublayer, `on_exit`, 120 ms guard) + state publisher
- `hotkeyd/internal/x11/` — [[poc015]]'s transport (auth, handshake,
  windowed sequence map, read loop) + requests + XI2 subset
- `hotkeyd/internal/i3/` — persistent IPC client as a real interface
  (the `getattr` seams become compile errors)
- `hotkeyd/internal/proc/` — flock lock + heartbeat, grab-report
  sidecar, spawn
- `hotkeyd/hotkeyd.sh`, `hotkeyd/hotkeyd-panic.sh` — stay shell
- `hotkeyd/test-hotkeyd.sh`, `test-launcher.sh`, `test-panic.sh` —
  parameterised on `HOTKEYD_BIN` / `HOTKEYD_PROC_PAT`; the parity
  contract
