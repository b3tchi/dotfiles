# ADR [[cat002]] [[product]]

## title
An overlay that outlives its hotkeyd layer owns kwi3's mode until it closes

## context
[[adr0041]] made the camera layer's terminal keys (snap, quit) run their
overlay verb AND leave the layer at once, so the keyboard is handed back
immediately. hotkeyd also reports every layer change to kwi3 as its mode
(ft010 `mode.set`), and kwi3 hides its focus ring in any non-default mode
(kwi3/config.js modeFrame '*': 'none'). The ring is a KWin-internal window
drawn above every layer-shell surface.

On the phone ([[sp045]], 2026-11-24) the camera preview stays up after the
snap key for 0.3-2 s (the verb reaches the overlay through `quickshell ipc`,
then the photo is taken and saved). hotkeyd's `mode.set default` at the key
brought the ring back over the still-visible preview. Re-hiding it from the
overlay once kwi3 reported the ring was too late: it still flashed (user
verified). hotkeyd restarting while the preview was up also left a preview
with no keys to close it.

## decision
For a hotkeyd layer that drives an external overlay which outlives the
layer's terminal key, the overlay owns kwi3's mode from the layer's exit
until the overlay closes:

- hotkeyd does NOT report the exit back to default to kwi3 for such layers
  (`kwi3HandOffLayers`, today `camera`); it records kwi3 as already at
  default, so the next layer it enters is sent, even the same one again.
- The overlay sends `mode.set default` itself when it closes, and while
  open re-hides a ring that comes back for another reason.
- The overlay follows hotkeyd's state feed while open and closes itself
  when the feed ends (hotkeyd restarted or died), so no preview outlives
  the daemon that owns its keys.

[[adr0041]] stands unchanged (keys still exit at once, no OnExit);
[[adr0022]] stands (no external process clears a chord-entered layer).

## consequences
- No focus ring over the camera preview at any point; the ring returns
  exactly when the preview closes.
- kwi3's mode is no longer a pure function of hotkeyd's layer: between a
  camera exit and the overlay closing, kwi3 says camera while hotkeyd says
  default. A second writer of kwi3's mode now exists (the overlay, over
  Kwi3Client); both use ft010 `mode.set`.
- If the overlay never closes (quickshell dead), kwi3 stays in camera mode
  with the ring hidden until the next layer change; harmless but visible.
- Pinned by hotkeyd TestKwi3ModeHandsCameraExitToOverlay.
