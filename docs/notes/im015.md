# Implementation [[cat002]] [[product]]

## solves
[[us030|camera-keyboard-focus-exposure]]

## approach
hotkeyd's `camera` layer ([[ft011]]) has step keys that stay in the layer
([[adr0041]], superseding [[adr0040]]): n / Alt+n focus nearer / farther,
d far focus, a auto / manual exposure, e / Alt+e brighter / darker; snap and
quit still leave it. Each key runs `qs-overlay.sh camera-<verb>`, an IPC
call into quickshell's CameraOverlay, which drives the LibCamera QML module
([[ft019]], widened):

- Focus: the module finds the lens V4L2 subdev by its focus_absolute
  control ([[sp044]], [[poc030]]: writes from the streaming process land in
  one frame), steps a dioptre ladder from the machine file's far default
  (camera.focusFar, 385), and sets the default on every start and stop.
- Exposure: manual time x gain as libcamera request controls on every
  request (stills included), 1/3-stop steps seeded from the AE metadata,
  auto again on every start. EV is not used (softISP ignores it, [[us029]]).
- Display: F / AE / capturing bottom-left over the picture in the session
  font; the bar's camera strip lists the keys (held Alt shows the reverse
  strip) and stays up for as long as the preview is.
- kwi3's focus ring: hotkeyd does not report the camera layer's exit to kwi3;
  the overlay owns kwi3's mode until it closes ([[adr0042]]). The overlay
  also closes itself when hotkeyd's state feed ends.

Picture quality (sharpness, AE tuning, the brightness jump after a still)
is out of scope here: [[us029]], bd dotfiles-u95w.
