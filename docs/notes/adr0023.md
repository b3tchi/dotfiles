# ADR [[cat002]] [[cat001]] [[product]]

## title
deliberate divergence from the python golden dump is declared in code,
never absorbed by editing the fixture

## context
[[sp021]] froze `hotkeyd/cmd/hotkeyd/testdata/golden-dump-python.json` at
the moment `binds.py` was deleted: the last surviving statement of the
bind table the user's keyboard actually had before the Go rewrite.
`TestGoldenDumpParity` compares the compiled Go table against it chord
for chord, action for action, including `OnRelease`.

That contract had never been tested against an INTENTIONAL behavior
change. [[sp023]] and [[sp024]] both added External layers, which the
dump excludes by construction, so parity stayed green without anyone
deciding anything. `dotfiles-b3d4` was the first change to alter a
global bind's behavior on purpose — `$mod+Shift+s` moved to `OnRelease`
so a held chord stops relaunching the screenshot launcher.

The obvious move was to edit the fixture to match. It is one line, the
test goes green, and nothing appears to be lost.

## decision
The frozen dump is a HISTORICAL RECORD and is never edited to
accommodate a later change. Editing it to say Python fired
`$mod+Shift+s` on release would make the record assert something Python
never did, and the next engineer reading it would have no way to know.

Intentional divergence is instead declared in
`config_test.go`'s `intentionalDivergences` map, keyed by chord, carrying
the reason and the issue that changed it. The parity comparison applies
those divergences to the PYTHON side before comparing, so chord, device
and actions stay asserted for that bind and only the named field stops
being compared.

A guard test (`TestIntentionalDivergencesAreLive`) rejects any entry that
no longer describes a real divergence — a stale entry would silently stop
asserting the field it names, which is strictly worse than no entry at
all.

## consequences
An ACCIDENTAL behavior change still fails parity, which is the property
the contract exists for; only a change someone chose and wrote down
passes. The cost is one map entry per deliberate change, and the benefit
is that the fixture keeps meaning exactly what it says.

The map is also the honest measure of how far the shipped table has drifted
from what Python ran. When it grows long enough that the parity test is
mostly exceptions, that is the signal to retire the contract deliberately
— a decision someone makes and records — rather than letting it erode one
silent fixture edit at a time.

This generalises past `hotkeyd`: any frozen-fixture parity contract in this
repo follows the same shape. Record what was, declare what changed.
